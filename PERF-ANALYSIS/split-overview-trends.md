## 拆分策略

### 目录结构
```
dashboard/components/trends/
├── index.tsx                    # 导出入口
├── OverviewTrends.tsx           # 主组件（~60行，原150行目标）
├── components/
│   ├── TrendChart.tsx           # 图表组件（~50行）
│   ├── TrendFilters.tsx         # 时间范围筛选（~30行）
│   ├── TrendStats.tsx           # 统计卡片（~40行）
│   └── TrendLegend.tsx          # 图例选择器（~60行）
├── hooks/
│   └── useTrendData.ts          # 数据获取与状态管理（~25行）
├── types.ts                     # 类型定义（~50行）
└── utils.ts                     # 工具函数（~50行）
```

### 组件职责划分

#### 1. **主组件** (`OverviewTrends.tsx`)
- **职责**: 整体布局和组件组合
- **大小**: ~60行
- **特点**: 只负责组件组合，不包含业务逻辑

#### 2. **图表组件** (`TrendChart.tsx`)
- **职责**: 渲染折线图/柱状图/面积图
- **依赖**: recharts 库
- **特点**: 纯展示组件，根据 props 渲染不同图表类型

#### 3. **筛选组件** (`TrendFilters.tsx`)
- **职责**: 时间范围选择和刷新按钮
- **特点**: 独立的状态管理，与父组件通过回调通信

#### 4. **统计组件** (`TrendStats.tsx`)
- **职责**: 显示总调用、Token、成本、成功率统计
- **特点**: 纯计算组件，无状态依赖

#### 5. **图例组件** (`TrendLegend.tsx`)
- **职责**: 指标选择器和图表样式选择器
- **特点**: 封装了所有指标和图表的配置

#### 6. **Hook** (`useTrendData.ts`)
- **职责**: 管理指标选择、图表样式等状态
- **特点**: 封装所有业务逻辑，使主组件保持简洁

#### 7. **类型文件** (`types.ts`)
- **职责**: 定义所有接口和类型
- **特点**: 统一的类型定义，避免重复

#### 8. **工具文件** (`utils.ts`)
- **职责**: 数据转换、格式化、常量定义
- **特点**: 纯函数，易于测试和复用

## 性能优化收益

### 1. **组件渲染优化**
- **按需加载**: 每个子组件可独立更新，避免不必要的重渲染
- **Memoization**: Hook 中使用了 `useCallback` 缓存计算
- **树摇**: 拆分后更容易进行代码分割

### 2. **开发体验提升**
- **关注点分离**: 每个文件职责单一，便于理解和维护
- **类型安全**: 完整的 TypeScript 类型定义
- **测试友好**: 小文件更容易编写单元测试

### 3. **代码复用性**
- **独立导出**: 每个组件都可以独立导入使用
- **配置灵活**: 通过 props 控制组件行为
- **样式统一**: 统一的样式系统和设计规范
