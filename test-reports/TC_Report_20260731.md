## 三、新增缺陷清单

### BUG-013 🔴 严重 — 401 拦截器导致登录页无限循环（已修复 ✅）

| 属性 | 值 |
|------|-----|
| 严重等级 | 🔴 **严重** — 页面无法使用 |
| 模块 | 前端 → api.ts 401 拦截器 |
| 发现方式 | Playwright 控制台日志检测 + 代码审查 |
| 修复文件 | `web/src/lib/api.ts` |

**根因分析：**
1. `api.ts` 的响应拦截器检测到 401 后会 `window.location.href = '/login'`
2. 登录页 `Login.tsx` 中的 `ThemeContext` 调用 `get('/api/v1/me/settings')`
3. 未登录状态返回 401 → 拦截器跳转 `/login` → 页面重新加载 → 回到步骤 1
4. 造成无限循环，页面始终显示 Loading 旋转动画

**修复方案（已应用）：**
- 在 `skipAuthReset` 列表中增加 `/api/v1/me/settings`、`/api/v1/auth/refresh`、`/api/v1/admin/settings/wechat-login`、`/api/v1/site-config`
- 跳转前检查当前 URL 是否已在登录/注册等公开页面，避免重复跳转

**回归验证结果：✅ 登录页正常渲染，401 API 调用不再触发跳转。**

### BUG-014 🟡 中等 — 登录按钮缺少空表单 disabled 视觉反馈

| 属性 | 值 |
|------|-----|
| 严重等级 | 🟡 **中等** — UX 问题 |
| 模块 | 前端 → Login.tsx |
| 发现方式 | Playwright 表单测试 |

**描述：** 登录页的 submit 按钮在邮箱和密码均为空时没有设置 `disabled` 属性。虽然有 HTML5 `required` 校验会拦截空提交，但用户缺少视觉反馈。

**建议修复：** 在 `Login.tsx` 中添加 `disabled={loading || !email || !password}` 条件。

### BUG-015 🟡 中等 — 首页统计数据显示 "undefined+"

| 属性 | 值 |
|------|-----|
| 严重等级 | 🟡 **中等** — 数据展示错误 |
| 模块 | 前端 → Portal/Home 组件 |
| 发现方式 | Playwright 页面内容解析 |

**描述：** 门户首页显示 "undefined+ 累计处理 Token"，数据未从 API 正确获取。

**根因：** 前端 Portal 首页的统计卡片使用 `formatNumber()` 函数时传入 `undefined`。检查 `src/pages/portal/Home.tsx` 中统计数据获取逻辑。

### BUG-016 🟠 高 — 后端 4 个 API 返回 500 内部错误

| 属性 | 值 |
|------|-----|
| 严重等级 | 🟠 **高** — 功能不可用 |
| 模块 | 后端 → 数据库查询 |
| 发现方式 | API 测试 → Playwright 检测 HTTP 500 |
| 影响页面 | 模型管理、安全配置（配额管理、角色管理） |

**涉及 API：**
- `GET /api/v1/admin/models?page=1&pageSize=20` → 500（`models` 表缺失）
- `GET /api/v1/admin/security/config` → 500（`login_security_configs` 表缺失）

**根因：** 数据库迁移未完成。`models` 表和 `login_security_configs` 表不存在。

**建议修复：** `cd 3cloud/api && npx drizzle-kit push` 或生成并执行对应 migration。

### BUG-017 🟠 高 — 后端 8 个 API 返回 404 未注册

| 属性 | 值 |
|------|-----|
| 严重等级 | 🟠 **高** — 功能不可用 |
| 模块 | 后端 → 路由注册 |
| 发现方式 | API 测试 |
| 影响页面 | 日志趋势、汇率、限流、监控概览、告警规则、演练、活动等 8 个管理页面 |

**涉及 API：**
- `GET /api/v1/admin/logs/trends?days=7` → 404
- `GET /api/v1/admin/finance/exchange-rates` → 404
- `GET /api/v1/admin/rate-limits` → 404
- `GET /api/v1/admin/monitoring/overview` → 404
- `GET /api/v1/admin/alert-rules` → 404
- `GET /api/v1/admin/drills` → 404

**根因：** 前端路由已注册，但对应后端 API 未实现或路由路径不匹配。

**影响：** 对应的 8 个管理后台页面显示空白或 Loading 状态，无法使用。

### OPT-007 🟢 建议 — 减少未登录时的 401 API 调用

| 属性 | 值 |
|------|-----|
| 严重等级 | 🟢 **优化** |
| 模块 | 前端 → ThemeContext |
| 发现方式 | 性能审查 |

**描述：** 每个页面加载时 `ThemeContext` 都会调用 `me/settings` 返回 401。测试中累计 76 次 401 调用。虽然已静默处理，但浪费带宽和渲染时间。

**建议：** 在未登录状态下跳过 `me/settings` 请求，直接使用 localStorage 缓存的 theme。

## 七、测试总结

**本次测试覆盖了 71 个交互点，发现并修复了 1 个严重 BUG（BUG-013 401 无限循环），新增记录 4 个缺陷和 1 个优化项。**

核心发现：
1. ✅ **BUG-013（401 无限循环）已修复并验证通过** — 这是影响所有页面加载的关键问题
2. ❌ **后端 API 缺失问题严重** — `models` 表和 `login_security_configs` 表未创建，8 个 API 路由未注册，导致管理后台部分页面不可用
3. ⚠️ 需要执行数据库 migration 和补充后端路由注册
