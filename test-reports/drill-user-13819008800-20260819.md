## 1. 本次修复与新增（代码改动）

### 1.1 P0 — `/app/announcements` 公告页空白（用户报障根因）

- **现象**：以该用户登录后打开 `/app/announcements`，页面白屏（React 卸载整棵树），控制台报
  `Minified React error #31: object with keys {unread}`。
- **根因**：`ConsoleLayout`（顶栏铃铛）与 `AnnouncementsPage` 使用**同一个 React Query key
  `["me-announcements-unread"]`，但 queryFn 返回形状不一致**：
  - 布局：`(…).data.data?.unread ?? 0`（数字）
  - 公告页：`(…).data.data`（对象 `{unread}`）
  - React Query 按 key 去重共享缓存 → 公告页挂载后其 queryFn 覆盖缓存为对象，
    顶栏铃铛渲染 `unread`（对象）→ 触发 React #31 → 白屏。仪表盘等页无此冲突故正常。
- **修复**：`web-console/src/pages/AnnouncementsPage.tsx` 的 unread query 改为与布局同形状
  （返回数字 `?.unread ?? 0`），渲染处同步适配；两处共享 key 语义一致，读后失效联动保留。
- **验证**：重建 SPA（`scripts/prepare-app.cjs`）后，headless Chrome 以该用户登录打开
  `/app/announcements`：公告列表/未读角标/「全部已读」均正常，无 React 异常；
  52 路由走查公告页 0 错误。

### 1.2 P1 — 协议确认（ConsentBanner）用户端端点缺失

- **现象**：前端 `ConsentBanner` 依赖 `GET /me/consent/status`、`POST /me/consent/privacy`、
  `POST /me/consent/terms`，后端**全部 404**（每个页面轮询报错，横幅永不出现）。
- **实现**：`api/src/routes/me-gap.ts` 新增 3 个端点（jwtAuth）：
  - `GET /me/consent/status` → `{ status: none|privacy_pending|tos_pending|both_pending, privacy_policy, terms_of_service }`；
    **pending 判定在 SQL 内完成**（用户最近一次 agree 早于策略更新 → 需重新确认），
    规避客户端时区解析差异（见 §4.4）。
  - `POST /me/consent/privacy|terms` → 每次同意写一条新 `consent_logs`（版本升级后重新确认产生新时间戳）+ 审计。
- **闭环验证**（演练 A25/A26/U69/U76/U76b）：管理员升级隐私政策 v3→v8 → 用户状态变
  `privacy_pending` → 用户重新同意 → 状态回 `none`。✅

### 1.3 P2 — `/admin/roles/permissions/list` 缺失

## 4. 发现的问题（按优先级）

### 4.1 P1 — 前端→后端契约缺口 7 项（页面可渲染，数据接口 404）

| 前端页面 | 缺失后端接口 |

| 在线客服 `/app/chat` | `GET /api/v1/me/chat/history` |

| 模型管理 `/app/admin/models` | `GET /api/v1/admin/models`（列表；仅存在 `/models/:id`、`/models/marketplace`） |

> 影响：页面骨架可渲染但数据区为空/报错，功能不可用。建议后端按前端契约补齐（多数为只读查询，
> 已有对应表/服务可复用）。

### 4.2 P2 — 演练时区/序列化观察（本机 Asia/Shanghai 会话）

- postgres-js 在会话时区非 UTC 时，**drizzle 写入的 `new Date()` 参数存在 8 小时偏移**：
  `consent_policies.updated_at`（API 写入）比 PG `now()`（默认值）早 8h，导致跨源时间比较错乱。
  已在协议策略更新端点改用 `sql\`now()\`` 修复；**建议排查全库其他 `updatedAt: new Date()` 写入点**
  （如定时公告 `publish_at` 未来排期在 cron 比较下会晚 8h 触发），统一改为 PG now() 或
  在 db 连接上固定 `timezone: 'UTC'`。
