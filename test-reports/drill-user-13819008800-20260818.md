## 4. 发现的问题与系统改进建议

### 4.1 P1 — 阻断真实用户资金/使用的缺陷

**① 无余额账户行的用户资金操作 404（BALANCE_NOT_FOUND）**
- 现象：user 57（及约 **1075/4210** 个历史用户）无 `customer_balances` 行；管理员审核充值、兑换码兑换均返回 404 `Balance account not found`，资金无法入账。
- 根因：运行中 API 为旧快照，充值审核走裸 `UPDATE customer_balances`、兑换走 `addBalance`，均**不自动建户**；工作区 `api/src/services/billing/balance.ts` 的 `creditBalance`（INSERT ON CONFLICT DO NOTHING 自动建户 + 审计）与 `recharge.ts` 的收口已写入但**未提交且未生效**（API 进程 21:49 启动，早于 23:03 的文件修改）。
- 建议：① 重启 API 使 creditBalance 收口生效；② **兑换码 redeem 路径统一到 creditBalance**（代码注释自述「本期未收口（裁决 Q6）」，但对历史用户是真实 404 面）；③ 提交该批修复并补回归测试；④ 对存量无余额行用户做一次性数据修复（幂等 INSERT 兜底脚本）。

**② 网关调用被上游 401 阻断，无 mock 回退（当前环境直接不可用）**
- 现象：余额充足时 `POST /v1/chat/completions` 返回 `401 Authentication Fails, Your api key: ****5eb0 is invalid`（DeepSeek 上游格式，掩码 key 与用户 key 无关）；`GET /anthropic/v1/models` 正常。
- 影响：用户会误以为自己的 API Key 无效；当前环境（供应商全部 offline、`supplier_keys` 为空）下**所有真实模型调用失败**。
- 建议：① API 重启后复测（磁盘代码已有 `mockFallback` 路径，疑似旧快照未生效）；② 若仍复现，排查上游默认 key 配置来源（运行代码中含已不存在的 `****5eb0` key）；③ 网关对上游 401 应区分「用户 key 无效」与「平台上游故障」：后者应返回 503/502 并注明「平台上游异常，请稍后重试」，而不是透传上游格式错误误导用户；④ 增加上游认证失败的故障转移/熔断。

### 4.2 P2 — 用户端功能缺口

**③ 帮助中心知识库接口缺失**
- 现象：前端 `HelpCenterPage` 依赖 `GET /me/knowledge-base` 与 `GET /me/knowledge-base/categories`，后端仅实现 `POST /me/knowledge-base/:id/feedback`（反馈）与 admin 的 `/admin/knowledge-base`；两个用户端 GET 均 **404** → `/app/help` 页面文章列表不可用。
- 建议：补齐用户端知识库列表/分类接口（复用 `knowledge_base_articles` 表，仅返回已发布文章），前端联调验收。

**④ 空 JSON body 端点兼容性（FST_ERR_CTP_EMPTY_JSON_BODY）**
- 现象：9 个无体端点（工单解决、公告/通知 read-all、2FA setup、Webhook 测试/重置密钥/删除、数据导出撤回、登出）在请求头带 `Content-Type: application/json` 且无 body 时返回 400。
- 影响：前端 axios 在无 data 时不带该头，**UI 正常**；但 curl/Postman/外部 SDK 直连 `-H 'Content-Type: application/json'` 必踩。
- 建议：在 Fastify 层统一对空 JSON body 按 `{}` 处理（或这些端点不声明 JSON content-type），并在 API 文档标注；新增集成测试覆盖「无体 POST/DELETE + JSON 头」。

### 4.3 P3 — 体验 / 文案 / 安全基线

**⑤ 402 文案矛盾**：`Insufficient balance: have 0, need 0` — need=0 仍拒绝，无法理解；0 余额首调应引导充值/体验金。建议：成本估算为 0 时按最小计价单位预扣或给出「余额不足，请充值」+ 充值入口。

**⑥ 兑换码 EXISTS 错误不带 requestId**：`AppError` 的 details（`{requestId}`）未随响应返回，客户端无法定位/取消进行中的申请。建议序列化 details 或返回 pending 申请 id。

**⑦ 安全基线弱**：演练账号为 8 位纯数字口令、未开 2FA。建议：注册密码策略（长度/复杂度）、弱口令检测、登录失败风控、安全中心引导开启 2FA（已有完整 2FA 流程，本次演练全流程通过）。

**⑧ 用户端模型列表被测试数据污染**：965 个模型中大量 `market-test-*`/`alias-upstream-*`/`compat-*` 测试模型，用户选择器/定价页体验差。建议：用户端仅展示 `is_active` 且非测试标记的模型（或按分组白名单过滤）。

**⑨ 支付通道配置**：支付宝通道未启用、对公收款户名为「测试公司」占位。上线前需在后台配置真实支付通道与对公账户（`payment_config`），并补充通道未启用时的前端禁用/提示一致性。

**⑩ `/app/` 尾斜杠 308**：Next.js 尾斜杠规范化行为，建议统一为 `/app`（无尾斜杠）或加 301 到规范 URL，避免不必要的重定向一跳。

### 4.4 运行环境一致性（运维注意事项）

- 当前 API（PID 9012，21:49 启动）执行的是**早于工作区的代码快照**：工作区 23:03–23:04 有未提交修复（creditBalance 收口、R4 入账通知、requirePerm 鉴权、审计留痕、migration 0026-0028 等，疑似另一会话在途）。
- **建议：协调在途会话完成后统一提交并重启 API，重启后按 §5 回归清单复测**，重点验证：充值审核自动建户、兑换码兑换、入账通知、网关调用（含 mock 回退）、帮助中心接口。
