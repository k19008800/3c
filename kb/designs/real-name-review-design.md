# 实名审核系统 — 完整功能设计方案

> 更新：OCR 证件识别（身份证+营业执照）+ 自动填充 + 审核附件浏览

---

## 一、现状诊断

**核心问题：** 注册提交的证件附件在审核侧看不到。

**根因：** 用户上传的证件图片存为本地相对路径（如 `/real-name/1/3_id_front.jpg`），审核弹窗 `<img>` 直接使用该路径作为图片 URL，浏览器无法加载。

**已有基础设施但未利用：**

| 资源 | 路径 | 状态 |
|------|------|------|
| 管理员文件服务 | `GET /api/v1/admin/real-name/file/:userId/:filename` | ✅ 存在 ✅ 已注册 |
| 用户文件服务 | `GET /api/v1/auth/real-name/file/:filename` | ✅ 存在 ✅ 已注册 |
| 审核列表 API | `GET /api/v1/admin/real-name-reviews` | ✅ 正常 |
| 审核弹窗 UI | `RealNameReview.tsx` | ❌ 图片 URL 未正确拼接 |
| 阿里云身份核验 | `AliyunIdVerifyProvider` | ✅ 已接入（姓名+身份证号二要素） |
| 阿里云 OCR 身份证识别 | 不存在 | ❌ 需要新增 |
| 阿里云 OCR 营业执照识别 | 不存在 | ❌ 需要新增 |

### 3.1 🔑 OCR 证件信息识别（核心新增）

#### OCR 覆三种证件类型

| 证件类型 | 文件类型标识 | 识别内容 | 用户端自动填充 |
|----------|-------------|---------|---------------|
| 身份证正面 | `id_front` | 姓名、身份证号、性别、民族、出生日期、地址 | ✅ 姓名 + 身份证号 |
| 身份证反面 | `id_back` | 签发机关、有效期 | ℹ️ 仅供审核参考 |
| 营业执照 | `business_license` | 企业名称、统一信用代码、法人代表、注册资本、成立日期、有效期、注册地址 | ✅ 企业名称 + 信用代码 + 法人 |

#### OCR 接口设计

```typescript
// POST /api/v1/auth/real-name/ocr
// Input: { filePath: string, fileType: "id_front" | "id_back" | "business_license" }

// 身份证接口返回值
interface IdCardOcrResult {
  type: 'id_card';
  name?: string;           // 姓名
  idNumber?: string;       // 身份证号
  gender?: string;         // 性别
  nationality?: string;    // 民族
  birthDate?: string;      // 出生日期
  address?: string;        // 住址
  issuedBy?: string;       // 签发机关（反面）
  validDate?: string;      // 有效期（反面）
  confidence: number;      // 整体识别置信度 0-1
  rawResult?: Record<string, any>;
}

// 营业执照接口返回值
interface BusinessLicenseOcrResult {
  type: 'business_license';
  companyName?: string;     // 企业名称
  regNumber?: string;       // 统一社会信用代码
  legalPerson?: string;     // 法定代表人
  registeredCapital?: string; // 注册资本
  establishedDate?: string; // 成立日期
  validPeriod?: string;     // 营业期限/有效期
  address?: string;         // 注册地址
  businessScope?: string;   // 经营范围
  confidence: number;       // 整体识别置信度 0-1
  rawResult?: Record<string, any>;
}

type OcrResponse = IdCardOcrResult | BusinessLicenseOcrResult;
```

#### OCR 供应商选择

| 方案 | 成本 | 准确率 | 身份证识别 | 营业执照识别 | 集成复杂度 |
|------|------|--------|-----------|-------------|-----------|
| **阿里云文字识别** | 按量约 0.01 元/次 | 98%+ | ✅ 专用 API | ✅ 专用 API | 低 |
| **腾讯云 OCR** | 类似阿里云 | 98%+ | ✅ | ✅ | 低 |
| **百度云 OCR** | 类似 | 98%+ | ✅ | ✅ | 低 |
| **DeepSeek/GPT 视觉** | API 按 token | 90%+ | ✅ (图片理解) | ✅ (图片理解) | 低（无需接口对接）|
| **自建 PaddleOCR** | 免费需 GPU | 95% | ✅ | ✅ (需额外模型) | 需部署 |

**推荐方案（二选一）：**

**方案 A：DeepSeek/GPT 视觉模型（先验证，0 成本）**
- 上传图片 → base64 → 调用 DeepSeek/GPT 视觉模型
- Prompt 指定提取字段
- 初期无需对接任何第三方 OCR API
- 适合验证阶段

**方案 B：阿里云市场 OCR（正式上线）**
- 身份证识别 API：`https://yhk.market.alicloudapi.com/ocr/idcard`
- 营业执照识别 API：`https://yhk.market.alicloudapi.com/ocr/businessLicense`
- 配置 key 放在 `system_configs` 表，支持动态切换

### 3.2 🖼️ 审核弹窗附件浏览（修复现有问题）

#### 文件 URL 映射

审核列表 API 返回的图像字段存的是相对路径（如 `/real-name/1/3_id_front.jpg`），前端需要拼接为可访问 URL：

```typescript
// 工具函数
function getAdminFileUrl(userId: number, relativePath: string | null): string | null {
  if (!relativePath) return null
  const filename = relativePath.split('/').pop()
  if (!filename) return null
  return `/api/v1/admin/real-name/file/${userId}/${filename}`
}

// 使用
getAdminFileUrl(selected.userId, selected.idFrontImage)
// → /api/v1/admin/real-name/file/3/5_id_front.jpg
```

- 不一致可秒发现：用户填"张三"，OCR 识别"张二" → 直接拒绝
- 营业执照 OCR 识别企业名+信用代码自动校验一致性
- 有效期自动检测是否过期（身份证超期直接预警）

### 4.5 上传 → OCR → 提交流程

```
Step 1: 用户选择证件图片（身份证/营业执照）
Step 2: 前端自动触发 upload 到服务器
Step 3: 上传完成后自动调用 OCR 端点
Step 4: OCR 结果回填表单对应字段
Step 5: 表单字段显示 📸 来源标记（用户可见）
Step 6: 用户核对信息无误 → 点击"提交"
Step 7: 提交时携带 { idFrontImage, idBackImage, businessLicense, ocrResult }
Step 8: 后端保存到 userRealNameReviews
Step 9: 审核员在后台可见原图 + OCR 对比信息
```

### 4.6 营业执照 PDF 特殊处理

企业营业执照可能以 PDF 格式上传（当前 schema 已支持），有两种处理方式：

| 方式 | 说明 | 适用阶段 |
|------|------|---------|
| 直接拒绝 PDF | 前端限制只能上传图片，OCR 只能识别图片 | 严格方案 |
| PDF 转图片 | 后端用 `sharp` 或 `pdf2pic` 转第一页为 JPEG，再送 OCR | 宽松方案 |

**推荐：前期限制只接受图片（JPG/PNG），PDF 支持作为后续增强。**

## 六、关键交互细节

### 6.1 OCR 失败的兜底

```
场景：OCR 服务不可用 / 图片不清晰 / 识别失败

用户上传后 → OCR 调用 → 识别失败
                   ↓
┌──────────────────────────────────────┐
│  ⚠️ 证件识别失败                      │
│  原因：图片不清晰 / 服务异常          │
│  [重新上传]  [跳过，手动填写]         │
│                                       │
│  选择跳过后，用户需手动输入姓名和身份证号│
└──────────────────────────────────────┘
```

### 6.2 多次提交的版本管理

```
v3 (当前待审)  → 审核员查看 v3 的附件 + OCR 结果
v2 (已拒绝)    → 审核员可切换查看 v2 的附件
v1 (已拒绝)    → 审核员可切换查看 v1 的附件

每个版本独立记录：
  - name, idNumber, companyName
  - idFrontImage, idBackImage, businessLicense
  - ocr_result (JSONB) — 包含所有已识别结果
```

### 6.3 审核结论对 OCR 的引用

```
审核通过时：
  如果 OCR 识别存在，用 OCR 识别的姓名+身份证号更新 users 表
  （OCR 比用户手动输入更可靠）

审核拒绝时：
  审核员参考 OCR 对比表快速判断不一致
  "用户填'张三'，OCR 识别'张二'" → 信息不符，拒绝
  "营业执照 OCR 识别企业名是'A公司'，用户填'B公司'" → 拒绝
```
