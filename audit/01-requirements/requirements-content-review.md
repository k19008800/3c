# 需求原子清单内容质量复核

## 当前结论

需求原子清单已满足 CSV 结构、编号唯一、源文件存在和基础引用匹配要求，但**尚未满足正式验收要求**。当前内容质量门禁为 `FAIL`，不得将需求清单标记为“已完整通过”。

## 当前发现

- 有效需求记录：13,936 条。
- 疑似编码损坏、复合断言、源文档重建等问题仍需人工处理。
- 当前质量门禁总发现：2,627 项；字段级发现可能来自同一需求记录的多个字段，不能直接当作 2,627 条独立需求缺陷。

## 修复原则

1. 不根据乱码文本猜测原文；无法可靠恢复的条目保持 `UNKNOWN`，并记录缺失原因。
2. `source_quote` 必须是目标 `source_path` 中可定位的原文片段。
3. `source_section` 必须引用源文档真实标题或明确的源位置，不使用推测标题。
4. `atomic_assertion` 一行只保留一个可独立验证的断言；拆分后为每个断言建立独立 `req_id` 或保留可追溯的拆分关系。
5. 修复后必须重新运行结构、引用、报告重建和源完整性校验。
6. 不修改业务源码，不覆盖旧版 CSV；修复结果只写入新的 reviewed 产物或经审阅后替换。

### 人工复核字段约束

| 字段 | 通过条件 | 否决/保留条件 |
|---|---|---|
| `section_check` | 章节标题或明确位置能回到当前 `source_path` | 章节错配、仅凭推测或无法定位 |
| `quote_check` | 引用是当前源文档的完整准确原文，行号一致 | 截断、拼接、仅匹配乱码行或行号不一致 |
| `assertion_check` | 一个可独立验证的条件、动作或结果 | 多动作、多结果、条件与副作用混在一行 |
| `format_risk_check` | 标点、路径、数值和 Markdown 结构均可解释 | 任何未经确认的格式、数值或路径变化 |

只有四项均通过并在 `review_notes` 留下依据，才可填写 `review_decision=APPROVE`。否则保持 `PENDING`，或根据证据填写 `UNKNOWN`/`REJECT`。

### 形成正式 reviewed 清单的闸门

1. 人工复核表完成逐条签核；
2. `APPROVE` 条目能回到当前可读源文档；
3. `UNKNOWN`、`REJECT` 和未处理条目不得进入正式通过集；
4. 生成新的 reviewed 版本并保留 `derived_from`/`req_id` 追踪关系；
5. 重新运行结构、引用、复合断言和报告门禁；
6. canonical v2 仅在明确批准后才可另行更新，不能由机械脚本覆盖。

## 验收门槛

- 疑似编码损坏：0 条未处理发现，或每条都有人工复核结论。
- 复合断言：0 条未处理发现，或每条有明确的拆分依据与关联 ID。
- 源引用逐条可回溯。
- 需求内容门禁通过后，仍需另外完成源码定位和测试证据闭环；需求门禁通过不等于业务实现通过。
