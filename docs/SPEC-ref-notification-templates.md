# 统一通知模板引擎：SPEC-ref-notification-templates

> **关联文档**：§4.15 系统通知广播、§4.23 外部通知渠道集成、§9.3 财务日报推送、§22.6 通知偏好
> **优先级**：P1
> **核心价值**：统一管理全平台通知模板，确保多渠道格式一致，避免各模块重复开发

---

## 概述

当前各模块的通知推送分散定义在不同的 SPEC 文档中，存在以下问题：

1. **格式不统一**：§4.23 定义了企业微信/钉钉/飞书各渠道的模板格式，但 §4.15 广播通知和 §9.3 日报推送未定义多渠道适配
2. **模板管理碎片化**：邮件模板在 §4.5.4、站内通知在各模块分别定义，缺少统一模板引擎
3. **变量体系不一致**：各模块使用不同的变量占位符（`{{xxx}}`/`${xxx}`/`{xxx}`）

本 SPEC 定义一个统一的**通知模板引擎**，所有通知渠道共享同一个模板库和变量体系。

---

## 1. 模板引擎架构

```
发送方（各模块）         模板引擎                   渠道适配器              接收渠道
────────────     ─────────────────     ────────────────     ────────────
§4.15 广播通知 ─→  ├─ 模板选择      ─→ ├─ 站内通知渲染   ─→ 站内通知
§9.3 日报推送  ─→  ├─ 变量替换      ─→ ├─ 邮件渲染       ─→ SMTP 邮件
§5.4 告警规则  ─→  ├─ 渠道分发      ─→ ├─ 企微 Markdown  ─→ 企业微信群
§22.6 通知偏好 ─→  ├─ 频率控制      ─→ ├─ 钉钉 Markdown  ─→ 钉钉群
                    └─ 失败重试      ─→ └─ 飞书卡片      ─→ 飞书群
                                         └─ Slack 消息   ─→ Slack 频道
```

### 1.1 模板引擎核心流程

```
触发事件 → ① 查询用户/管理员通知偏好（§22.6）
         ② 按偏好渠道选择对应的模板
         ③ 变量替换（统一变量体系）
         ④ 渠道适配器将通用模板渲染为渠道特有格式
         ⑤ 发送 + 失败重试（3 次，指数退避）
         ⑥ 记录发送日志（时间/渠道/状态/错误）
```

## 2. 统一变量体系

所有通知模板使用统一的变量占位符格式 `{{变量名}}`，支持以下内置变量：

### 2.1 全局变量/通用变量

| 变量 | 说明 | 示例值 |
|------|------|--------|
| `{{site_name}}` | 平台名称 | 3Cloud |

| `{{admin_url}}` | 管理后台地址 | https://api.unmisa.com/admin |
| `{{current_time}}` | 当前时间 | 2026-07-28 14:30 |
| `{{operator_name}}` | 操作管理员 | admin@3cloud.ai |

### 3.3 渠道模板差异处理

| 渠道 | 消息类型 | 内容限制 | 富文本支持 | 特殊说明 |
|------|---------|---------|-----------|---------|
| 站内通知 | 标题+纯文本 | 无 | 支持简单 HTML | 可嵌入超链接 |
| 邮件 | 标题+HTML正文 | 无 | 完整 HTML | 支持 CSS 样式，含页脚退订链接 |
| 企业微信 | Markdown | 4096 字节 | Markdown 子集 | 支持 @所有人/@指定成员 |
| 钉钉 | Markdown | 2048 字节 | Markdown 子集 | 支持 @所有人 |
| 飞书 | 消息卡片 JSON | 30 个元素 | 富文本卡片 | 支持交互式按钮 |
| Slack | Block Kit JSON | 50 个 block | Block Kit | 支持按钮/选择器交互 |

## 4. 场景与模板映射

### 4.1 事件通知场景

| 场景 | 触发事件 | 默认推送渠道 | 优先级 | 防打扰规则 |
|------|---------|------------|--------|-----------|
| 充值成功 | 充值回调成功 | 站内通知 + 邮件 | P0 | 无限制 |
| 充值异常 | 充值支付成功余额未增 | 站内通知 + 企微/钉钉 | P0 | 每事件即时 |
| 余额不足 | 余额 < ¥10 | 站内通知 + 邮件 | P1 | 每日最多 1 次 |
| API Key 过期 | 过期前 7/3/1 天 | 站内通知 + 邮件 | P1 | 每 Key 独立 |
| 实名审核通过 | 审核状态变更为通过 | 站内通知 | P1 | 无限制 |
| 实名审核驳回 | 审核状态变更为驳回 | 站内通知 + 邮件 | P1 | 无限制 |
| 工单回复 | 客服回复工单 | 站内通知 + 邮件 | P0 | 无限制 |
| 安全事件 | 风控规则命中 | 站内通知 (管理员) + 企微 | P0 | 每事件即时 |
| 代理提现申请 | 代理提交提现 | 站内通知 (财务) + 企微 | P0 | 每申请即时 |
| 代理提现完成 | 提现打款完成 | 站内通知 + 邮件 (代理) | P1 | 无限制 |
| 供应商可用率下降 | 可用率 < 99% | 企微/钉钉群 | P0 | 每 5 分钟汇总 |
| 系统错误率上升 | 5xx > 5% | 企微/钉钉群 | P0 | 每事件即时 |

### 4.2 定时推送场景

| 场景 | 推送时间 | 渠道 | 内容 | 数据来源 |
|------|---------|------|------|---------|
| 财务日报 | 每日 9:00 | 邮件 + 企微 | 昨日收入/支出/充值/提现/新增用户 | §9.3 |
| 运营周报 | 每周一 10:00 | 邮件 | 上周营收/用户/调用量/活动效果 | §4.9 |
| 系统健康报告 | 每日 8:00 | 企微 | CPU/内存/磁盘/API P99/数据库连接 | §12.6 |

## 5. 模板优先级与覆盖规则

```
全局默认模板 → 模块自定义模板 → 用户/管理员自定义模板（优先级递增）

全局默认模板：系统初始化时创建的种子数据，各场景必备
模块自定义模板：各功能模块可覆盖全局模板（如财务模块自定义日报模板）
用户/管理员自定义：用户可在通知偏好中覆盖自己的模板（仅影响个人收到的通知）
```

## 6. 通知发送日志

每条通知发送记录写入 `notification_logs` 表：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | serial | 主键 |
| event_type | varchar(50) | 事件类型（recharge_success / balance_low 等）|
| channel | varchar(20) | 推送渠道（notification / email / wecom / dingtalk 等）|
| template_id | int | 使用的模板 ID |
| recipient | text | 接收方（用户ID / 邮箱 / Webhook URL）|
| variables | jsonb | 替换变量快照 |
| content | text | 实际发送内容快照 |
| status | varchar(20) | success / failed / pending |
| error | text | 失败原因 |
| sent_at | timestamp | 发送时间 |
| delivered_at | timestamp | 到达确认时间（部分渠道支持）|

**留痕要求**：所有通知日志保留 180 天（与调用日志同级），失败记录标注重试次数和最终状态。

## 8. 验收标准

1. 管理后台 → 通知模板 → 显示所有场景的模板列表
2. 编辑模板 → 修改企业微信和钉钉的渠道模板 → 保存 → 下次触发使用新模板
3. 模板使用 `{{user_name}}` 变量 → 发送时自动替换为实际用户名
4. 使用不存在的变量（如 `{{unknown_var}}`）→ 发送时保留原样 `{{unknown_var}}`
5. 测试发送 → 指定渠道收到测试消息，内容正确渲染
6. 通知发送失败 → 自动重试 3 次 → 仍失败 → 记录错误日志 + 标记通知状态为 failed
7. 变量注入防护：变量值包含恶意内容（HTML/JS）→ 各渠道模板自动转义
