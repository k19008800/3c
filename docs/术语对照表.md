# 3Cloud 术语对照表（渠道化统一口径）

> 适用范围：3cloud 全部 PRD / SPEC / kb 文档 / 运营手册 / 评审材料。
> 使用方式：当文档中出现本表所列对象时，统一采用“新统一中文”。底层英文标识、表名、字段名、接口路径、组件名、类型名 **保留不改**。

## 1. 统一口径

> 本表的「旧称谓（不再使用）」一栏刻意保留**旧词原文**（供应商/厂商/Vendor 等）供对照回溯；它不属于需要被替换为“渠道”的正文，而是术语表自身记录旧称的引用列。

| 新统一中文 | 旧称谓（不再使用） | 底层英文标识 | 说明 |
|---|---|---|---|
| 渠道 | 供应商 / 厂商 / Vendor | `suppliers` | 上游提供模型、Key、结算能力的业务实体。此标识保留不改，仅展示层中文化。 |
| 渠道密钥 / 渠道 Key | 供应商密钥 / 供应商 Key | `supplier_keys` | 渠道侧凭据管理对象。此标识保留不改，仅展示层中文化。 |
| 渠道模型 / 渠道-模型映射 | 供应商模型 | `supplier_models` | 某渠道提供的某模型。此标识保留不改，仅展示层中文化。 |
| 渠道售价 / 渠道价目 | 供应商定价 / 供应商价目 | `vendor_pricing` | 面向用户展示的售价口径。此标识保留不改，仅展示层中文化。 |
| 渠道成本价 | 供应商成本 / 供应商成本价 | `supplier_models.cost_*` | 平台内部采购成本，不对用户展示。此标识保留不改，仅展示层中文化。 |
| 渠道中心 / 渠道门户 | 供应商门户 / 供应商中心 | `Vendor*` 页面 | 渠道侧登录、Key 管理、数据统计、结算等页面。此标识保留不改，仅展示层中文化。 |
| 渠道结算 | 供应商结算 | `vendor-settlements` | 渠道侧的结算对账与账单流程。此标识保留不改，仅展示层中文化。 |
| 渠道分组供给 | 供应商分组 / 渠道分组 | `suppliers.allowed_groups` | 渠道可服务哪些用户分组。此标识保留不改，仅展示层中文化。 |

## 2. 术语替换规则

1. 文档正文中凡涉及上述业务对象的中文称谓，统一改为“渠道”体系。
2. 只改中文展示语，不改任何代码标识符、接口路径、表名、字段名、变量名、类型名、组件名。
3. **例外**：术语对照表/词汇表/映射表中的「旧称谓」引用列、以及需要说明旧称的文档段落，**应保留“供应商/厂商”旧词原文**，不应替换。
4. 如果某文档需要保留英文对照，保留原英文标识，并在中文处使用本表术语。

## 3. 供所有 Agent 引用的写法

- 写 PRD / SPEC / 文档标题时：优先使用“渠道”。
- 描述业务角色时：使用“渠道”，避免在正文中再用“供应商/厂商”。
- 描述后台结算与管理页面时：使用“渠道中心”“渠道结算”“渠道售价”“渠道密钥”。
- 描述技术实现时：继续保留 `suppliers`、`supplier_keys`、`supplier_models`、`vendor_pricing`、`Vendor*` 等英文标识原样不动。

## 4. 备注

- 本文档只约束展示层中文称谓，不构成数据库重命名或接口迁移要求。
- 若后续新增术语，以 PRD / SPEC 中的最新统一口径为准。
