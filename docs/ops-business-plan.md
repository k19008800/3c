# 3cloud 平台运营方案与系统迭代建议（v2）

> **视角**：平台管理方，在纯按量计费、无推荐体系的前提下，如何拓客、运营、迭代
> **前提**：保留现有三级代理制 + 纯按量计费 + 兑换码系统
> **最后更新**：2026-07-28

---

## 一、核心定位（不变）

```
3cloud 本质 = AI API 批发转售平台

  上游：向 DeepSeek / OpenAI / Anthropic 等供应商批量采购
  中游：智能路由 + 精细计费 + 多级分销
  下游：开发者 / 中小企业 / 代理渠道

  利润模型 = 采购价与售价之间的差价 + 代理商佣金抽成
  竞争壁垒 = 多模型聚合 + 智能路由 + 精细的运营管理工具

  没有推荐系统，就没有自传播 → 就必须靠主动拓客和内容营销
  没有套餐，就没预付费 → 就必须靠充值优惠和兑换码驱动
```

|------|------|------|---------|
| **技术部** | 后端 | 3 | API 核心、计费、路由、供应商接入 |
| | 前端 | 2 | 控制台、Portal、管理后台 |
| | 运维 | 1 | 服务器、CI/CD、监控 |

**关键区别**：去掉了推荐体系，市场部的作用更重——内容营销团队需要主动制造流量，而不是靠用户自传播。

## 三、拓客策略（调整版）

### 3.1 当前系统的拓客优势

| 优势 | 说明 |
|------|------|
| 代理商体系 | 三级代理制，预备→一级→高级，天然的分销引擎 |
| 兑换码系统 | 已有的活动系统可以生成兑换码给代理分发 |
| 免费试用 | 注册即送 ¥5 试用额度，降低决策门槛 |
| OpenAI 兼容 | 零代码迁移，开发者的最低切换成本 |
| 多模型聚合 | 130+ 模型，一站式满足各种需求 |
| 开发者 Portal | 文档齐全、Playground 在线测试、快速上手 |

### 3.2 拓客渠道矩阵

```
渠道矩阵：
┌──────────────────┬──────────────────┐
│                  │                  │
│ 代理商网络（主力）  │ 内容营销（驱动）  │
│  贡献 50% 用户    │  贡献 25% 用户   │
│                  │                  │
├──────────────────┼──────────────────┤
│                  │                  │
│ 企业客户直营      │ 运营活动（催化）  │
│  贡献 15% 收入    │  贡献 10% 转化   │
│                  │                  │
└──────────────────┴──────────────────┘

没有推荐系统 → 代理商网络和内容营销是核心引擎
没有套餐 → 兑换码和充值活动是核心转化工具
```

### 3.3 渠道 A：代理商网络（主力，贡献 50%+）

**现状**：已有一级代理制，但代理招募、赋能、激励工具薄弱。

**核心问题**：没有推荐链接，代理如何拉人？

**解决方案**：用**兑换码作为代理的拉新工具**

```
每个代理可以申请专属兑换码配额：
  - 一级代理：每月可申请 100 个兑换码（¥10 面值）
  - 高级代理：每月可申请 500 个兑换码（¥10 + ¥50 面值）
  - 代理自行分发兑换码给客户
  - 用户使用兑换码后自动关联到该代理名下

兑换码的"拉新追踪"能力：
  每个兑换码生成时，绑定到代理 ID
  用户兑换时，系统自动建立代理-用户关联
  代理后台可查看兑换码使用情况（谁用了、什么时候用的）
```

**系统需要新增的功能**：

| 需求 | 规格 | 优先级 |
|------|------|--------|
| 代理兑换码配额管理 | 运营端配置每个代理的月配额 | P0 |
| 兑换码绑定代理 | 生成时关联 agent_id，兑换后自动绑定 | P0 |
| 代理兑换码使用统计 | 代理后台查看兑换码分发/使用数据 | P0 |
| 代理推广素材库 | 海报、文案模板、使用教程（文件管理） | P1 |
| 代理排行榜 | 按拉新数/消费额排名，激励竞争 | P1 |
| 代理自动晋升提醒 | 条件满足时自动通知 | P1 |

### 3.5 渠道 C：企业客户直营（贡献 15% 收入）

**现有系统已支持**：企业认证 ✅ 发票 ✅ 对公转账 ✅

**当前缺失 / 待加强**：

| 需求 | 规格 | 优先级 |

### 3.6 渠道 D：运营活动（催化，贡献 10% 转化）

**现有系统已有**：活动系统 ✅ 兑换码系统 ✅ 公告系统 ✅ 邮件模板 ✅

**重点强化**：利用现有活动系统做充值转化

## 四、用户生命周期运营（强化版）

### 4.1 各阶段运营动作

| 阶段 | 时间 | 目标 | 运营动作 | 系统支持 |
|------|------|------|---------|---------|
| 触达 | — | 让用户知道 3cloud | 内容营销 + 代理商推广 + 广告 | ❌ 无营销页分析 |
| 注册 | Day 0 | 完成 Onboarding | 引导创建 Key + 首次调用 | ✅ Onboarding 引导 |
| 激活 | Day 1-3 | 体验 API 调用 | 发送使用教程、Playground 引导 | ✅ Playground |
| 首充 | 试用耗尽 | 完成首次充值 | 余额不足提醒 → 展示充值活动 | ✅ 余额告警 |
| 活跃 | 首充后 7 天 | 持续调用 | 推送新模型上线、成本优化建议 | ✅ 模型推荐 |
| 留存 | 30 天 | 稳定消费 | 账单推送、充值活动通知 | ✅ 账单周期 |
| 流失预警 | 7 天无调用 | 召回 | 发送召回邮件、推送新模型 | ❌ 无自动召回 |
| 沉睡 | 30 天无登录 | 重新激活 | 推送兑换码优惠、新功能通知 | ❌ 无自动沉睡策略 |

### 4.2 流失召回（需要新增）

```
自动化召回规则（运营端配置）：

规则 1：7 天无调用
  → 发送邮件："最近是不是太忙了？3cloud 新上了 3 个模型，来看看"
  → 站内通知：推送新模型上线信息

规则 2：14 天无调用
  → 发送邮件："回来看看吧，送你 ¥10 体验金"
  → 自动发放兑换码到用户账户
  → 站内通知：提示有优惠券可用

规则 3：30 天无登录
  → 发送邮件："账号即将进入休眠状态"
  → 站内通知：最后提醒

规则 4：首次充值后 15 天无二次充值
  → 发送邮件："首充用户福利，再充送 ¥20"
  → 展示专属充值活动
```

### 4.3 用户分群运营

```
用户分层 → 运营策略：

高价值用户（月消费 ¥500+）：
  - 专属客服对接
  - 新模型抢先体验
  - 定期用量报告

活跃用户（月消费 ¥100-500）：
  - 推送充值活动通知
  - 定期推送成本优化建议
  - 邀请参与产品调研

普通用户（月消费 ¥10-100）：
  - 邮件推送活动通知
  - 新模型上线通知

休眠用户（有登录无消费）：
  - 推送兑换码优惠
  - 推送新模型/新功能

流失用户（30 天无登录）：
  - 自动化召回
  - 3 次召回无效 → 标记为沉默用户
```

## 五、系统迭代建议（按优先级）

### P0 — 必须做（直接影响拓客和转化）

#### 1. 代理兑换码配额与绑定

```
现状：代理无法通过兑换码拉新，无法追踪拉新效果
价值：让代理有可量化的拉新工具

功能规格：
  - 运营端：配置每个代理的月兑换码配额（数量 + 面值）
  - 代理端：申请兑换码配额 → 运营审核 → 代理获得兑换码
  - 生成兑换码时绑定 agent_id
  - 用户兑换后自动建立代理-用户关联
  - 代理后台：兑换码使用统计（已发放/已使用/余额）

API 接口：
  POST /api/v1/admin/agents/:id/redemption-quota → 设置配额
  GET  /api/v1/agent/redemption-codes → 代理查看兑换码
  GET  /api/v1/agent/redemption-stats → 代理兑换统计
  （兑换码兑换接口已有）

Schema 变更：
  agent_redemption_quotas 表（配额配置）
  campaigns 或 campaign_codes 表新增 agent_id 字段
```

#### 2. 充值活动自动赠送

```
现状：充值活动需要用户手动输入兑换码，转化率低
价值：充值后自动赠送，大幅提升活动参与率

功能规格：
  - 运营端创建活动时，选择"自动赠送"模式
  - 用户充值后，系统自动发放兑换码到用户账户
  - 用户可查看"我的优惠券"中已到账的兑换码
  - 用户余额不足时优先展示可用优惠券

API 接口：
  POST /api/v1/admin/campaigns/:id/auto-grant → 配置自动赠送规则
  GET  /api/v1/me/coupons → 我的优惠券列表（新增）
  POST /api/v1/me/coupons/:id/redeem → 兑换优惠券（新增）

前端变更：
  用户控制台 → 我的优惠券页面（新入口）
  充值成功页 → 展示到账优惠券
  余额不足时 → 提示可用优惠券
```

#### 3. 用户分群推送

```
现状：通知只能全部推送，无法针对特定用户群
价值：精准触达，提升转化率

功能规格：
  - 运营端创建用户分群规则：
    按注册时间 / 消费金额 / 最后登录时间 / 最后调用时间
  - 基于分群的推送任务：
    推送渠道：站内通知 + 邮件
    推送内容：模板 + 变量替换
  - 推送效果统计：发送量 / 打开率 / 转化率

API 接口：
  POST /api/v1/admin/user-segments → 创建用户分群
  POST /api/v1/admin/notifications/segment → 向分群推送通知
  GET  /api/v1/admin/notifications/stats → 推送统计

Schema 变更：
  user_segments 表（用户分群定义）
  segment_notifications 表（分群推送记录）
```

#### 4. 自动化流失召回

```
功能规格：
  - 运营端配置召回规则：
    触发条件：7 天无调用 / 14 天无调用 / 30 天无登录
    发送内容：邮件模板（可配置）
    发送渠道：邮件 + 站内通知
  - 自动发放兑换码作为召回奖励
  - 召回效果统计：发送量 / 打开率 / 召回率

API 接口：
  POST /api/v1/admin/recall-rules → 配置召回规则
  GET  /api/v1/admin/recall-stats → 召回效果统计
```

### P2 — 锦上添花（长期竞争力）

```
Schema 变更：
  user_events 表（用户行为事件）
```

#### 10. 竞品价格监控看板

```
功能规格：
  - 定期抓取竞品定价信息

  - 价格变动告警（竞品降价时通知运营）
```

## 八、总结

### 核心定位

```
纯按量计费 + 无推荐系统 → 拓客靠主动，转化靠活动

  代理商网络：用兑换码作为拉新工具（替代推荐链接）
  内容营销：用技术内容主动获取流量（替代自传播）
  运营活动：用充值优惠和兑换码驱动转化（替代套餐锁定）
```

### 系统迭代路线图

```
P0（本月）→ 代理兑换码配额 + 充值自动赠送 + 用户分群推送 + 自动化流失召回
P1（下月）→ 代理排行榜 + 推广素材库 + 企业版/团队协作  
P2（长期）→ 活动效果分析 + 用户行为分析 + 竞品监控
```

### 一句话总结

没有推荐机制和套餐，就把**代理商兑换码**和**运营活动**做到极致——用兑换码解决代理拉新追踪问题，用充值活动替代套餐的预付费价值，用内容营销替代自传播的流量来源。
