# 3Cloud 产品设计原则（Product Design Principles）

> 本文档定义 3Cloud 平台的底层产品设计基础要求。
> **所有功能模块、所有页面、所有操作入口的 UI 设计必须遵守本文档。**
> 后续任何新的 PRD、SPEC、功能迭代，在进入开发阶段前必须先确认满足本文档中所有适用的原则。

---

## P1: 每个操作入口必须有功能帮助说明

### 原则描述

**平台中的每个功能按钮、操作入口、页面标题旁都必须提供 `[?]` 帮助说明。**

| 层级 | 位置 | 触发方式 | 内容形式 |
|------|------|---------|---------|
| 页面级 | 页面/功能模块标题右侧 | 点击 `[?]` 弹出帮助弹窗 | 适用角色、功能定位、核心操作、注意事项、常见问题 |
| 按钮级 | 每个操作按钮/入口旁边 | 悬停 `[?]` 显示 Tooltip | 一句话说明该操作的作用 |

### 适用范围

- 管理后台所有页面（`/admin/*`）
- 用户端所有页面（`/dashboard/*`、`/profile/*` 等）
- Portal 门户（`/` 首页及各子页）
- 代理端所有页面
- 供应商自助管理页面
- 任何配置/编辑/操作弹窗和对话框

### 不适用范围

- 系统级错误提示页（404/500）
- 纯展示且无交互操作的页面区域（如统计数字、静态文本段落）

### 实现要求

```
// 页面级帮助：PageHelp 组件
<PageHeader title="用户管理">
  <PageHelpTrigger pageKey="user-management" />
</PageHeader>

// 按钮级帮助：ButtonHelp 组件或 Tooltip
<Button onClick={handleAction}>
  批量充值
  <ButtonHelp text="批量为选中用户充值指定金额" />
</Button>
```

### 内容来源

每个 SPEC 文档中必须包含以下内容：

1. `### [?] 页面帮助` 段落 —— 页面级帮助弹窗的数据来源
2. `### [?] 按钮级帮助对照表` 表格 —— 按钮级帮助 Tooltip 的数据来源

**没有这两个段落的 SPEC 文档不能进入开发阶段。**

### 验收标准

1. 每个页面标题旁有 `[?]` 按钮，点击弹出帮助弹窗
2. 帮助弹窗内容包含：适用角色、功能定位、核心操作、注意事项、常见问题
3. 每个功能操作按钮/入口旁有 `[?]` 图标，悬停显示功能说明
4. 帮助内容与对应 SPEC 文档的定义一致
5. 新增页面/功能时自动遵循此原则，无需额外评审

## P2: 一致性优先于灵活性

### 原则描述

当需要在"保持平台风格统一"和"提供灵活配置选项"之间做选择时，优先选择**一致性**。

- 所有列表页使用相同的搜索/筛选/排序/导出交互模式
- 所有弹窗使用相同的标题/确认/取消/Dismiss 布局
- 所有表单使用相同的字段/校验/提交/错误展示方式

---

## P3: 操作可逆与安全优先

### 原则描述

- 批量操作执行前必须展示`预览`（受影响数据/用户预览）
- 涉及资金/权限/状态变更的操作必须`二次确认`
- 所有敏感操作记录到`审计日志`，可追溯
- 批量操作执行后提供`错误报告`下载

---

## P4: 状态可见性

### 原则描述

- 数据加载中必须有 loading 指示器
- 空数据状态必须有空状态说明（非空白页）
- 错误状态必须有错误提示和重试按钮
- 长时间操作必须有进度提示
- 操作成功/失败必须有明确的状态反馈（toast/通知）

---

## 违反原则的后果

- P1 违反：SPEC 不进入开发阶段，UI 设计不进入验收
- P2/P3/P4 违反：需在 code review 中整改
