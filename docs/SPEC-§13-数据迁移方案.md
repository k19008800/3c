### 功能描述

规范平台数据迁移流程，包括从零初始化、旧版数据迁移、第三方导入、表结构变更后校验。

### 完成能力

**迁移场景覆盖：**

| 场景 | 说明 |
|------|------|
| 零基础初始化 | 全新系统从空数据库开始，seed 脚本可重复执行 |
| 旧版数据迁移 | 从旧版或其他平台迁入用户/订单/消费记录 |
| 第三方导入 | 从其他聚合平台批量导入用户和 Key |
| 表结构变更 | migration 执行后的数据迁移和校验 |

**目录结构规范：**
- `seeds/` — 种子数据（角色权限 / 管理员 / 分类 / 邮件模板 / 系统配置）
- `transforms/` — 数据转换脚本（用户 / 订单 / Key）
- `validate/` — 校验脚本（数据完整性 / 引用完整性 / 数据一致性）

**要求：**
- 所有脚本可重复执行（IF NOT EXISTS / 幂等设计）
- 迁移前自动备份受影响表
- 迁移完成后自动校验数据完整性
- 大表分批迁移（每批 1000 条），支持断点续传

**迁移脚本规范：**
- 脚本统一放在 `api/src/migrations/` 目录，分三类：
  - `seeds/` — 种子数据（角色权限/管理员/分类/模板/配置）
  - `transforms/` — 数据转换脚本（用户/订单/Key）
  - `validate/` — 校验脚本
- 每次迁移必须有对应的回滚脚本
- 执行后自动记录迁移版本号到 `migration_versions` 表

**数据校验规则：**
- 完整性校验：源表行数 = 目标表行数
- 引用完整性校验：外键关联无断裂
- 数据一致性校验：关键字段（余额/金额）サンプリング对比
- 校验结果报告：通过/失败项目列表

**API 接口：**

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| POST | /api/v1/admin/migrations/run | 执行迁移 | 超级管理员 |
| POST | /api/v1/admin/migrations/rollback | 回滚迁移 | 超级管理员 |
| GET | /api/v1/admin/migrations/status | 迁移状态列表 | 管理员 |
| GET | /api/v1/admin/migrations/validate | 执行数据校验 | 超级管理员 |
