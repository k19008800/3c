# PRD — 代理商体系（后台主导版 / 报备划拨制）

> 状态：**已定稿** ｜ 版本：v1.0 ｜ 日期：2026-08-01
> 定位：本文件是对现有 `PRD-代理商体系.md` 的**准入与归属模型修订**。核心改变：代理商从「用户自助注册/升级」改为「平台后台报备主导」；客户归属从「用户自助绑定」改为「代理商报备 + 后台审核划拨」（唯一来源）。
> 适用范围：个人用户与企业用户**统一使用同一套报备划拨流程**；企业不涉及多账号/多主体归属。

## 〇、决策基线（BOSS 已拍板）

| # | 决策项 | 结论 |
|---|--------|------|
| D1 | 分销层级 | **去掉三级分销，仅保留一级**（无多级抽成/团队深度） |
| D2 | 用户成为代理后，自助裂变/邀请码绑定客户能力 | **移除**（`me/agent/referral` 裂变下线；客户归属**唯一来源=后台报备划拨**） |
| D3 | 审核通过后是否自动划拨 | **自动划拨**（审核通过即生效） |
| D4 | 客户本人是否需要知情同意 | **不需要**，仅通知（运营推荐关系） |
| D5 | 已被 A 归属的客户被 B 报备 | **允许覆盖转移**，但全程留审计 |
| D6 | 被设为代理后是否保留用户原有功能 | **保留**（普通用户基础功能正常可用）；但**不保留**裂变绑定类代理自助能力（见 D2） |
| D7 | 归属生效时间点（佣金切分） | **以划拨执行时刻为界** |
| D8 | 现有裂变/绑定旧数据 | **迁移为归属关系**（见 §六 迁移方案） |

## 一、背景与目标

### 1.1 现状痛点

当前重构项目（`3cloud/`）的代理商体系沿用了旧模型：

- 用户可通过 `me/agent/profile` **自动创建代理商档案**（`getOrCreateProfile` 会自动生成 `prepare` 代理）
- 存在用户侧「升级入口」「裂变绑定」等自助行为
- 存在多级分销（`parentUserId` / 团队深度 / 多级抽成）
- 客户归属依赖用户主动绑定/邀请码裂变

这种模型的问题：
1. **代理商身份不隐蔽** —— 任何注册用户都能自助成为代理，代理商体系暴露在用户端。
2. **客户归属不可控** —— 依赖用户主动动作，平台无法主导「谁是谁的客户」这一商业关系。
3. **多级分销复杂** —— 抽成链路长、财务核算与合规风险高，不符合当前业务所需。

### 1.2 本次修订目标

> 一句话：**代理商是平台的「内部商业实体」，由后台创建、后台授权、后台划拨；单级、隐蔽、客户归属唯一来源=后台报备划拨。**

1. **代理商无注册入口、无升级入口**：用户端彻底移除"申请成为代理商/升级代理商"的任何入口。
2. **代理商身份由后台报备创建**：后台管理员在用户列表中选择目标用户，直接赋予其代理商身份（含等级、佣金档位），用户不可自荐。
3. **代理商身份隐蔽**：代理商对平台是显式实体，但对普通用户端整体不可见；仅后台可见全部代理商，代理商本人可见自身档案。
4. **客户归属走报备划拨（唯一来源）**：代理商向后台报备目标客户（手机号/邮箱/用户ID），后台审核通过后自动将该客户**划拨**到该代理商名下，此后该客户的消费佣金计入该代理商。
5. **单级分销**：不设上级/下级代理，无多级抽成；一个代理商只对自己的归属客户计佣金。
6. **个人/企业统一**：个人与企业用户使用同一套报备划拨流程与归属规则；企业不涉及多账号、多主体归属，一个企业客户实体即一个归属对象。

## 二、角色与准入模型

### 2.1 角色定义

| 角色 | 身份来源 | 用户端可见性 | 说明 |
|------|----------|--------------|------|
| **系统后台管理员** | 平台内置 | 不可见 | 创建代理商、审核报备、执行划拨的唯一操作者 |
| **代理商** | **后台报备创建** | 仅对本人可见自身代理档案 | 无注册/升级入口；单级，无上下级 |
| **用户（个人）** | 注册 | 正常可见 | 是潜在的"目标客户"，可能被划拨到某个代理商名下 |
| **用户（企业）** | 注册/认证 | 正常可见 | 与个人同一套划拨归属流程 |

### 2.2 代理商准入（后台报备创建）— 核心约束

| 约束 | 规则 |
|------|------|
| 注册入口 | ❌ **不存在**。用户端无任何"申请成为代理商"入口 |
| 升级入口 | ❌ **不存在**。用户端无任何"提交升级申请"入口 |
| 分销层级 | **仅一级**。`agent_profiles.parentUserId`、多级抽成、团队深度相关能力**移除** |
| 创建方式 | 仅后台：管理员在**用户列表**选中目标用户 → 「设为代理商」→ 填写代理等级 + 佣金档位 → 确认 |
| 前置状态 | 被设为代理商的用户可以是**已注册任意用户**（个人/企业均可），无需其主动申请 |
| 身份感知 | 被设为代理商的用户**会收到通知**（站内信），但此事由后台触发，非其自荐 |
| 权限边界 | 被设为代理商后，**保留其普通用户原有功能**（调 API/充值/看账单等）；但**移除**裂变/邀请码/自助绑定客户等代理自助能力（见 D2） |

### 2.3 等级与佣金档位

沿用现有等级体系，但**等级只能由后台调整，用户不可自助升级**：

| 等级 | 默认佣金率 | 调整方式 |
|------|-----------|----------|
| `prepare`（预备代理） | 0% | 后台 |
| `level1`（一级代理） | 10% | 后台 |
| `senior`（高级代理） | 15% | 后台 |

- 企业客户与个人客户在佣金档位、划拨规则上**不加区分**。
- 等级由后台 `admin/agents/:userId/level` 调整（已存在，保留）。
- 佣金**单级计算**：仅按该代理商的归属客户消费 × 该代理商自身档位，无上级再次抽成。

## 三、客户归属模型（报备划拨 · 唯一来源）

### 3.1 核心概念

- **目标客户**：被划拨到某代理商名下的用户（个人或企业，同一实体）。
- **归属关系**：一个客户在**同一时刻只能归属一个代理商**（归属唯一性）。
- **报备**：代理商提出"某客户归我"的请求。
- **划拨**：后台审核通过后**自动**将该客户正式归属到该代理商名下；生效后该客户消费佣金计入该代理商。
- **来源唯一性**：客户归属的**唯一产生方式**是报备划拨；用户端无任何自助绑定/裂变入口（D2）。

### 3.2 归属生命周期

```
[代理商] 提交报备 ──▶ [后台] 审核 ──▶ 通过(自动划拨) ──▶ 归属生效
                              │
                              └─▶ 驳回（代理商可修改后重新报备）
```

### 3.3 流程细节

**Step 1 — 代理商报备**

- 代理商在**代理端**提交目标客户：手机号 / 邮箱 / 用户ID（三选一，至少提供一种可唯一定位方式）。
- 同时可提交：客户备注（如企业名、合作意向等）。
- 系统校验：目标客户必须是**已注册用户**；若用户不存在，提示"客户未注册，无法划拨"。

**Step 2 — 后台审核**

- 后台进入**报备审核队列**，逐条审核。
- 审核信息展示：代理商信息、目标客户信息、当前归属状态（是否已被其他代理商归属）、历史佣金归属变动。
- 决策：
  - **通过** → **自动划拨**（D3），无需再点一次执行；
  - **驳回** → 填写原因，代理商可修改后重新报备。

**Step 3 — 自动划拨生效**

- 审核通过的瞬间客户归属即生效：
  - 该客户归属绑定到该代理商；
  - 客户**原归属（如有）被覆盖转移**（D5，留审计）；
  - 自划拨执行时刻起，该客户消费佣金按对应档位计入该代理商（D7）。

### 3.4 归属唯一性与变更

| 场景 | 规则 |
|------|------|
| 客户已被 A 代理归属，B 代理再报备 | 允许报备，审核时提示"该客户当前归属 A，划拨将变更归属"。后台可决定：通过（归属转移给 B）或驳回（D5） |
| 客户归属转移 | 归属从 A 转移到 B，需保留**审计日志**（归属变更历史、操作人、时间、原因） |
| 解除归属 | 后台可将某客户从某代理商解除归属（客户回到"无归属"状态），需留审计 |
| 佣金核算边界 | 归属变更的**生效时间点**（划拨执行时刻）之前的消费佣金归属原代理，之后归属新代理（D7，保证财务可追溯） |

### 3.5 客户本人感知

- 客户本人**会被通知**其归属关系（站内信），但**无需客户主动同意**（D4）。
- 说明：报备划拨本质是「平台对客户资源的运营推荐关系」，客户与平台的直接服务关系不受影响；客户归属是**运营侧的推荐归属**，非客户强制绑定关系。

## 四、对现有功能的改动清单（面向开发）

> 基于当前 `3cloud/` 重构代码现状。

### 4.1 后端（api/）

**移除 / 收敛**

| 现状 | 动作 |
|------|------|
| `me/agent/profile` 的 `getOrCreateProfile` 自动创建 `prepare` 代理档案 | 改为**只读查询**：仅当后台已为该用户创建代理档案时返回；否则返回"非代理商"状态，**不再自动创建** |
| `me/agent/referral`（邀请裂变/客户自助绑定）| **下线**。客户归属唯一来源=后台报备划拨（D2） |
| `agent_profiles.parentUserId`（上级代理/多级）| **移除**字段及多级抽成/团队深度相关逻辑，统一单级（D1） |
| 用户侧任何"申请升级代理"相关逻辑 | 移除 |

**新增（后台主导）**

| 模块 | 说明 |
|------|------|
| `POST /admin/agents/assign` | 后台设置某用户为代理商（选用户 + 等级 + 佣金档位） |
| `POST /admin/agent-reports` (代理端 `POST /agent/reports`) | 代理商提交客户报备 |
| `GET /admin/agent-reports` | 后台查看报备审核队列 |
| `POST /admin/agent-reports/:id/audit` | 后台审核（通过→**自动划拨** / 驳回 + 原因） |
| `GET /admin/agent-customers` | 后台查看各代理商的客户归属列表 |
| `GET /admin/agent-customers/:id/logs` | 归属变更审计日志 |
| `POST /admin/agent-customers/:id/unbind` | 后台解除客户归属 |

### 4.2 数据模型（api/src/db/）

**新增表建议**

| 表 | 关键字段 | 说明 |
|----|----------|------|
| `agent_customer_bindings` | `id, agent_user_id, customer_user_id, status, bound_at, unbound_at, operator_id` | 客户归属绑定（唯一约束：customer_user_id 同一时刻唯一 in-effect 记录） |
| `agent_report_requests` | `id, agent_user_id, target_phone/email/user_id, note, status(pending/passed/rejected), audit_operator_id, audit_at, reject_reason` | 报备审核队列 |
| `agent_binding_logs` | `id, customer_user_id, from_agent_user_id, to_agent_user_id, action(bind/transfer/unbind), operator_id, reason, created_at` | 归属变更审计日志 |

**改动现有表**

| 表 | 动作 |
|----|------|
| `agent_profiles` | 移除"用户端自助创建"语义；`level/commissionRate` 仅后台可写；可增加 `created_by_admin_id`（记录创建后台操作人）；**移除 `parentUserId`**（单级，D1） |

### 4.3 前端（web-console）

| 位置 | 动作 |
|------|------|
| 用户端（代理设置页）| 移除"申请成为代理/升级"入口；**移除裂变/邀请码/自助绑定**入口；保留代理本人查看自身档案、佣金、提现、**报备目标客户**能力 |
| 管理端（AdminAgentsPage）| 新增：① 用户列表「设为代理商」操作；② 报备审核队列页；③ 客户归属管理 + 审计日志页 |
| 代理端（Agent console）| 新增「报备目标客户」入口 + 报备记录查询 |

### 4.4 隐蔽性要求（对照 AGENTS.md 规范）

> ⚠️ 按 `3cloud/docs/PRODUCT-DESIGN-PRINCIPLES.md`，以下新增页面/按钮均需配套 `[?]` 帮助说明。

- 用户端：确保任何普通用户页面**不出现**"代理商"相关入口/引导（首页、设置、帮助中心均不露出）。
- 后台：报备审核、客户归属、设为代理商等操作按钮旁加 `[?]` 悬浮说明。

## 五、验收标准

1. 用户端**任何页面**不出现"申请/升级为代理商"入口 ✅
2. 后台可将任意用户一键设为代理商（含等级/佣金档位）✅
3. 代理商仅通过后台报备目标客户，报备进入审核队列 ✅
4. 后台审核通过后客户**自动**划拨到该代理商名下，消费佣金计入 ✅
5. 一个客户同一时刻仅归属一个代理商 ✅
6. 归属变更全程留审计日志（操作人/时间/原因/前后归属）✅
7. **无多级分销**：代理商无上级/下级，佣金单级计算 ✅
8. 用户成为代理后**无裂变/邀请码/自助绑定**能力，客户归属唯一来源=报备划拨 ✅
9. 用户成为代理后**保留**普通用户原有功能（调 API/充值/看账单等）✅
10. 个人与企业用户使用同一套报备划拨流程 ✅（企业不涉及多账号归属）
11. 所有新增页面/按钮均带 `[?]` 帮助说明 ✅

## 六、迁移方案（D8：现有裂变/绑定旧数据 → 归属关系）

> 针对重构前旧系统（`3cloud-backup/`）遗留的裂变/绑定客户数据。

| 数据 | 迁移动作 |
|------|----------|
| 已存在的邀请裂变绑定关系（客户 A 经邀请码挂到代理 B 名下） | 写为一条 `agent_customer_bindings` 归属记录（agent=B, customer=A, bound_at=原绑定时间），并写入一条 `agent_binding_logs`（action=bind，注"迁移自旧裂变数据"） |
| 已存在的多级代理关系（parentUserId 指向上级） | **扁平化为单级**：仅保留最底层实际归属客户的代理为归属人，丢弃上级抽成链（D1） |
| 旧 `agent_profiles` 中用户端自动创建的 prepare 档案 | 仅迁移**后台确认过/有实际归属客户的**档案；无归属业务的自动档案**不迁移**（避免暴露无意义代理身份） |
| 迁移范围与校验 | 迁移脚本输出核对报告（迁移条数、归属唯一性冲突、异常堆），由后台复核后再启用报备划拨 |
