## 1. 目标与非目标

### 1.1 目标
1. 将对账标准化为**可持续的闭环**：将 3Cloud 平台内部账务与外部凭据（支付通道回调、银行流水、渠道账单、日志审计）交叉比对、发现差异、驱动修复并归档（ref-4.4.5 §1.1）。
2. 提供三种对账精度（ref-4.4.5 §1.3）：**日切对账**（每日 T+1 02:00，精准到每笔）、**实时对账**（管理端手动触发，支持近 7 天快速与自定义 ≤90 天）、**深度对账**（每月 5 日 03:00，上月完整对账 + 资金平衡表 + 趋势）。
3. 对发现的差异做**分级处理与责任分离**：按严重级别（INFO/WARN/CRITICAL）分级，差异处理人与复核人职责分离（ADR-0004），实现补账、核销、误报、忽略的标准化处理（supplement/02 §三）。
4. 支持**代理结算对账**：按结算周期关账（每月 1 日 02:00自动），汇总已结算佣金、生成结算单、代理确认或 3 天自动确认、管理员调整金额（sprint-1/03 §1.1）。
5. 当前版本**禁止负余额**，禁止退款/红冲/对账补扣产生负余额（ADR-0020）。

### 1.2 非目标
1. **不**启用 `platform_ledger` 作为本期对账入账依赖；当前余额与对账依据为 `customer_balances`、`balance_transactions`、业务单据和 `billing_logs`（ADR-0012）。来源（ref-4.4.5/SPEC-§29）中依赖 `platform_ledger` 的"平台总账/资金账户/结转"能力属于**架构预留**，本期不实现。
2. **不**引入多币种结算兑付（汇率管理为 P2 预留，本期仅 CNY 单币种，ref-4.4.5 §7.5）。
3. **不做**财务锁账后的数据不可修改强制（`platform_ledger` 相关结转/锁账属 P1/P2 预留）。
4. 对账引擎不作为资金写入口替代业务链路；对账仅在授权下执行补账/核销/红冲，且必须遵守 ADR-0002/0003/0009/0020。

## 2. 角色与业务场景

### 2.1 角色
| 角色 | 对账/结算能力 | 依据 |
|------|--------------|------|
| 财务（finance_ops/财务员） | 查看对账报告、运行对账、处理差异、补账、核销 | ADR-0004、ref-4.4.5 §5.1（`FINANCE_COMMISSION`、`RECONCILIATION_VIEW`） |
| 财务主管/管理员 | 复核差异处理、审批结算金额调整 | ADR-0004、sprint-1/03 §4.7（`adjust`） |
| `super_admin` | 全权限，含终审、财务锁账临时解锁（预留） | ADR-0004 |
| 系统（对账引擎/定时任务） | 自动触发对账、自动修复容差内差异、3 天自动确认结算 | ref-4.4.5 §2.1、sprint-1/03 §6 |
| 代理商 | 查看结算单、确认结算 | sprint-1/03 §5 |

**职责分离（ADR-0004，强制）**：对账差异的**处理人**（补账/核销）与**复核人**（确认处理结果、关闭差异）不得为同一人；结算金额**调整操作人**与**复核审批人**不得为同一人；创建人 ≠ 审批人、一级审批 ≠ 二级审批。无权限统一返回 `403 PERMISSION_DENIED`。

### 2.2 业务场景
| # | 场景 | 处理类型 | 说明 |
|---|------|---------|------|
| S1 | 每日/周/月定时对账 | 日切/深度对账 | 每日 02:00 T+1、周日深度、每月 5 日月结（ref-4.4.5 §2.1） |
| S2 | 管理端手动对账 | 实时对账 | 近 7 天快捷或自定义范围（≤90 天），排查即时问题（ref-4.4.5 §1.3） |
| S3 | 发现差异并处理 | 差异分级处理 | 财务查看差异详情、归因、补账/核销/误报/忽略（supplement/02 §三） |
| S4 | 代理结算周期关账与确认 | 结算对账 | 每月 1 日 02:00 自动关账，代理确认（3 天自动确认），管理员可调整（sprint-1/03 §1.1） |
| S5 | 充值/消费/佣金/提现/余额分维对账 | 分维度对账 | 充值对账（外部回调为基准）、消费对账、佣金验算、提现对账、余额连续性（ref-4.4.5 §3） |

## 3. 业务规则

### 3.1 核心校验等式（ref-4.4.5 §1.1）
```
等式 1（资金平衡）：期初余额 + 充值总额 - 消费总额 - 提现总额 - 佣金支出 ≈ 期末余额（容差 ¥0.01）
等式 2（充值闭环）：recharge_orders.amount(+) ⇔ 支付通道回调金额 ⇔ 余额变动记录(+)（绝对值一致）
等式 3（消费闭环）：call_logs.cost(-) ⇔ 余额变动记录(type=consumption).amount(-)
```
> 注：等式中的"平衡/变动"以 ADR-0006 命名（`customer_balances` / `balance_transactions` / `billing_logs`）为准；来源中的 `users.balance`/`balance_logs` 为历史兼容对象，迁移后禁止新增业务引用（ADR-0006）。

### 3.2 对账精度分层（ref-4.4.5 §1.3）
- **日切**：T+1 02:00，UTC+8 自然日颗粒度；充值按 `paidAt/confirmedAt`、消费按 `createdAt`、佣金按 `createdAt`、提现按 `paidAt` 归属。
- **实时**：管理端手动，支持近 7 天快捷 + 自定义（≤90 天，防全量扫描）。
- **深度**：每月 5 日 03:00，上月完整对账 + 资金平衡表 + 趋势。

### 3.3 对账触发与调度（ref-4.4.5 §2.1）
| 调度 | 表达式 | 范围 | 类型 |
|------|--------|------|------|
| `daily-recon` | `0 2 * * *` | 前一日 T-1 | `full` |
| `weekly-deep` | `0 3 * * 0` | 上周 | `full` |
| `monthly-full` | `0 4 5 * *` | 上月整月 | `full` |

**手动对账校验**：`startDate ≤ endDate`；范围 ≤ `maxCustomRangeDays`（默认 90）；`endDate` ≤ 当前；同一 `(startDate,endDate,reconType)` 不允许并行（Redis 分布式锁 `recon:lock:{start}:{end}:{type}`，TTL 600s）。单次对账超时 300s 标记 failed；最大异常写入 500 条截断告警；分页查询每页 1000 条防 OOM（ref-4.4.5 §2.2/2.3）。

### 3.4 差异分级与量化判定（补充规格，supplement/02 §二）
| 级别 | 偏差范围 | 处理方式 | 通知 |
|------|---------|---------|------|
| INFO | 偏差 ≤ ¥1 或笔数 ≤ 3 | 自动归集报告，无需人工 | 报告内标注 |
| WARN | ¥1 < 偏差 ≤ ¥100 | 自动归集 + 推送报告提醒 | 站内通知 + 邮件 |
| CRITICAL | 偏差 > ¥100 或笔数 > 50 | 立即告警 + 人工介入 | P0 通知（短信/电话） |

**分维度定量规则（来源 supplement/02）**：
- **渠道消费对账（每日）**：以平台 `request_id`/`model`/`prompt_tokens`/`completion_tokens`/`cost` 逐笔比对；Token 数以平台为准；金额差异 < 1% 自动核销，≥1% `pending_review`；DIFF-001 漏报自动模糊匹配重查（时间±5min、金额±10%）1 次，连续 3 天同一笔自动升级 CRITICAL。
- **渠道结算对账（每月）**：偏差 ≤ ¥10 自动核销；¥10 < 偏差 ≤ ¥500 按笔核查；> ¥500 暂停结算 + P0 告警 + 人工核查；偏差率 > 2% 即使金额 <¥500 也告警。
- **充值对账**：日终对账 ≤¥10 → INFO、>¥10 → WARN、>¥100 → CRITICAL。
- **代理佣金对账**：佣金计算 vs 佣金记录偏差 ≤¥1 自动核销；>¥1 且精度问题 → 下期调整；>¥1 且费率变更 → 按快照费率重算；>¥100 → 暂停该代理提现人工核查。
- **余额对账（会计恒等式）**：偏差 ≤¥10 INFO；¥10<偏差≤¥100 WARN；>¥100 CRITICAL；连续 3 天偏差 >¥10 自动标记系统性问题入技术改进队列。

> 上述阈值以 supplement/02 为来源；其立项状态仍在 `open-issues.md` 项 11 评审中，若后续评审修订，以修订版为准。凡来源未给出的交叉阈值（如金额与笔数并集时的优先级）标注 `【待人工裁决】`。

### 3.5 差异自动修复边界（ref-4.4.5 §5、§3）
| 差异类型 | 自动修复能力 | 人工介入条件 |
|---------|-------------|-------------|
| `missing_record`（少账） | 消费补扣可自动；充值/提现少账否（需人工确认） | 充值/提现一律人工 |
| `amount_mismatch`（金额不匹配） | 平台内 log-vs-log 且差异 ≤¥1.00 自动补退/补扣 | 差异 >¥1.00 或涉外部通道 |
| `calculation_error`（佣金计算错误） | 容差 ¥0.01 内公式值覆盖 | 超容差或规则变更 |
| `duplicate_record`（重复记录） | 自动撤销多余一条（写负值记录） | 多条重复待人工保留 |
| `orphan_record`（孤儿记录） | 否 | 人工确认数据清理/bug |

> **精度约束（ADR-0002）**：差异判断与补账涉及金额一律以 `numeric(18,8)` 内部运算，禁止 JS `Number` 作为最终计算依据；输入最多 2 位小数。

### 3.6 代理结算规则（sprint-1/03 §1.1）
- 月结制度：每月 1 日 02:00 自动关账上月佣金；开关 `settlement_auto_enabled`。
- 仅汇总 `status='settled'` 的佣金日志；零佣金代理跳过。
- 关账后生成结算单（`pending`），代理确认或 **3 天自动确认**转入 `settled`。
- 管理员可调整金额（可为正/负，需填 ≥5 字原因）；调整后金额不得为负。
- 结算单/明细/日志**永久保留**（审计合规）。
- 审批与复核职责分离（ADR-0004）。

### 3.7 状态流转（ADR-0003/0020）
- 结算周期：`open → closed → settled`；结算单：`pending → settled`。
- 对账差异处理详见状态机（`docs/06-data-and-architecture/state-machines/settlement.md`）。
- 退款/红冲相关资金状态遵循 ADR-0020（消费失败退余额只加一次、充值原路退款不通时回滚、调账纠错走红冲、禁止负余额）。

## 4. 状态与结果

引用并展开 [结算/对账状态机](../../06-data-and-architecture/state-machines/settlement.md)：
- **结算周期**：`open`（已创建未关账）→ `closed`（已关账，账单已生成等待确认）→ `settled`（所有账单已结算，终态）。
- **结算单**：`pending`（待代理确认）→ `settled`（已确认/自动确认，终态）；管理员调整仅限 `pending`。
- **对账报告**：`pending → running → completed / failed`。
- **对账差异**：差异处理状态见状态机（引擎创建 `pending` → 处理 → 终态；补账/核销/误报/忽略）。

业务结果（成功完成后）：
| 对象 | 结果 |
|------|------|
| 对账完成 | 生成 `reconciliation_reports`（含汇总/各维度/平衡校验/差异列表）；差异写入 `reconciliation_mismatches` |
| 差异补账 | 授权下对用户余额补退/补扣（写 `balance_transactions`），余额不得为负 |
| 结算关账 | 生成 `settlement_cycles` + `agent_settlements` + `settlement_details` |
| 结算确认 | 代理可提现余额增加（`agent_balance_ledger`），写入确认日志 |

## 6. 权限与安全
- **权限点鉴权**：角色仅作聚合，按权限点控制（ADR-0004）；对账相关端点绑定 `RECONCILIATION_VIEW`、`FINANCE_COMMISSION`（ref-4.4.5 §9.2）；无权限返回 `403 PERMISSION_DENIED`。
- **职责分离**：差异处理与复核分离；结算调整与复核分离（ADR-0004）。
- **操作级 2FA**：补账、核销、红冲、结算金额调整等资金写操作强制后端操作级 2FA（ADR-0008 语义），`super_admin` 不默认豁免。
- **幂等**：对账任务、补账/核销、结算关账与确认纳入统一幂等规范 + 状态条件更新（ADR-0009）；Redis 仅加速，DB 约束/事务/状态守卫为最终边界。
- **补账**涉及退/扣余额，遵守 ADR-0020 禁止负余额 + 用量校验。

## 7. 通知、审计与合规
- **告警分级通知（ref-4.4.5 §5.4）**：`critical` → 平台告警 + Webhook（钉钉/飞书）→ 财务主管；`high` → 平台告警 → 财务（当日）；`medium` → 平台通知（本周）；`low` → 仅报告记录。同类型同用户差异 24h 内不重复告警。
- **对账报告推送（SPEC-§29 §29.8.3）**：每日对账完成后推送报告（飞书/企微/邮件）。
- **差异处理审计**：所有补账/核销/误报/忽略/结算调整写入操作日志（操作人、前后值、生效时间、原因）；审计事件采用出站 outbox（ADR-0010 语义：事务提交成功后才写入，异步发送；失败不回滚资金事务）。
- **通知是否状态**：通知状态 `queued/sent/failed/skipped`（ADR-0010），支持查询、告警、重试、人工补发。
- **合规**：结算单/明细/日志永久保留；对账平衡公式含所有资金类型；日差异 >¥0.01 生成异常（ref-4.4.5、ref-4.4 §6）。
- **测试基线**：结算/对账的验收证据归属唯一发布基线 `docs/07-quality-and-acceptance/release-baseline.md`（ADR-0029）；不得用历史文档中的数字（1159/1132/808）宣称基线。

## 8. 页面与交互要求
页面标题旁与每个操作按钮旁都必须有 `[?]` 帮助说明（PRODUCT-DESIGN-PRINCIPLES）。

**对账管理页（admin → 财务 → 对账管理）**：
- 工作台：昨日/本周/本月对账状态卡片、待处理异常数、快速操作（昨日对账 / 本周对账 / 自定义）、对账报告列表（筛选/分页/详情/导出）。
- 运行对账弹窗：对账类型（full/recharge/balance/commission/withdraw/consumption）、时间范围（默认近 7 天、自定义 ≤90 天），超范围提示分批执行。
- 报告详情页：汇总卡片（总订单/匹配/异常/差额）、资金平衡校验可视化、异常明细（批量处理）、趋势图。
- 差异处理面板：展示平台金额 vs 对方金额、差额、原始数据、建议操作；处理方式（补录差额/标记已修复/标记误报/标记忽略）+ 备注；确认前 2FA。
- 结算管理 Tab（管理端 `admin/finance`）：结算周期列表、创建周期、结算单列表、展开明细/操作日志、调整金额弹窗、导出 CSV。
- 代理端 `agent/finance` 结算对账 Tab：待确认结算金 / 已结算总额卡片、结算单列表、确认结算、明细（无客户姓名列，隐私保护）、导出 CSV。
- 每个按钮/操作旁 `[?]` 悬停说明；页面标题旁 `[?]` 页面帮助弹窗。详见 [SPEC](../../03-functional-spec/03-billing-and-finance/settlement-and-reconciliation.md) §9 对照表。

## 9. 验收标准
1. **定时对账**：日切（T+1 02:00）、周深度、月度完整按调度执行，生成对账报告；手动对账范围/并发校验生效（ref-4.4.5 §2）。
2. **差异量化分级**：INFO/WARN/CRITICAL 分级与通知符合 supplement/02；金额与笔数阈值映射真实测试（来源 supplement/02，随后续评审定稿）。
3. **差异处理闭环**：补账/核销/误报/忽略状态正确流转；处理人与复核人职责分离（ADR-0004）。
4. **结算关账与确认**：`open→closed→settled`、`pending→settled`；3 天自动确认；管理员调整校验（原因 ≥5 字、禁负、仅 pending）；重复关账 409（sprint-1/03）。
5. **禁负余额**：补账/调整产生负余额时返回受控业务错误，DB 不出现负余额（ADR-0020）。
6. **精度**：对账差额判定与补账按 `numeric(18,8)` 运算，输入 ≤2 位小数（ADR-0002）。
7. **幂等**：对账任务、补账/核销、结算关账/确认幂等；同 Key 重放首结果、异摘要 409、重复业务引用固定错误码（ADR-0009）。
8. **2FA**：补账/核销/结算调整未带有效操作 token 时拒绝（ADR-0008）。
9. **审计/通知**：差异处理与结算生成审计 + 分级通知；通知失败不影响资金结果（ADR-0010）。
10. **面向开发可验收**：每条验收标准给出真实测试映射来源；发布验收证据归属唯一基线文件（ADR-0029）。
