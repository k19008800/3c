# 3Cloud 需求文档完整性审计报告

- 审计日期：2026-08-30
- 审计范围：`docs/` 当前非归档需求资产；重点为 2026-08-29 建立的核心资金正式文档体系，同时复核 `PRD-README.md` 所称的既有在役 PRD/SPEC。
- 审计依据：`PRODUCT-DESIGN-PRINCIPLES.md`、ADR-0015/0016/0017/0019、`00-index/document-map.md`、`PRD-README.md`、`docs/README.md`。
- 审计方法：文档存在性、状态/权威性、PRD→SPEC→状态机→权限→API→数据→TEST→OPS 可追溯性、交叉引用、需求可开发性及帮助原则抽查。
- 结论：**不通过（不具备作为正式开发与验收依据的条件）**。第一批核心资金文档已完成目录与 ADR 基线，但正文仍是 draft/占位；既有文档体系与新正式体系对“唯一权威入口”的定义相冲突。

## 一、审计口径与总体判断

### 1. 文档权威性存在冲突

- `docs/README.md:5,98-104` 声称 `PRD-README.md` 是“唯一总纲”、且只有它引用的文件是当前有效需求文档。
- 但 `00-index/README.md:8-10,20-22` 明确新正式体系仍在整理，根目录资料不是自动 `approved` 正文，且只有 `approved` 正式文档可用于开发和验收。
- ADR-0015:9-13 与 ADR-0019:9-14 进一步要求：完成复核与联合评审前不得 `approved`，仅 `approved/accepted` 可作开发与验收依据。

因此目前团队无法仅凭入口判断“哪个需求可开发”。本报告将 **ADR 定义的正式体系** 作为准入判定依据；根目录既有 PRD/SPEC 作为待迁移来源资料审查，不将其误判为已批准需求。

### 2. 第一批范围的覆盖状况

ADR-0016:8-11 要求第一批打通充值、人工上账、调账、退款/红冲、结算/对账的 `PRD → SPEC → 状态机 → 权限 → API → 数据库 → TEST → OPS`。

当前各层虽已建立大部分文件，但主题 PRD/SPEC、API、数据/权限、测试和运维文件全部标记 `draft` 或明确“待补充/待核验”；没有任何第一批 PRD/SPEC 状态为 `approved`。故目录覆盖不能等同于需求完整。

## 三、准入结论

### 1. 立即结论

- **第一批核心资金：禁止进入开发/验收批准。**理由是不存在 `approved` 的 PRD/SPEC/API/测试正文，且 P0 问题未关闭。
- **根目录既有 PRD/SPEC：不得被视为新正式体系的批准需求。**仅可作为来源或迁移参考，必须先完成 ADR-0015 规定的冲突、链接、术语、金额、状态、权限、API、数据与联合评审。
- **不建议以代码现状反向补全需求。**ADR-0015:11-12 已禁止将代码现状自动升格为需求；差异应登记 `DOC_CODE_GAP` 或 `CODE_DOC_DRIFT`。

### 2. 建议整改顺序

1. **治理止血（P0）**：发布唯一权威入口和迁移/废止清单，关闭 DOC-P0-01。
2. **规则冻结（P0）**：依已接受 ADR（如 ADR-0020）修订所有“已解决但仍未决”章节，建立剩余冲突表与裁决 owner，关闭 DOC-P0-04。
3. **五主题正文（P0）**：按充值→人工上账→调账→退款/红冲→结算/对账顺序打通 PRD→SPEC→状态机→权限→API→数据→TEST→OPS，关闭 DOC-P0-02/03。
4. **体验与链接质量（P1）**：修正相对链接；为所有可交付页面/按钮补专属 `[?]` 帮助；CI 加入链接与必填章节校验，关闭 DOC-P1-01/03。
5. **真实验收（P0/P1）**：生成候选版本测试/迁移/恢复证据填充 release baseline；联合评审通过后才将相应文档置 `approved`，关闭 DOC-P0-05/P1-02/04。

## 四、复审退出标准

以下全部满足，方可将本次审计结论改为“有条件通过”：

1. 文档入口唯一，每份现役需求有 ID、owner、语义版本、状态、权威来源与替代关系；
2. 五个第一批主题各自存在无冲突、非占位、`approved` 的 PRD、SPEC、API、状态机、权限/数据、测试、OPS 文档；
3. 所有 PRD→SPEC→API/状态机/数据→TEST→OPS 链接可解析，且每项验收标准映射至实际测试证据；
4. 所有页面与操作入口在 SPEC 中有定制化 `[?]` 帮助定义并通过 UI 验收；
5. 发布基线包含真实候选版本、测试结果与最近备份恢复演练记录，整体门禁通过。
