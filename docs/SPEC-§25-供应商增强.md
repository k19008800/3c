## 25.1 供应商结算对账

### 功能描述

供应商自助页面增加结算对账功能，展示结算周期、应收金额、已付金额、待对账明细。支持导出对账单。

### 完成能力 / 展示效果

**供应商端结算页面：**

```
结算中心
  ┌────────────────────────────────────────────┐
  │  当前结算周期: 2026-07-01 ~ 2026-07-31      │
  │                                              │
  │  基础服务费:          ¥12,500.00             │
  │  质量扣减:            -¥250.00               │
  │  应结算总额:          ¥12,250.00             │
  │  结算状态:            ⏳ 待对账              │
  │                                              │
  │  [查看明细] [导出对账单 CSV]                  │
  └────────────────────────────────────────────┘

  历史结算
  周期            总额          状态          结算日期
  2026-06         ¥11,200.00   ✅ 已结算     2026-07-10
  2026-05         ¥10,800.00   ✅ 已结算     2026-06-08
```

### 数据来源

现有供应商费用的聚合结算 — 基于 `vendor_costs` 表按结算周期聚合：

```
├── 基础服务费: 周期内累计调用费用总和
├── 质量扣减: 根据 SLA 达标率折算（可用性 < 99.9% 扣减比例）
└── 应结算总额: 基础服务费 - 质量扣减
```

### API 接口

```
// 结算对账（§25.1，对应代码 vendor/settlements）
GET  /api/v1/vendor/settlements            — 结算周期列表（当前/历史，支持 status 筛选）
GET  /api/v1/vendor/settlements/:id        — 结算详情/明细
POST /api/v1/vendor/settlements/:id/confirm — 确认对账
POST /api/v1/vendor/settlements/:id/dispute — 发起争议（disputeNote 必填）
```

> 📌 **路径说明**：文档此前写为 `vendor/settlement`（单数），代码实际为 `vendor/settlements`（复数），已于 2026-07-31 统一为复数路径。对账单 CSV 导出暂未提供独立接口，可通过结算详情获取数据。

### 验收标准

#### □ 流程图一致性校验 — 与对应流程图对比验证流程分支、异常处理、决策节点完全一致

1. 供应商端展示当前结算周期的应结算金额和明细
2. 供应商可下载对账单 CSV
3. 历史结算记录可按月份查看

## 25.2 供应商公告/通知

### 功能描述

平台通过公告系统向供应商推送通知（API 变更、结算通知、新模型上线要求、系统维护等），供应商在自助后台查看。

### 通知类型

| 类型 | 触发场景 | 紧急程度 |
|------|---------|---------|
| 结算通知 | 结算单生成/结算完成 | 高 |
| API 变更 | 平台 API 版本升级/参数调整 | 高 |
| 新模型上线 | 要求供应商接入新模型 | 中 |
| 系统维护 | 平台系统维护通知 | 中 |
| 政策变更 | 结算政策/分成比例变更 | 高 |

### API 接口

```
// 供应商公告（§25.2，对应代码 vendor/announcements）
GET  /api/v1/vendor/announcements          — 公告列表（含已读标记）
GET  /api/v1/vendor/announcements/:id      — 公告详情
POST /api/v1/vendor/announcements/:id/read — 标记已读（幂等）

// 管理后台发送（未实现，待开发）
POST /api/v1/admin/vendor/notifications    — 向供应商群发通知
```

> 📌 **路径说明**：文档此前写为 `vendor/notifications`，代码实际为 `vendor/announcements`（公告系统，数据表 `vendor_announcements`），已于 2026-07-31 统一。已读接口方法为 `POST`（非 `PUT`）。管理端群发接口 `admin/vendor/notifications` 代码未实现。

### 验收标准

1. 供应商后台显示平台推送的通知列表
2. 通知内容和紧急程度正确展示
3. 供应商可标记通知为已读

## 25.3 供应商性能排行榜

### 功能描述

内部运营工具，展示各供应商的健康评分、响应速度、错误率、成本效率等多维度对比。用于运营决策和供应商管理。

### 展示内容（管理后台）

```
供应商性能排行 — 2026-07 月
  排名  供应商   健康评分  平均延迟  错误率   调用量    综合得分
  🥇   DeepSeek  98.5      380ms     0.12%   8.2M      95.2
  🥈   阿里云    97.2      210ms     0.25%   5.1M      93.8
  🥉   GLM       95.8      890ms     0.80%   2.3M      88.5
  4     OpenAI   92.1      1200ms    1.50%   1.8M      82.3
```

### 数据来源

```
├── 健康评分: 供应商健康检查通过率（按小时采样，近 7 天平均）
├── 平均延迟: 供应商 API 响应时间（近 7 天平均）
├── 错误率: 调用失败率（近 7 天）
├── 调用量: 近 7 天总调用次数
└── 综合得分: 加权计算（健康 30%+延迟 25%+错误率 25%+成本 20%）
```

### 验收标准

1. 管理后台展示供应商性能排行榜
2. 各项指标和综合得分正确计算
3. 可查看不同时间范围的排名

## 25.4 供应商自助结算

### 功能描述

供应商可主动发起结算申请，平台审核后完成打款。区别于被动等待周期结算。

### 流程

```
供应商发起结算申请 → POST /api/v1/vendor/self-settlement/apply
  └── 校验条件:
       ├── 当前周期内未申请过
       └── 待结算金额 ≥ ¥500（最小结算额）
  └── 状态: pending

管理员审核 → 管理后台结算审核页面
  └── 查看结算明细 → 确认或驳回
  └── 确认 → 状态变为 confirmed → 触发打款流程
  └── 驳回 → 填写驳回原因 → 供应商可修改后重新申请
```

### API 接口

```
// 供应商自助结算（§25.4，对应代码 vendor/self-settlement）
POST /api/v1/vendor/self-settlement/apply      — 发起结算申请
GET  /api/v1/vendor/self-settlement/eligibility — 结算资格/可结算金额检查
GET  /api/v1/vendor/self-settlement/history     — 结算申请记录

// 管理后台审核（未实现，待开发）
GET  /api/v1/admin/vendor/settlement/requests       — 待审核结算申请
POST /api/v1/admin/vendor/settlement/:id/approve    — 审核通过
POST /api/v1/admin/vendor/settlement/:id/reject     — 驳回（需填写原因）
```

> 📌 **路径说明**：文档此前写为 `vendor/settlement/request`，代码实际为 `vendor/self-settlement/apply`（自助结算模块），已于 2026-07-31 统一。管理后台审核接口 `admin/vendor/settlement/*` 代码未实现（差距分析 P0 项）。

### 验收标准

1. 供应商发起结算申请 → 管理后台看到待审核
2. 管理员审核通过 → 结算流程开始
3. 管理员驳回 → 供应商看到驳回原因
4. 不满足条件（金额不足/已申请过）→ 提示友好错误

### [?] 页面帮助

**页面名称**：供应商增强

**适用角色**：供应商、管理员（平台运营）

**功能定位**：在供应商自助页面基础上补充结算对账、公告通知、性能排行榜、自助结算能力，让供应商更自主地管理合作事务。

**子模块说明**：
- §25.1 供应商结算对账：供应商查看结算周期、应收金额、对账明细，支持跨月结算周期
- §25.2 供应商公告/通知：平台推送 API 变更、结算通知、新模型上线要求
- §25.3 供应商性能排行榜：各供应商健康评分/响应速度/错误率对比（新接入 <7 天显示"新接入"标签）
- §25.4 供应商自助结算：供应商发起结算申请（最低 ¥500），平台审核后打款

**注意事项**：
- 结算对账按结算周期独立聚合，不受自然月切割影响
- 待结算金额不足 ¥500 时无法发起结算申请
- 打款失败后结算状态回退为"打款失败"并通知财务手动处理
- 结算账户信息在结算日前 3 天锁定并提醒确认
- 供应商资质过期自动冻结新增业务发布权限

**常见问题**：
Q: 为什么无法发起结算？
A: 待结算金额低于最低结算额 ¥500，或当前有进行中的结算申请、账户信息未确认。

Q: 结算周期跨月怎么算？
A: 按结算周期独立聚合，不受自然月切割影响，明细按实际日期区间展示。

Q: 打款失败了怎么办？
A: 状态自动回退为"打款失败"并通知财务，处理完成后状态更新为已打款。

## 边界条件

| # | 场景 | 触发条件 | 预期行为 |
|---|------|---------|---------|
| VEN-001 | 结算对账周期跨月 | 结算周期的起止日期跨越两个自然月 | 按结算周期独立聚合，不受自然月切割影响，明细列表按实际日期区间展示 |
| VEN-002 | 供应商自助结算金额不足最小额 | 供应商发起结算申请时待结算金额 < ¥500 | 前端按钮置灰并提示"待结算金额 ¥xxx 不足最低结算额 ¥500，请累计后再申请" |
| VEN-003 | 供应商性能排行榜数据不足 | 新供应商接入 < 7 天，历史健康数据不足以计算评分 | 排行榜中排名栏显示"新接入"标签，综合得分暂不展示，数据充足后自动加入排名 |
| VEN-004 | 公告通知发送给已失效供应商 | 管理员群发通知时选择了已被冻结或终止合作的供应商 | 发送时过滤已失效供应商，通知发送记录中标记"X 个供应商因状态异常未发送" |
| VEN-005 | 结算申请审批后实际打款失败 | 管理员审批通过结算申请后，支付渠道返回打款失败 | 结算状态回退为"打款失败"，自动标记为待处理，触发告警通知财务手动处理 |
| SUP-001 | 供应商信息变更同步 | 供应商更新结算账户信息后未及时同步到计费系统 | 下次结算日前 3 天锁定账户信息并提醒供应商确认 |
| SUP-002 | 供应商资质过期 | 供应商上传的资质文件超过有效期 | 自动标记为"资质待更新"，冻结新增业务的发布权限直至更新 |
| SUP-003 | 供应商评级下调 | 供应商连续 3 个月服务质量评级低于阈值 | 触发降级流程，调整结算周期从月结改为周结或预付款模式 |
| SUP-004 | 供应商数据批量操作 | 批量更新供应商信息时部分更新失败 | 事务回滚到操作前状态，记录失败行详情供管理员重试 |
| SUP-005 | 供应商结算争议 | 供应商对结算金额提出异议 | 冻结该笔争议款项，生成争议工单进入人工审核流程 |
| SUP-006 | 供应商接入断连 | 供应商 API 接入连续中断超过 24 小时 | 自动标记供应商为"临时不可用"，系统切换到备用供应商 |
