## 2.1 角色与权限体系

### 功能描述

平台内置 9 个角色等级（L2-L5），通过 Bitset 权限引擎精确控制每个角色在 10 个资源模块上的 7 种操作权限。支持多管理员协作时的操作审计留痕。

### 完成能力 / 展示效果

**管理员侧（管理后台 → 角色管理）：**
- 查看完整的角色-权限矩阵表，一目了然各角色拥有的资源操作权限
- 支持创建自定义角色模板（如"财务专员"、"运营专员"、"客服专员"）
- 每个角色的权限以勾选框方式展示：10 个资源 × 7 种操作（read/create/update/delete/export/audit/operate）
- 角色模板预设了"财务专员"、"运营专员"、"客服专员"、"审计员"、"只读管理员"5 个模板一键启用

**用户侧（无感）：**
- 用户登录后，系统自动根据角色限制可访问的功能模块和可见数据范围
- 管理员操作时，系统自动记录完整操作日志（操作人/时间/IP/操作类型/变更前后值）

### 上下游关系

```
上游：管理员创建用户 → 分配角色 → 角色关联权限
       └→ 角色模板预设（种子数据）→ 开箱即用
权限引擎 ─→ middleware/auth.ts 中间件拦截每个 API 请求 → 校验权限
       └→ 校验通过 → 继续处理请求
       └→ 校验拒绝 → 返回 403 错误
操作审计 ─→ 任一资源变更操作 → 自动写入 operation_logs 表
```

### 边界条件

| 场景 | 行为 |
|------|------|
| super_admin 被操作 | 不可被任何角色管理/禁用/删除 |
| 角色变更后 | 新权限在下次 API 请求时即时生效（中间件实时查角色表） |
| 数据范围限制 | agent 角色只能看名下用户数据；user 只能看自己的数据 |
| 操作审计丢失 | operation_logs 写入失败时，主操作失败—保证审计完整性 |

### 登录安全与异地登录检测

登录记录包含：时间、IP、归属地、设备信息/User-Agent。
当本次登录 IP 归属地与上次登录归属地不同且距离超过 500km 时，系统自动在该条记录上标注"⚠️ 异地登录"红色标签。
管理后台用户详情页的安全标签页中同样展示这些记录和异常标记。

## 2.2 用户端仪表盘 `/console` — 16 个功能区

### 功能描述

用户登录后进入控制台首页，集中展示个人账户概况、今日用量趋势和核心操作入口，分为 16 个功能区域。

### 完成能力 / 展示效果

**区域 1：欢迎卡片**
- 用户看到自己的昵称、角色标签、VIP 等级
- 账户余额展示，余额低时黄色/红色底色预警
- 今日已用 Token + 剩余免费额度（10 秒轮询刷新）
- 上次登录时间、IP、归属地
- 新手用户额外显示"新手保护期"标识

**区域 2：核心指标卡片（4 张）**
- 今日调用次数（成功/失败拆分，环比昨日变化率）
- 今日 Token 消耗（输入/输出拆分，环比变化率）
- 今日消费金额（月累计消费）
- 账户余额（上次余额对比）
- 变化率正增长绿色 ↑，负增长红色 ↓

**区域 3-16：其他功能区**
- 快捷操作（创建 Key、充值、查看日志等）
- 用量趋势概览图
- 常用模型快捷入口
- 最近调用记录
- 通知/告警列表
- 技术文档/API 文档入口
- 客服联系入口
- ...

### 上下游关系

```
数据来源：
  users 表 → 昵称/余额/角色/VIP
  call_logs 表 → 今日调用量/Token/费用（当日聚合）
  login_history 表 → 上次登录信息
  user_quotas 表 → 免费额度
  定时轮询（10秒）→ 用 Token 消耗实时更新
操作触发：
  点击"充值"→ 跳转 /console/recharge
  点击"创建 Key"→ 跳转 /console/api-keys
  点击"查看日志"→ 跳转 /console/logs
```

### 边界条件

| 场景 | 行为 |
|------|------|
| 余额为负（欠费） | 红色显示 `¥-XX.XX`，卡片顶部出现"账户欠费，请立即充值"横幅 |
| 账号被禁用 | 余额卡片不可见，显示"账户已被禁用" |
| 数据加载失败 | 卡片显示 `--`，右下角灰字"数据加载失败" |
| 数值 > 9999 | 自动换算为 K/M 单位（如 12500 → "12.5K"） |
| 首次登录 | 上次登录显示"首次登录" |

## 2.4 API Key 管理 `/console/api-keys`

### 功能描述

用户创建、管理、监控 API Key，Key 是调用平台模型的凭证入口。支持名权限粒度配置和 Key 池分组。

### 完成能力 / 展示效果

用户看到 Key 管理页面：

- **Key 列表**：展示所有已创建的 Key（Key 前缀、名称、状态、最近使用时间、调用量统计）
- **创建 Key**：输入名称 → 选择可用的模型范围 → 设置 QPS/TPM/日调用量限制 → 生成 Key
  - 创建后**仅展示一次完整 Key**，后续只能看到前缀（sk-3c...abc）
- **Key 状态切换**：启用/禁用/删除（删除后 Key 立即失效）
- **Key 详情**：查看 Key 的完整配置、调用统计图表（近 7 天/30 天趋势）、最近失败记录
- **Key 权限**：限制 Key 只能调用某些模型（白名单或黑名单模式）
- **闲置检测**：近 7 天无调用的 Key 标注"未使用"、"闲置"、"沉睡"三种状态标签
- **批量操作**：批量启用/禁用/删除 Key

### 上下游关系

```
上游：用户 → 创建 Key → api_keys 表（存 Key 的 hash，不存明文）
      配额限制 → user_quotas 表（QPS/TPM/日调用量）
下游：第三方应用 → 使用 Key 调用 API → proxy 代理 → 校验 Key → 计费
      call_logs 表 → 记录每次调用的 Key 使用情况
      Key 闲置检测 → 标注闲置状态 → 展示在前端
```

### Key 权限控制（P1）

支持为每个 Key 设置模型白名单，限制该 Key 只能调用指定模型。
- 白名单模式：选择允许的模型列表，未选中的模型该 Key 无法调用
- 黑名单模式：选择禁止的模型列表，其余模型均可调用
- 默认：无限制（可调用所有可用模型）
- 权限变更立即生效，不影响正在进行的请求

### Key 过期时间管理（P2）

- 创建 Key 时可选设置过期时间
- 过期后 Key 自动失效，返回 403 `key_expired`
- 用户可在管理端续期 Key（延长过期时间）
- 列表中已过期的 Key 标注“已过期”状态标签
- 用户可筛选查看即将过期的 Key（近 30 天到期）

### 安全约束

| 场景 | 行为 |
|------|------|
| Key 明文存储 | 不存在数据库中，仅存 bcrypt hash；创建时一次性展示 |
| Key 泄露 | 用户可在管理端立即禁用/删除，不影响其他 Key |
| 单个用户 Key 数量上限 | `site_configs.max_keys_per_user`（默认 50 个）|
| 删除 Key | 硬删除，不可恢复，正在进行的调用立即中断 |

## 2.5 调用日志 `/console/logs`

### 功能描述

用户查看自己的 API 调用历史记录，包括每次调用的模型、Token 消耗、费用、状态、耗时等维度。支持搜索、筛选、详情追溯。

### 完成能力 / 展示效果

用户看到调用日志列表：

- **列表视图**：时间 | 模型名 | Token 数（输入/输出） | 费用 | 状态（成功/失败）| 耗时 | 来源 IP
- **搜索筛选**：按时间范围、模型、状态、Key、IP 搜索
- **详情抽屉**：点击任一日志行 → 弹出详情 → 展示完整请求/响应内容
- **CSV 导出**：将筛选后的日志列表导出为 CSV 文件
- **统计摘要**：列表顶部展示筛选范围内的汇总（总调用/成功/失败/总费用/总Token）
- **错误码参考**：失败调用展示错误码，点击可查看错误码含义

### 上下游关系

```
上游：call_logs 表 → 每次 API 调用的完整记录
      call_logs 按月分区 → 查询优化
用户操作：查看日志 → 监控调用行为
         查看失败记录 → 排查 API 调用问题
         导出 CSV → 自行分析
```

## 2.7 充值 `/console/recharge`

### 功能描述

用户为账户充值，支持多种支付方式和金额。充值后余额实时到账，触发通知。

### 完成能力 / 展示效果

- **充值金额**：预设档次（¥50/¥100/¥500/¥1000/¥5000） + 自定义金额
- **支付方式**：支付宝/微信支付（对接第三方支付网关）
- **充值记录**：展示所有历史充值记录（时间/金额/方式/状态/订单号）
- **充值到账**：支付成功后实时到账，触发站内通知 + 可选邮件通知
- **充值送额度**：管理员可配置充值满赠活动（如充 ¥1000 送 ¥100）
- **大额充值预警**：单笔 > ¥10000 触发人工审核（finanace 角色确认）

### 上下游关系

```
上游：用户选择金额 → 发起支付 → 对接支付网关 → 异步回调
      回调成功 → 更新 users.balance → 写入 recharge_logs
下游：余额更新 → 调用链：计费引擎扣除余额
      通知服务 → push 站内通知 + 邮件
      finance 角色 → 审核大额充值
```

## 2.10 发票 `/console/invoices`

### 功能描述

用户根据消费记录申请开具发票，支持企业发票和个人发票。

### 完成能力 / 展示效果

- **申请发票**：选择消费区间（可跨月）→ 填写发票抬头（企业需税号）→ 选择发票类型（电子普票/专票）
- **发票列表**：展示所有历史发票记录（发票号/金额/抬头/状态/下载）
- **状态跟踪**：已开票/开票中/已驳回
- **下载**：电子发票支持 PDF 在线下载
- **开票额度**：显示可开票余额（已消费未开票部分）

### 上下游关系

```
上游：consumption_logs 表 → 可开票的消费记录
      用户申请 → 写入 invoice_requests 表
下游：finance 角色 → 审核发票申请 → 确认开票
      邮件服务 → 开票完成通知用户下载
```

### 费用预检说明

用户发起 API 调用时，路由引擎在请求发送给供应商前做费用预检：
1. 解析 `model` 字段 → 查询该模型的定价策略
2. 按 `max_tokens` 参数预估最大费用
3. 检查余额是否能覆盖最大费用（至少 ¥0.01）
4. 能覆盖 → 预扣 → 继续
5. 不能覆盖 → 返回 402 `insufficient_balance`
6. 调用完成后 → 按实际 Token 计算 → 多退少补

### 双因素认证（2FA）

管理员/财务等敏感角色可开启 2FA，提升账号安全性。
- 开启流程：设置 → 安全中心 → 开启双因素认证 → 扫码绑定认证器（Google Authenticator / Authy）
- 验证码：每次登录时，输入密码后还需输入 6 位动态验证码
- 强制范围：可配置指定角色强制开启 2FA
- 恢复码：开启时生成 8 个一次性恢复码，用于丢失认证器时恢复访问
- 关闭：需验证当前 2FA 验证码 + 密码确认

## 2.11 用户账号注销 `/console/settings/account`

### 功能描述

用户在控制台的账户设置中发起账号注销申请，填写原因并确认后提交审核。管理员审核通过后进入数据清除流程（详见 §4.22 数据生命周期管理）。

### 完成能力 / 展示效果


**已注销用户的登录限制：**
- 用户提交注销后，账号状态标记为 `deleting`，仍可登录查看进度
- 管理员审核通过后状态为 `deleted`，无法再登录
- 用户登录提示："账号已注销，如有疑问请联系客服"

### 注销生命周期

```
用户提交注销申请 → 状态标记 deleting ⏳
  ↓ 管理员审核
  审核通过 → 状态标记 deleted，7 天冷静期倒计时 ⏰
    ↓ 用户可在 7 天内联系客服撤回（撤回后恢复为 active）
    ↓ 7 天后（或用户确认立即删除）：
      ├── 执行 §4.22 数据清除流程
      │   ├── 物理删除：users 表（标记 deleted→DELETE）、api_keys、user_preferences
      │   ├── 匿名化保留：call_logs（userId→NULL）、recharge_logs（userId→NULL）
      │   └── 关联记录清除：消费预算、登录历史、安全事件关联
      └── 注销完成通知用户（邮件 + 站内通知）
  审核驳回 → 状态恢复为 active → 通知用户驳回原因
```

### API 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | /api/v1/account/deletion-request | 提交注销申请 |
| GET | /api/v1/account/deletion-request | 查看注销申请状态 |
| POST | /api/v1/account/deletion-request/cancel | 撤回注销申请 |

### 边界条件

| 场景 | 行为 |
|------|------|
| 余额 > 0 时注销 | 弹窗提示流程："注销后余额将清零，建议先消费或联系客服退款" |
| 有进行中的工单 | 提示："您有 N 个工单处理中，建议处理完成后再注销" |
| 有进行中的合同 | 提示："您有 N 个合同未完结，请联系业务员处理" |
| 代理身份用户注销 | 需先清理解除代理关系，名下有子代理时不可注销 |
| 已实名用户注销 | 实名信息在审核通过后退回（不可用），7 天后物理删除 |
