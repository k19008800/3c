# 泳道图 4：供应商状态切换流程

> **对应章节**：PRD-README.md §4.3 供应商与模型管理
> **涉及角色**：系统（自动触发） / 运营管理员
> **状态机**：`active → offline_maintenance → offline_permanent → active`

```mermaid
sequenceDiagram
    participant S as 系统（自动触发）
    participant O as 运营管理员
    participant V as 供应商

    Note over S: 监控触发条件（以下任一）
    Note over S: ① 健康检查连续失败 > 3 次
    Note over S: ② 失败率 > 5%（最近 5 分钟）
    Note over S: ③ 响应时间 P95 > 2s（持续 5 分钟）
    Note over S: ④ 供应商结算余额低于阈值 → 财务告警 → 通知系统管理员（不触发熔断器）

    S->>S: ⑤ 触发熔断器（自动隔离）
    S->>S: ⑥ 路由系统自动切换流量到备用供应商
    S->>O: ⑦ 发送告警通知（供应商异常 + 自动切换）

    O->>O: ⑧ 确认告警，评估影响范围
    O->>S: ⑨ 打开供应商状态切换弹窗

    Note over O: 弹窗内容：
    Note over O: - 影响范围：涉及 N 个模型、M 个用户
    Note over O: - 备用供应商列表及当前状态
    Note over O: - 下线原因（必填）
    Note over O: - 预计恢复时间（可选）

    O->>S: ⑩ 提交状态切换

    alt 切换为下线维护（offline_maintenance）
        S->>S: ⑪ 更新供应商状态（vendors.status）
        S->>S: ⑫ 路由系统排除该供应商
        S->>S: ⑬ 通知受影响用户（站内 + 邮件）
        S->>O: ⑭ 切换完成确认
    else 切换为永久下线（offline_permanent）
        S->>S: ⑪' 更新供应商状态
        S->>S: ⑫' 路由系统永久排除
        S->>S: ⑬' 全部关联模型标记
        S->>S: ⑭' 通知全部用户（模型下线）
        S->>O: ⑮' 需要确认供应商结算事宜
    else 恢复上线（active）
        S->>S: ⑪'' 健康检查通过后自动恢复
        S->>S: ⑫'' 路由系统重新纳入
        S->>O: ⑬'' 通知供应商已恢复
    end

    Note over O: 切换后持续监控
    O->>S: ⑮ 查看备用供应商负载情况
    O->>S: ⑯ 确认整体服务质量正常
```

## 关键决策点

| 步骤 | 决策 | 分支 | 说明 |
|------|------|------|------|
| ⑤ | 熔断器触发 | 自动隔离 | 连续失败 > 3 次自动熔断 |
| ④' | 余额不足 | 财务告警 | 不触发熔断器，走财务告警通道 → 通知 super_admin |
| — | 余额持续不足(24h) | 自动切换 | 系统管理员未处理 → 24h 后自动切换该供应商为维护模式 |
| ⑩ | 下线类型 | 维护/永久/恢复 | 影响范围不同 |
| ⑪'' | 自动恢复 | 健康检查通过 | 5 分钟恢复检查周期 |

## 可能的异常场景

1. **备用供应商也异常** → 全链路降级，仅返回缓存结果
2. **供应商自动恢复后仍有问题** → 二次熔断 + 自动转为 permanent
3. **关键供应商下线** → 高优先级告警，通知所有管理员
4. **用户投诉** → 客服安抚 + 解释原因 + 补偿方案（赠送额度）
