## 0. 变更概述

主 PRD 决策 M-C-01 原定编码规则为**固定短 code**（`{模型缩写}-{供应商code}`，如 `dsv4f-vb`）。
本补充将其修订为：**编码规则后台可自定义，系统默认「厂商 + 模型」**，即默认编码 = `{厂商标识}-{模型名}`。

对业务形态无影响：同一逻辑模型多供应商 → 系统内仍为多条唯一「模型编码」，用户只选模型、无「供应商选择」菜单；
变化仅在**编码的生成规则**：由固定格式变为「默认模板 + 后台可配置模板」。

**示例（默认模板生效）**：逻辑模型 `deepseek-v4-flash` 由供应商 A、B 同时提供 →

| 条目 | 编码（默认生成） | 展示名 |
|------|----------------|--------|
| 供应商A | `va-deepseek-v4-flash` | deepseek-v4-flash（供应商A） |
| 供应商B | `vb-deepseek-v4-flash` | deepseek-v4-flash（供应商B） |

## 2. 编码规则定义（规格）

### 2.1 默认模板（「厂商+模型」）

```
默认模板：{supplier_code}-{model_name}
```

- `{supplier_code}`：供应商 code（`suppliers.code`，ASCII 安全、稳定）；供应商无 code 时回退 `suppliers.name` 并执行清洗。
- `{model_name}`：逻辑模型名（`supplier_models.model_name`，如 `deepseek-v4-flash`）。
- 默认语义即「厂商 + 模型」：同一模型不同厂商 → 编码前缀不同 → 天然多条唯一编码。

### 2.2 模板变量白名单（后台自定义时可选）

| 变量 | 取值 | 示例值 |
|------|------|--------|
| `{supplier_code}` | 供应商 code | `vb` |
| `{supplier_name}` | 供应商名称 | `云供应商B` |
| `{model_name}` | 逻辑模型名 | `deepseek-v4-flash` |
| `{model_short}` | 模型名缩写（字母数字连字符清洗） | `dsv4f` |
| `{platform_model}` | 上游真实模型名 | `deepseek-v4-flash` |
| `{seq}` | 序号（唯一冲突兜底） | `2` |

### 2.3 清洗与校验规则

1. 模板渲染结果仅保留 `[a-zA-Z0-9_-]`，其余字符（含中文、空格、`@`、`.` 等）替换为 `-`。
2. 连续 `-` 合并为单个；首尾 `-` 去除；长度截断至 200。
3. 全局唯一性：命中已有编码 → 自动追加 `-{seq}`（`2,3,…`）；仍冲突则保存失败并提示。
4. 模板保存校验：变量必须来自 §2.2 白名单；字面量仅允许 `[a-zA-Z0-9_-]`；含 `@` 一律拒绝。
5. 渲染结果为空或全部被清洗 → 保存/生成失败并提示「变量值不可编码，请使用厂商 code 或模型名」。

### 2.4 变更生效边界（M-C-07）

- 修改全局模板：仅对**新接入/尚未生成编码**的映射生效；存量编码**不自动重写**。
- 单条「重新生成」：后台可对指定映射按当前模板重新生成编码（操作确认弹窗提示：调用方已使用旧编码将 404，需同步变更通知）。
- 编码一经生成：不可复用、不可改码（沿用主 PRD 规则）；改码必须走迁移流程。

## 5. 验收关注点

1. 无配置（默认）：编码 = `{供应商code}-{model_name}`（厂商+模型），同一模型多供应商生成多条唯一编码。
2. 后台修改模板 → 新映射按新模板生成；存量编码不变。
3. 模板含未知变量 / 非法字符 / `@` → 保存 400 + 明确提示。
4. 渲染冲突 → 自动追加 `-{seq}`；复用/改码被拒。
5. 「恢复默认模板」生效且不重写存量。
6. 新增/改动页面与按钮 `[?]` 帮助齐全。
7. 与主 PRD 验收一致：编码精确路由、404/400/403、默认编码偏好、DB 空回退全部不受影响。
