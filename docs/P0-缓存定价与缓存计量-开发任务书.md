   - 新增显式价公式：
     ```ts
     export interface CacheCostResult extends CacheBillingResult {
       cacheWriteTokens: number;   // 缓存写入 token 数（已收敛）
       cacheHitCost: number;       // 缓存读取计费金额（¥）
       cacheWriteCost: number;     // 缓存写入计费金额（¥）
       cacheWritePriceSource?: 'explicit' | 'full_price';  // D-4
     }
     export function computeCacheCost(
       inputTokens: number,
       outputTokens: number,
       pricing: TokenPricing & { cacheReadInputPrice?: number | null; cacheWriteInputPrice?: number | null },
       cacheTokens: CacheTokenInfo | null | undefined,
       cacheReadPrice: number,
       cacheWritePrice: number,
     ): CacheCostResult
     ```
     公式（方案 §6）：
     ```
     输入费用 = cacheRead × cacheReadPrice + cacheWrite × cacheWritePrice
               + (prompt − cacheRead − cacheWrite) × inputPrice
     输出费用 = completion × outputPrice
     cacheHitCost = cacheRead × cacheReadPrice；cacheWriteCost = cacheWrite × cacheWritePrice
     discountAmount = 全价（全部按 input/output 价）− 实际费用（≥ 0）
     ```
     - 收敛（**D-11 双保险**）：`read = min(cacheReadTokens, input)`；`write = min(cacheWriteTokens, input − read)`。

## 4. 计费引擎改造说明

### 4.1 价格解析优先级（P0 生效 4 级，D-10）

| 级 | 来源 | 说明 | P0 状态 |
|----|------|------|---------|
| 1 | `models.override_cache_read_input_price` | L2 覆盖 | **缺省（D-10）**：models 表不存在、P0 不建；**级 2 default 组显式缓存价列天然承载 L2 覆盖语义**（pricing.ts 中 default 组即 L2 载体，双载体歧义消除） |
| 2 | `vendor_pricing.cache_read_input_price` | L1 标准价显式缓存读取价 | ✅ 实现（权威计费依据） |
| 3 | `vendor_pricing.cache_discount_rate` → `**生效 input** × rate` | 兼容/快捷（D-3：生效 input_price = 请求最终生效输入单价，经 L5/L4/L3/L2/L1 后） | ✅ 实现 |
| 4 | `system_config.billing.cache_hit_discount` → `生效 input × rate` | 全局（默认 0.1） | ✅ 实现 |
| 5 | `CACHE_HIT_DISCOUNT = 0.1` 代码兜底 | 前 4 级不可用 | ✅ 实现 |

写入价解析（D-3）：显式 `cache_write_input_price` → 缺失按**生效 input 全价**（保守口径，来源标识 `full_price`，D-4）。显式缓存价（级 2）独立于折扣类优惠（L3 代理折扣只乘总费用，不联动缓存显式价）。

### 4.2 `cache_pricing_mode` 开关（D-13）

- 读取：`getCachePricingMode()`（T1，Redis 缓存 60s + 后台修改即时失效）。
- `explicit`（**默认**）：读取价走 §4.1 全链（显式优先），写入价显式优先/全价兜底。存量无显式价模型自动回退 折扣率→全局→兜底，**行为与旧版一致，默认即安全**。
- `discount_rate`（灰度/回退开关）：读取价强制走折扣率链（3→4→5），写入 token 按全价——**与旧版计费结果完全一致**（§12 验收 2、§10.4）。后台一键切换，无需发版。

### 4.3 公式与精度（D-1）

```
输入费用 = cacheRead × cacheReadPrice + cacheWrite × cacheWritePrice
         + (prompt − cacheRead − cacheWrite) × inputPrice
输出费用 = completion × outputPrice
总费用   = (输入费用 + 输出费用) × user_discount_rate   ← 沿用现有用户折扣链路（外部乘）
cacheHitCost   = cacheRead × cacheReadPrice
cacheWriteCost = cacheWrite × cacheWritePrice
cacheDiscount  = 全价（input×prompt + output×completion）− 实际费用（≥ 0）
```

- 收敛（D-11）：`read = min(read, prompt)`；`write = min(write, prompt − read)`（归一化层与计费层双保险同规则）。
- **精度（D-1 定稿）**：单价列 numeric(18,6)（¥/1K）；**计费金额一律 numeric(18,8)（元），计算输出 `toFixed(8)`**——与 `consumption_records.cost / cache_discount` 现有精度完全一致，**不引入 6 位/4 位舍入层**；批量按每笔计算后汇总；展示 toFixed(2) 属前端职责（不丢原始精度）。ref-5.2 §8.2"4 位"/§3.1"6 位"的文档同步修订由 product-agent 执行（R-P2），实现以 8 位为准。
- 生效范围（D-9）：非流式 + 携带 usage 缓存字段的流式（`stream_options.include_usage`，注入 chat/messages/openai-compat）均适用；上游未返回缓存字段 → 公式退化为全价，计费结果与现状一致。

### 4.4 流式计费时点与回滚口径（A9 时序确认，R-B2）

> 详见 T4"**A9 时序确认**"注释块。要点：计费时点 = 流结束采信**末帧（finish_reason 非空）usage**（`determineStreamBilling` 采信 `lastValidUsage`，缓存字段随末帧透传）；失败回滚口径 = 已累计有效 usage → 按累计结算多退少补 / 无 usage 有文本 → fallback 全价 / 无响应 → 回滚预扣全额；预扣估算仍按全价（不含缓存价，方向安全不会少扣，评审 §6.5）；**无新增状态机/回滚改动**。
