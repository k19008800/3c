## 23.1 操作审计追溯增强

### 功能描述

在现有 `audit_logs` / `operation_logs` 基础上，增加前端"审计追溯"能力。用户在关键操作后可以查看"谁在什么时候改了什么"，支持按用户/操作类型/时间范围多维筛选。

### 完成能力 / 展示效果

**用户端操作日志页增强：**

```

  2026-07-28 10:23  |  修改 API Key 权限  |  限制模型: GPT-4
  2026-07-25 14:12  |  禁用 API Key       |  Key: 测试环境 Key
  2026-07-20 09:00  |  创建 API Key       |  "我的生产 Key"
  2026-07-18 16:45  |  修改密码           |  ----
```

**管理后台审计日志页增强：**


### 功能规格

| 维度 | 用户端操作日志 | 管理后台审计日志 |
|------|--------------|----------------|
| 数据范围 | 仅当前用户的操作 | 所有用户的操作 |
| 筛选条件 | 操作类型/时间 | 操作用户/目标/时间 |
| 查看权限 | 用户本人 | audit_admin 或 super_admin |
| 导出 | 支持 CSV 导出 | 支持 CSV/JSON 导出 |

### API 接口

```

// 管理后台（复用现有 audit_logs）
GET /api/v1/admin/audit-logs?operatorId=&targetType=&startDate=&endDate=&page=&limit=
GET /api/v1/admin/audit-logs/:id    — 审计详情
GET /api/v1/admin/audit-logs/export — 导出
```

## 23.2 全局搜索（Cmd+K）

### 功能描述

管理后台提供全局搜索面板（类似 Cmd+K 快捷键），一键搜索用户/API Key/模型/供应商/订单等，搜索结果聚合展示，点击直接跳转。

### 完成能力 / 展示效果

```
按 Cmd+K (Mac) 或 Ctrl+K (Windows) → 弹出搜索面板：

┌────────────────────────────────────────────┐
│  🔍 搜索用户、Key、模型、订单...             │
├────────────────────────────────────────────┤
│                                            │
│  用户                                        │
│  ├── zhangsan@example.com  (ID: 42)         │
│  ├── lisi@example.com      (ID: 88)         │
│                                            │
│  API Key                                    │
│  ├── sk-abc...xyz (生产环境 Key)             │
│  ├── sk-def...uvw (测试环境 Key)             │
│                                            │
│  模型                                        │
│  ├── deepseek-chat (DeepSeek)               │
│  ├── qwen-plus (阿里云)                      │
│                                            │
│  订单                                        │
│  ├── 充值订单 #20260728-0001 (¥100.00)      │
│                                            │
│  按 ↑↓ 导航 | 按 Enter 跳转 | 按 Esc 关闭   │
└────────────────────────────────────────────┘
```

### 搜索范围

| 搜索类型 | 搜索结果 | 跳转目标 |
|---------|---------|---------|
| 用户 | 按 ID/邮箱/用户名模糊匹配 | 用户详情页 |
| API Key | 按 Key 名称/掩码匹配 | Key 管理页 |
| 模型 | 按模型 ID/名称匹配 | 模型配置页 |
| 供应商 | 按供应商名称匹配 | 供应商详情页 |
| 订单（充值/提现） | 按订单号匹配 | 订单详情页 |
| 页面跳转 | 输入 "用户管理" "日志" 等 → 显示路由匹配 | 对应页面 |

### 后端接口

```
GET /api/v1/admin/search?q=keyword&types=user,key,model,vendor,order
  响应: { users: [], keys: [], models: [], vendors: [], orders: [], pages: [] }
  超时: 3 秒（部分类型超时不阻塞其他类型）
  限流: 每用户每秒最多 3 次搜索
```

### 前端组件

```tsx
interface GlobalSearchProps {
  open: boolean;
  onClose: () => void;
}

interface SearchResult {
  type: 'user' | 'key' | 'model' | 'vendor' | 'order' | 'page';
  label: string;        // 显示名称
  sublabel?: string;    // 次要信息（如邮箱）
  path: string;         // 跳转路由
  icon?: string;
}
```

### 验收标准

1. 按下 Cmd+K → 弹出搜索面板 → 输入关键词 → 显示聚合搜索结果
2. 搜索结果按类型分组展示
3. 按 Enter → 自动跳转到对应页面
4. 按 Esc → 关闭搜索面板
5. 输入不同关键词 → 搜索结果实时更新

## 23.3 快捷键支持

### 功能描述

管理后台和用户端常用操作支持键盘快捷键，提升高效用户的操作速度。

### 快捷键清单

| 快捷键 | 作用 | 范围 |
|--------|------|------|
| `g + d` | 跳转仪表盘 | 管理后台/用户端 |
| `g + k` | 跳转 API Key 管理 | 用户端 |
| `g + l` | 跳转调用日志 | 用户端/管理后台 |
| `g + u` | 跳转用户管理 | 管理后台 |
| `g + m` | 跳转模型管理 | 管理后台 |
| `g + v` | 跳转供应商管理 | 管理后台 |
| `?` | 显示所有快捷键帮助 | 全部 |
| `Ctrl+Enter` | 提交当前表单（Playground） | 用户端 |
| `Escape` | 关闭弹窗/取消选择 | 全部 |

### 实现

- 使用 `react-hotkeys-hook` 或 `mousetrap.js`
- 快捷键仅在焦点不在输入框时触发（防止输入框内误触发）
- 快捷键帮助面板：按 `?` 弹窗显示全部快捷键

### 验收标准

1. 在管理后台按 `g + d` → 跳转到仪表盘
2. 在用户端按 `g + k` → 跳转到 API Key 管理页
3. 按 `?` → 弹窗展示所有可用的快捷键
4. 在输入框中输入 `g + d` → 不触发跳转

## 23.4 i18n 国际化架构

### 功能描述

为未来出海或英文用户做架构准备。规划多语言框架（i18n），第一阶段 Portal 页面支持中英文切换，管理后台暂不涉及。

### 架构设计

```
前端 i18n 方案：
├── 框架: react-i18next + i18next-browser-languagedetector
├── 语言文件: public/locales/{lang}/translation.json
├── 第一阶段语言: zh-CN（默认）、en
├── 自动检测: 浏览器语言自动切换（navigator.language）
├── 手动切换: Portal Footer 增加语言切换下拉
└── URL 策略: 子路径方式 /zh/pricing /en/pricing（利于 SEO）

后端:
├── 不需要 i18n
├── 错误消息: 统一英文，前端负责翻译
└── 管理后台: 暂不支持国际化
```

### Portal 翻译范围（第一阶段）

| 页面 | 翻译要素 | 工作量估计 |
|------|---------|-----------|
| 首页 | Hero/特性/HowItWorks/CTA | ~50 条 |
| 定价页 | 定价表/FAQ | ~30 条 |
| 模型目录 | 分类/筛选/模型名称（保留英文） | ~20 条 |
| 文档页 | 全部文档内容 | ~200 条 |
| Blog/帮助中心 | 用户生产的内容不翻译 | — |

### 验收标准

1. Portal 页面根据浏览器语言自动切换中英文
2. Footer 语言切换下拉 → 切换后页面立即响应
3. 英文 URL 使用 `/en/pricing` 结构，SEO 正确
4. 翻译缺失时降级显示中文

## 23.5 移动端适配

### 功能描述

用户端关键页面（Dashboard/Key 管理/日志/统计）实现响应式适配，在手机上可读可用。管理后台深度大，暂不覆盖。

### 适配页面优先级

| 优先级 | 页面 | 适配要求 |
|--------|------|---------|
| P1 | `/console/dashboard` | 卡片布局改为垂直堆叠，核心指标数字放大 |
| P1 | `/console/api-keys` | 表格改为卡片列表，操作按钮折叠到"更多" |
| P1 | `/console/logs` | 列减少（仅显示时间和关键信息），筛选折叠 |
| P2 | `/console/stats` | 图表缩小但保持可读，切换周/月视图 |
| P2 | `/console/recharge` | 输入框和按钮适配触屏 |
| P2 | `/console/settings` | 侧边栏改为底部 tab |

### 实现

```
技术方案:
├── TailwindCSS 响应式断点: sm(640px) / md(768px) / lg(1024px)
├── 布局: Grid → 移动端单列, 桌面端多列
├── 表格: 移动端 → 隐藏非关键列 + 左侧缩略展示
├── 图表: Recharts 响应式容器（width="100%"）
├── 导航: 左侧侧边栏 → 移动端底部 Tab Bar 或汉堡菜单
└── 测试: Chrome DevTools 手机模拟 + 真实设备测试
```

### 验收标准

1. 在 375px 宽的手机屏幕上，Dashboard 卡片垂直排列，数字清晰可读
2. API Key 列表在手机上每行展示关键信息（名称+状态），操作通过"更多"菜单
3. 日志页在手机上显示时间和核心内容，筛选可展开/折叠
4. 移动端底部导航可正常切换页面

## 边界条件

### 模块概述

系统级能力增强涵盖操作审计追溯增强、全局搜索（Cmd+K）、快捷键支持、i18n 国际化架构、移动端适配。

### 边界条件清单

| # | 场景 | 触发条件 | 预期行为 | 影响范围 | 优先级 |
|---|------|---------|---------|---------|--------|
| SYS-001 | 全局搜索索引失败 | 全局搜索引擎重建索引时部分数据源不可用 | 已成功索引的数据源正常搜索；失败的数据源标记"索引暂不可用"，并在搜索结果中显示数量较少的提示；索引任务自动重试 | 全局搜索 | P0 |
| SYS-002 | i18n 语言切换不全 | 切换语言后部分界面文字未翻译（缺少翻译文件） | 未翻译的 key 使用 key 本身或英文 fallback 展示；翻译缺失不阻塞功能使用；后台显示"翻译覆盖率"监控面板 | 用户界面 | P1 |
| SYS-003 | 快捷键冲突 | 系统内置快捷键与用户浏览器默认快捷键冲突 | 系统快捷键重新绑定可自定义；检测到冲突时提示用户选择；使用 `Ctrl+Shift+` 前缀以减少与浏览器默认冲突 | 快捷键系统 | P1 |
| SYS-004 | 审计追溯查询超时 | 查询跨度很大（如 1 年）的操作审计日志 | 审计日志查询超时 30 秒，返回已查询的部分结果；建议缩小时间范围；支持按模块、操作类型、操作人分片查询 | 审计追溯 | P1 |
| SYS-005 | 移动端适配布局断裂 | 在非标准分辨率或老旧浏览器上使用移动端 | 移动端使用响应式断点设计（320px / 375px / 414px / 768px）；对 ES6+ 特性使用 polyfill；不支持的浏览器显示"浏览器版本过低"提示 | 移动端页面 | P1 |
| SYS-006 | 操作审计事件积压 | 审计事件产生速率超过事件处理速率 | 审计使用独立的事件处理队列；队列积压超过 10000 条时触发告警；若积压持续增长，降级为批量提交（每 5 秒提交一次） | 审计系统 | P2 |
| SYS-007 | i18n 动态内容翻译丢失 | 后端动态生成的错误消息/通知缺少翻译 | 动态消息使用预定义的翻译键（message key），参数化填充；缺少翻译键时显示英文原始消息 + 语言标签 | 用户界面 | P2 |

### 详细边界说明

#### SYS-001: 全局搜索索引失败

**恢复策略**:
- 数据源索引失败后自动重试 3 次（间隔 30s/2min/5min）
- 连续 3 次失败则标记该数据源索引为 `FAILED`
- 管理员可在搜索设置中手动触发单独重建
- 索引失败不影响其他健康数据源的搜索功能

#### SYS-003: 快捷键冲突

**处理规则**:
- 系统内置快捷键使用 `Ctrl+Shift+Key` 组合，减少与浏览器默认冲突
- 用户可在设置中自定义快捷键绑定的操作
- 检测到已占用的快捷键时，在高亮显示冲突并让用户选择
- 重置所有快捷键为默认的入口

### 异常流程汇总

| 场景 | 恢复策略 | 是否通知 |
|------|---------|---------|
| 搜索索引失败 | 部分索引可用 + 自动重试 | P2 运维通知 |
| i18n 翻译缺失 | 英文 fallback | 无 |
| 快捷键冲突 | 自定义绑定 + 冲突提示 | 用户提示 |
| 审计查询超时 | 返回部分结果 | 用户提示 |
| 事件积压 | 降级写入 + 告警 | P2 运维通知 |
