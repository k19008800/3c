# 方案：模型缓存定价与缓存计量（缓存费用闭环）

> 状态：方案设计稿（待 product-agent 落 PRD / backend-agent 落实现）
> 关联：`ref-5.2-billing.md §3.2.1`、`ref-2.2.2-model-center.md`、`ref-4.3-vendor-model.md`、`ref-4.15-vendor-settlement.md`、`data-dictionary.md §2.2/§2.6`

## 一、问题与现状

| # | 缺口 | 现状 | 后果 |
|---|------|------|------|
| G1 | **渠道模型定价没有缓存费用定义** | `vendor_models` 仅有 `input_price/output_price/cost_input_price/cost_output_price`，无任何缓存字段 | 缓存成本无法定价 → 渠道结算无法区分缓存成本，毛利率失真 |
| G2 | **渠道模型定价没有显式缓存价格** | `vendor_pricing` 只有 `cache_discount_rate`（命中按全价×折扣率） | ① 无法表达各上游**独立发布的缓存读取价**（DeepSeek 命中 ¥0.5/1M vs 未命中 ¥2/1M）；② 无法表达 Anthropic 的**缓存写入价**（`cache_creation` 有独立单价）；③ 折扣率是"比例"，不满足"给用户明码标价" |
| G3 | **用户无处查询缓存定价** | 模型中心价格弹窗设计稿含 `cache_hit_price`，但数据来源未定义、列表不展示、公开价目/帮助中心缺失 | 用户无法预知缓存调用成本 |
| G4 | **用户看不到调用消费到的缓存信息** | `call_logs` 有 `cache_hit_tokens/cache_discount` 落库，但调用日志页、用量统计、账单均不透出 | 用户不知道"这次调用有多少 token 命中缓存、省了多少钱" |

## 二、目标

1. 渠道模型定价、渠道模型定价中**显式定义模型缓存费用**（读取价 + 写入价，双轨兼容现有折扣率）。
2. 用户可在**模型中心、公开价目 API、帮助中心**查询缓存定价信息。
3. 用户在**调用日志、用量统计、账单、调用响应**中看到 token 消费到的缓存信息（命中/写入 token、缓存费用、节省金额）。
4. 渠道结算按缓存成本价拆分，审计与对账可追溯。

## 三、核心设计决策

**从"折扣率"升级为"显式价格为主、折扣率为兼容层"的双轨制：**

- **显式价格（权威计费依据）**：`cache_read_input_price`（缓存读取/命中单价）、`cache_write_input_price`（缓存写入单价，仅 Anthropic 系使用）。
- **折扣率（兼容/快捷配置）**：保留 `cache_discount_rate`。未配置显式价格时回退到折扣率计算（`缓存读取价 = 输入价 × 折扣率`），保证存量模型行为不变；配置显式价格后自动反推折扣率仅用于展示。
- **计价单位**：与现有价格一致为 **¥/1K tokens**；上游同步时做单位归一化（上游 `/1M` → ÷1000 存 `/1K`）。

> 理由：三家主流上游（DeepSeek/Anthropic/OpenAI）官方均发布**显式缓存价格**，折扣率无法表达写入价，且用户要的是"明码标价"。

## 四、数据模型变更

### 4.1 `vendor_models`（渠道模型，L0 成本价）

```typescript
costCacheReadInputPrice:  numeric("cost_cache_read_input_price",  { precision: 18, scale: 6 }),  // 缓存读取成本价（¥/1K，可空）
costCacheWriteInputPrice: numeric("cost_cache_write_input_price", { precision: 18, scale: 6 }),  // 缓存写入成本价（¥/1K，可空）
```

- 由渠道同步引擎从上游价格页抓取/映射填充；无法获取时置空。
- 渠道自助价格维护页（ref-4.10）同步开放这两个字段。

### 4.2 `vendor_pricing`（渠道售价，L1 标准价）

```typescript
cacheReadInputPrice:  numeric("cache_read_input_price",  { precision: 18, scale: 6 }),  // 缓存读取售价（¥/1K，可空）
cacheWriteInputPrice: numeric("cache_write_input_price", { precision: 18, scale: 6 }),  // 缓存写入售价（¥/1K，可空）
// cacheDiscountRate 保留，语义降级为"兼容/快捷配置 + 展示反推"
cacheDiscountRate: varchar("cache_discount_rate", { length: 10 }),  // 0-1，可空
```

### 4.3 `models`（模型覆盖价，L2，可选增强）

```typescript
overrideCacheReadInputPrice:  numeric("override_cache_read_input_price",  { precision: 18, scale: 6 }),  // 可空
overrideCacheWriteInputPrice: numeric("override_cache_write_input_price", { precision: 18, scale: 6 }),  // 可空
```

### 4.4 `call_logs` / `consumption_records`（调用计量审计）

```typescript
// 已有
cacheHitTokens: integer("cache_hit_tokens"),                    // 缓存命中（读取）token 数
cacheDiscount:  numeric("cache_discount", { precision: 18, scale: 8 }),  // 节省金额（全价口径 − 实际口径）
// 新增
cacheWriteTokens: integer("cache_write_tokens"),                // 缓存写入 token 数（Anthropic cache_creation）
cacheHitCost:     numeric("cache_hit_cost", { precision: 18, scale: 8 }),   // 缓存读取计费金额
cacheWriteCost:   numeric("cache_write_cost", { precision: 18, scale: 8 }), // 缓存写入计费金额
```

### 4.5 `billing_logs`（定价快照，审计/对账）

```typescript
cacheReadInputPrice:  numeric("cache_read_input_price",  { precision: 18, scale: 6 }),  // 本次调用实际采用的缓存读取单价快照
cacheWriteInputPrice: numeric("cache_write_input_price", { precision: 18, scale: 6 }),  // 本次调用实际采用的缓存写入单价快照
```

### 4.6 全局配置（`system_config.billing`）

| key | 类型 | 默认 | 说明 |
|-----|------|------|------|
| `cache_hit_discount` | decimal (0,1] | `0.1` | 保留，降级为第 3 级回退 |
| `cache_pricing_mode` | `explicit` / `discount_rate` | `explicit` | 计费模式开关；`discount_rate` 为兼容旧行为 |

### 4.7 渠道结算快照（`vendor_settlement_snapshots`）

- `unitPriceCache` 取值源改为 `cost_cache_read_input_price`（读取）与 `cost_cache_write_input_price`（写入），与 `cachedTokens/costCache` 对齐拆分。

## 五、上游 usage 归一化

| 上游 | 原始字段 | 归一化 | 说明 |
|------|---------|--------|------|
| DeepSeek | `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens` | 命中 → `cacheReadTokens`；miss 不单独计 | 命中/未命中成对出现 |
| Anthropic | `cache_read_input_tokens` / `cache_creation_input_tokens` | read → `cacheReadTokens`；creation → `cacheWriteTokens` | **写入价独立** |
| OpenAI | `prompt_tokens_details.cached_tokens` | → `cacheReadTokens` | 官方按 50% 计费，落显式价 |
| 其他/无缓存字段 | — | 全部按未命中全价 | 与现状一致 |

约束：`cacheReadTokens + cacheWriteTokens ≤ prompt_tokens`，超出时收敛到输入数（沿用现规则）。

## 六、计费公式与引擎变更

```
输入费用 = cacheReadTokens × cacheReadPrice
         + cacheWriteTokens × cacheWritePrice
         + (prompt_tokens − cacheReadTokens − cacheWriteTokens) × inputPrice
输出费用 = completion_tokens × outputPrice
总费用   = (输入费用 + 输出费用) × user_discount_rate
```

**价格解析优先级（读取价，从高到低）：**

| 级 | 来源 | 说明 |
|----|------|------|
| 1 | 模型覆盖价 `models.override_cache_read_input_price` | L2，可空 |
| 2 | 标准价 `vendor_pricing.cache_read_input_price` | L1，可空 |
| 3 | 折扣率 `vendor_pricing.cache_discount_rate` → `input_price × rate` | 兼容/快捷 |
| 4 | 全局 `system_config.billing.cache_hit_discount` → `input_price × rate` | 默认 0.1 |
| 5 | 代码兜底 `CACHE_HIT_DISCOUNT = 0.1` | 前四级均不可用 |

**写入价解析**：显式价缺失时按 `input_price` 全价计（保守口径，标注"未配置写入价"）。`cache_pricing_mode = discount_rate` 时：写入 token 按全价、读取按折扣率，行为与旧版完全一致。

**生效范围**：非流式 + 携带 usage 缓存字段的流式（`stream_options.include_usage`）均适用；上游未返回缓存字段时公式退化为全价，计费结果与现状一致。

## 七、用户查询缓存定价（G3 闭环）

### 7.1 模型中心

- **ModelCard 价格区**：有缓存读取价的模型展示 `输入 ¥x / 输出 ¥y / 缓存读取 ¥z`（无缓存计费能力的模型不显示）。
- **PriceDetailModal**：新增「缓存计费」区块，展示缓存读取单价、缓存写入单价（如有）、示例换算（"输入命中 1K tokens 仅 ¥z，未命中 ¥x"）+ 每项 `[?]`。
- 数据来源：`vendor_pricing` / `models` 覆盖价解析后的**实收价**，与计费引擎同源。

### 7.2 API

| 接口 | 变更 |
|------|------|
| `GET /api/v1/me/models/:id/price` | `prices` 增加 `cache_read_input_price` / `cache_write_input_price`；新增 `cache_pricing_mode` 与回退说明 |
| `GET /api/v1/me/models` | 列表项增加 `cache_read_input_price`（轻量，可空） |
| `GET /api/v1/public/models` | 公开价目增加缓存价（无鉴权，价目透明） |
| `GET /api/v1/admin/pricing` / `PUT /api/v1/admin/pricing/:id` | 增/改缓存读取价、写入价（校验：≥0；写入价可空；单位 ¥/1K） |
| `GET /api/v1/admin/vendor-costs` | 渠道成本列表增加缓存成本价 |

### 7.3 帮助中心与通知

- 帮助中心新增《模型缓存计费说明》：缓存是什么、哪些模型支持、怎么查价、怎么在日志里看命中。
- 各模型价格表页（可嵌入模型中心）展示缓存价列。
- 价格变更通知（`§5.5`）把"缓存价变更"纳入 `fields` 变更集合，用户可订阅。

## 八、消费侧缓存信息透出（G4 闭环）

### 8.1 调用日志（`/console/logs`）

- 表格列新增「缓存命中」：显示 `cache_hit_tokens`，命中 > 0 时高亮并显示 `节省 ¥x`。
- 行展开详情新增「缓存计费」区：读取命中/写入 token、对应单价、缓存费用、节省金额。

### 8.2 用量统计（`/console/stats`）

- Token 消耗构成堆叠图增加 **缓存命中 / 缓存写入 / 未命中** 三段。
- 指标卡新增「本月缓存节省 ¥xx」（= `cache_discount` 合计）。

### 8.3 账单（`/console/billing` + PDF/CSV）

- `by_model` 明细增加 `cache_hit_tokens` / `cache_savings`；CSV 增加 `cache_hit_tokens/cache_write_tokens/cache_hit_cost/cache_write_cost/cache_discount` 列。

### 8.4 调用响应透传（用户自己的系统可读）

- 网关转发响应时**透传**上游 usage 中的缓存字段，并在 `usage` 上补充平台归一化字段：

```json
"usage": {
  "prompt_tokens": 234,
  "completion_tokens": 567,
  "prompt_tokens_details": { "cached_tokens": 100 },
  "cache_read_tokens": 100,
  "cache_write_tokens": 0,
  "cache_cost": "0.00005",
  "cache_savings": "0.00045"
}
```

- 兼容：OpenAI 兼容端点（`/v1/chat/completions` 等）保持原 usage 结构 + 增加扩展字段，不破坏既有解析。

### 8.5 实时反馈

- Playground / 调用详情页展示"本次调用命中缓存，节省 ¥x"。

## 十、兼容与迁移

1. 存量数据：新字段全部可空，无数据迁移。
2. 存量模型未配显式缓存价：按折扣率/全局回退，计费结果与现状一致（0.1 折扣），**无行为变更**。
3. 配置显式缓存价后计费金额可能变化 → 按价格变更流程（`§5.5`）通知受影响用户。
4. `cache_pricing_mode = discount_rate` 可一键回到旧行为，作为灰度开关。

## 十二、验收要点（test-agent 引用）

1. 归一化：DeepSeek/Anthropic/OpenAI 三份 usage 样例 → `cacheReadTokens/cacheWriteTokens` 正确。
2. 计费：命中>输入收敛；写入价缺失按全价；折扣率回退；`discount_rate` 模式与旧版结果一致。
3. 查询：`/me/models/:id/price`、`/public/models` 返回缓存价；管理端 CRUD 校验（≥0、单位提示）。
4. 透出：调用日志列/详情、用量统计堆叠、账单 CSV 列齐全。
5. 结算：结算快照缓存成本拆分正确；`billing_logs` 快照可审计。
6. 精度：金额 6~8 位小数规则与 `ref-5.2 §8.2` 一致。
