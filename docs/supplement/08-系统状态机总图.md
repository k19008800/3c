## 二、模块间触发关系

### 2.1 充值 → 余额 → 总账

```
充值模块                余额模块                总账模块
─────────              ────────              ────────
充值订单 success ──────► 用户余额 +amount ────► platform_ledger
                                                  type=user_recharge
                                                  direction=in

充值订单 refunded ─────► 用户余额 -amount ────► platform_ledger
                                                  type=user_refund
                                                  direction=out
```

### 2.2 调用 → 计费 → 余额 → 总账

```
路由引擎              计费模块                余额模块                总账模块
─────────             ────────              ────────              ────────
call_logs pending ───► billing_logs pending ──► 预扣余额
                        │
call_logs completed ──► billing_logs settled ──► 多退少补 ────────► 日终归集
                        │                                            type=user_consumption
call_logs failed ─────► billing_logs refunded ──► 退还预扣
```

### 2.3 计费 → 代理佣金 → 总账

```
计费模块                代理佣金                总账模块
─────────              ────────              ────────
billing_logs settled ──► 日终计算佣金 ────────► 日终归集
                        agent_commissions        type=agent_commission
                        persistent               direction=out
```

### 2.4 代理提现 → 余额 → 总账

```
代理模块                余额模块                总账模块
─────────              ────────              ────────
提现申请 ──► 冻结佣金余额
                        │
提现审批通过 ──► 扣减佣金余额 ────────────────► platform_ledger
                                                 type=agent_withdraw
                                                 direction=out
```

## 四、模块间依赖关系

### 4.1 强依赖（必须按顺序执行）

```
充值 → 余额 → 总账
  └── 充值订单 success 必须在余额到账之前写入（但可接受 500ms 延迟）

调用 → 计费 → 余额
  └── 必须先预扣余额，再转发到供应商

计费 → 佣金 → 提现
  └── 佣金计算必须基于已 settled 的 billing_logs
  └── 提现必须在佣金计算完成之后
```

### 4.2 弱依赖（可异步处理）

```
计费 → 总账
  └── 总账归集是 T+1 批处理，不要求实时

对账 → 所有模块
  └── 对账是 T+1 的校验过程，不阻塞实时交易

路由熔断 → 供应商
  └── 熔断状态更新是异步的，不影响正在进行的请求
```

### 4.3 无依赖（可独立部署）

```
通知模块 ↔ 其他模块
  └── 通知发送可通过消息队列解耦
```

## 五、关键时间点汇总

| 时间 | 事件 | 模块 |
|------|------|------|
| 实时 | 用户充值 → 回调 → 余额到账 | 充值 → 余额 |
| 实时 | 用户调用 → 预扣 → 转发 | 计费 → 路由 |
| 实时 | 供应商返回 → 结算 | 计费 |
| 60s 后 | 预扣未返回 → 标记 orphaned | 计费 |
| 30min 后 | 充值未支付 → 标记 expired | 充值 |
| 每小时 | 过期覆盖清理 | 路由 |
| 每日 00:30 | 充值对账 | 对账 |
| 每日 00:35 | 计费对账 | 对账 |
| 每日 00:40 | 总账归集 | 总账 |
| 每日 00:45 | 余额校验 | 对账 |
| 每日 00:50 | 佣金计算 | 代理 |
| 每日 01:00 | 佣金汇总 | 代理 |
| 每日 02:00 | 快照生成 | 代理 |
| 每月 1 日 | 月结算切换 | 代理 |
| 每月 5 日 | 上个月佣金结算锁定 | 代理 |
| 每 30 秒 | 主动健康探测 | 路由 |
| 每 5 分钟 | 深度健康探测 | 路由 |
