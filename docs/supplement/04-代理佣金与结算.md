## 一、佣金等级与费率体系

### 1.1 代理等级

| 等级 | 枚举值 | 默认佣金率 | 月调用量门槛 | 提现权限 | 状态（后台主导版） |
|------|--------|-----------|-------------|---------|------|
| 预备 | `preparatory` | 0% | 无 | ❌ 不可提现 | 仅后台「设为代理商」创建，无自助获得 |
| 一级 | `primary` | 10% | 无 | ✅ 可提现 | 等级仅后台可调 |
| 高级 | `advanced` | 12%~18%（阶梯）| ≥ 100 万 Token | ✅ 可提现 | 等级仅后台可调 |
| ~~子代理~~ | ~~`sub`~~ | — | — | — | **已移除（D1：单级）** |

### 1.2 佣金率存储

> ⚠️ 当前实现（`api/src/db/schema/agents.ts`）为**单一费率** `agents.commission_rate`；下表 `commission_rules`（模型级/用户级精细费率）为扩展设计，可暂不实现。以下「名下用户」指**归属客户**。

```typescript
// commission_rules 表（扩展设计，当前实现为 agents.commission_rate 单值）
export const commissionRules = pgTable("commission_rules", {
  id: serial("id").primaryKey(),
  agentId: integer("agent_id").notNull().references(() => agents.id),

  // 佣金率范围——用于计算该代理归属客户的消费佣金
  rate: numeric("rate", { precision: 5, scale: 4 }).notNull(),   // 如 0.1000 表示 10%

  // 可指定模型级费率（空=使用全局费率）
  modelId: integer("model_id").references(() => models.id),

  // 可指定特定用户费率（空=所有归属客户适用）
  targetUserId: integer("target_user_id").references(() => users.id),

  // 生效范围
  effectiveStart: timestamp("effective_start").notNull().defaultNow(),
  effectiveEnd: timestamp("effective_end"),  // null=永久生效

  // 优先级（数值越小优先级越高，0 为最高）
  priority: integer("priority").default(100),

  createdAt: timestamp("created_at").defaultNow(),
  updatedAt: timestamp("updated_at").defaultNow(),
});

// 规则匹配优先级：
// 1. 同时指定了 modelId + targetUserId → 最高
// 2. 仅指定 modelId
// 3. 仅指定 targetUserId
// 4. 全局规则（modelId=null, targetUserId=null）
// 同优先级下，priority 数值小的优先
```

## 二、佣金计算精确公式

### 2.1 基本公式（单级 · 按消费时刻归属解析）

```
单笔佣金 = 该笔用户消费金额 × 佣金率

其中：
  用户消费金额 = consumption_records.cost（已 settled 的记录）
  佣金率 = 该代理当前 commission_rate（% 存储，×1/100）
  归属代理 = 消费时刻的归属解析：
    SELECT agent_user_id FROM agent_customer_bindings
    WHERE customer_user_id = $1 AND status = 'active'
      AND bound_at <= $2            -- $2 = 消费发生时刻
      AND (unbound_at IS NULL OR unbound_at > $2)
    LIMIT 1;
  未命中归属 → 该笔消费不计佣金

示例：
  归属客户消费 ¥10.00
  佣金率 10%
  佣金 = ¥10.00 × 0.10 = ¥1.00
```

### 2.2 多级佣金公式（已废弃 — D1）

> **⚠️ 已废弃**：代理商体系单级化（后台主导版 D1），**无下级代理、无多级抽成**。以下公式保留仅供追溯，**不实现**。

```
（原多级抽成公式已废弃，不实现）

┌─ 佣金（单级） ────────────────────────────────┐
│  公式：佣金 = 归属客户消费 × 该代理自身佣金率      │
│  示例：用户消费 ¥100，代理佣金率 10%              │
│       佣金 = ¥100 × 0.10 = ¥10.00              │
│  无上级抽成、无团队分润                          │
└────────────────────────────────────────────────┘
```

### 2.3 阶梯佣金

```
高级代理（advanced）可根据月调用量使用阶梯费率：

月调用量范围          佣金率
0 ~ 100 万 Token     10%
100万 ~ 500万 Token  13%
500万 ~ 1000万 Token 15%
1000万+ Token        18%

阶梯以"自然月"为周期，每月 1 日重新计算
计算依据：该代理**归属客户**上月实际消费 Token 总量
```

### 2.4 佣金精度规则

```
- 每笔佣金保留 4 位小数（numeric(14,4)）
- 每月佣金汇总保留 2 位小数展示
- 舍入方式：四舍五入
- 每月结算时，精度偏差 ≤ ¥0.01 自动核销
```

## 三、佣金计算触发时机

| 时机 | 触发方式 | 计算范围 | 说明 |
|------|---------|---------|------|
| 实时（消费发生时）| billing_logs settled 后触发 | 只计算该笔 | 实时更新佣金汇总缓存 |
| 日终（每日 01:00）| cron 计算前一日 | 前一日所有 settled/reconciled 记录 | 生成日佣金明细 |
| 月终/月初（每月 1 日 02:00）| cron 计算全月 | 上月所有记录 | 生成月佣金汇总 + 阶梯费率切换 |
| 手动重算 | 后台操作（运营触发）| 指定时间范围 | 费率变更或数据修复后触发 |

### 3.1 日终计算

```sql
-- 每日 01:00 执行
-- 计算前一日所有消费的佣金
INSERT INTO agent_commissions (agent_id, user_id, billing_log_id, amount, rate, period_date, status)
SELECT 
  a.id AS agent_id,
  b.user_id,
  b.id AS billing_log_id,
  b.actual_cost * cr.rate AS amount,
  cr.rate,
  b.created_at::date AS period_date,
  'pending'
FROM billing_logs b
JOIN agent_user_relations aur ON aur.user_id = b.user_id AND aur.active = true
JOIN agents a ON a.id = aur.agent_id
JOIN commission_rules cr ON cr.agent_id = a.id
  AND (cr.model_id IS NULL OR cr.model_id = b.model_id)
  AND (cr.target_user_id IS NULL OR cr.target_user_id = b.user_id)
  AND cr.effective_start <= b.created_at
  AND (cr.effective_end IS NULL OR cr.effective_end > b.created_at)
WHERE b.created_at::date = CURRENT_DATE - 1
  AND b.status IN ('settled', 'reconciled')
  AND NOT EXISTS (
    SELECT 1 FROM agent_commissions ac 
    WHERE ac.billing_log_id = b.id AND ac.agent_id = a.id
  );

-- 多级佣金计算在日终佣金生成后补充执行
-- 即：先计算直系佣金，再根据代理树计算多级佣金
```

## 四、多期结算快照策略

### 4.1 快照时机

| 快照类型 | 触发时机 | 内容 |
|---------|---------|------|
| 日快照 | 每日 02:00 | 当日佣金汇总（代理维度）|
| 月快照 | 每月 1 日 02:00 | 当月佣金汇总 + 阶梯费率截图 |
| 快照版本 | 费率变更时 | 变更前的佣金规则快照 |

### 4.2 快照表结构

```typescript
// 佣金结算快照表
export const commissionSnapshots = pgTable("commission_snapshots", {
  id: serial("id").primaryKey(),
  agentId: integer("agent_id").notNull().references(() => agents.id),
  period: varchar("period", { length: 7 }).notNull(),  // YYYY-MM-DD 或 YYYY-MM
  
  // 汇总
  totalCommission: numeric("total_commission", { precision: 14, scale: 2 }).notNull(),
  totalConsumption: numeric("total_consumption", { precision: 14, scale: 2 }).notNull(),
  totalOrders: integer("total_orders").notNull(),
  
  // 快照时的费率（JSON 快照，防止费率变更后追溯）
  snapshotRate: jsonb("snapshot_rate"),  // [{model_id: null, rate: 0.10}, ...]
  
  // 快照类型
  snapshotType: varchar("snapshot_type", { length: 10 }).notNull(), // daily / monthly
  
  // 状态
  settled: boolean("settled").default(false),      // 是否已结算
  settledAt: timestamp("settled_at"),
  
  createdAt: timestamp("created_at").defaultNow(),
});

// 索引
// - idx_agent_period: (agent_id, period)
// - idx_settled: (settled) WHERE settled = false
```

### 4.3 结算周期

```
默认结算周期：月结（自然月）

结算时间：次月 5 日（与财务月结一致）
提现窗口：每月 1-5 日为提现申请窗口
结算锁定：每月 5 日后该月佣金不可调整
特殊情况：高级代理可申请周结（需 super_admin 审批）
```

## 五、提现并发保护

### 5.1 提现基本规则

| 条件 | 规则 |
|------|------|
| 最低提现金额 | ¥100 |
| 最高提现金额 | 可用佣金余额 |
| 提现频率 | 单一代理每月最多提现 2 次 |
| 审核流程 | 二级审核（初审 + 二审）|
| 到账时间 | 审核通过后 T+1 工作日 |

### 5.2 提现状态机

```
withdraw_requested（提现申请提交）
  │
  ▼
pending_first_review（待初审）
  │
  ├──(初审通过)──→ pending_second_review（待二审）
  │       │
  │       ├──(二审通过)──→ pending_payment（待打款）
  │       │       │
  │       │       ├──(打款成功)──→ paid（已打款）✅
  │       │       └──(打款失败)──→ payment_failed（打款失败）
  │       │               └──(重试或人工处理)──→ paid
  │       └──(二审驳回)──→ rejected（驳回）✅
  │
  └──(初审驳回)──→ rejected（驳回）✅

注：可配置 withdraw_second_review_role 决定二审角色
（agent_mgr 或 operator）
```

### 5.3 并发提现保护

```sql
-- 核心问题：同一代理发起两笔提现，总额超过可用佣金
-- 解决方案：提现申请时锁定佣金余额

-- 提现申请 SQL：
BEGIN;

-- 1. 锁定代理佣金账户（行级锁）
SELECT available_commission FROM agents WHERE id = $agent_id FOR UPDATE;

-- 2. 检查是否有已提交但未完成的提现
SELECT COALESCE(SUM(amount), 0) AS pending_amount
FROM withdraw_orders
WHERE agent_id = $agent_id 
  AND status IN ('withdraw_requested', 'pending_first_review', 
                 'pending_second_review', 'pending_payment');

-- 3. 计算可用余额
available = available_commission - pending_amount - this_withdraw_amount;

-- 4. 如果 available >= 0 → 提交提现
--    如果 available < 0  → 拒绝（超过可用余额）

COMMIT;

-- 提现完成后的余额清理
-- 打款成功后：UPDATE agents SET available_commission = available_commission - amount WHERE id = $agent_id
```

### 5.4 提现审核角色配置

```
通过 site_configs.withdraw_second_review_role 配置：

配置值         角色              说明
agent_mgr      代理管理岗        默认值
operator       运营岗            可选
```

### 5.5 提现失败处理

| 场景 | 处理方式 |
|------|---------|
| 银行信息错误 | 退回审核，要求代理商修改银行卡信息后重新提交 |
| 银行系统故障 | 自动重试（最多 3 次），失败后转入人工线下打款 |
| 代理等级变更（提现中）| 已提交的提现按原等级处理，不受影响 |
| 代理被冻结/禁用 | 提现退回，不可继续处理 |

## 六、佣金异常处理矩阵

| # | 场景 | 检测时机 | 自动处理 | 告警级别 |
|---|------|---------|---------|---------|
| C-001 | 佣金率配置为空（无匹配规则）| 日终计算时 | 该笔佣金为 0，标记日志 | WARN（邮件通知代理管理员）|
| C-002 | 佣金率超出最大限制（> 30%）| 费率配置时 | 拒绝保存，提示超限 | 无（前台校验）|
| C-003 | 下游消费金额异常大（单笔 ¥10,000+）| 实时/日终 | 正常计算佣金，标记该笔为 high_value | 无 |
| C-004 | 代理名下消费突然剧增（环比 > 300%）| 日终对比 | 正常计算，标记异常波动 | WARN（通知代理管理）|
| C-005 | 费率变更追溯冲突 | 费率配置时 | 新费率只影响变更后的消费，不影响历史 | 无 |
| C-006 | ~~多级佣金汇总超过总费率上限~~ | ~~计算时~~ | **已废弃（D1：单级佣金，无多级汇总）**；单级佣金率超上限时拒绝配置（C-002） | — |
| C-007 | 已结算佣金需要修正 | 运营操作 | 通过补发/回收流程处理（不直接修改已结算数据）| 需审核 |
