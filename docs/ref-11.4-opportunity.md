## 概述

企业客户通常需要定制价格方案。业务员当前没有标准化商机管理工具——商机靠微信群聊跟踪，报价靠微信发文字，老板拍脑袋批价格，流程不透明。

**核心价值**：商机全生命周期可视化，报价审批透明化，成交概率可预测。

### 3. 阶段推进

| 阶段 | 描述 | 预计停留 |
|------|------|---------|
| discovery（发现）| 潜在客户识别 | ≤ 7 天 |
| qualification（需求确认）| 明确客户需求和预算 | ≤ 14 天 |
| solution（方案）| 提供技术方案和初步报价 | ≤ 14 天 |
| quotation（报价）| 正式报价单 + 审批 | ≤ 7 天 |
| negotiation（谈判）| 价格和条款谈判 | ≤ 14 天 |
| won（成交）| 签约 + 充值 | — |
| lost（丢单）| 记录丢单原因 | — |

每个阶段停留超过建议天数 → 自动提醒业务员推进。

### 4. 丢单分析

丢单时必填原因：

| 丢单原因 | 说明 |
|---------|------|
| 价格太高 | 竞争对手价格更优 |
| 功能不满足 | 缺少客户需要的模型或功能 |
| 客户没有预算 | 预算不足或预算被砍 |
| 联系不上 | 无法建立进一步联系 |
| 选择了竞品 | 客户选择了其他平台 |
| 其他 | 手动填写 |

丢单原因报表 → 管理员可汇总分析："哪个原因占比最高"。

## API 接口

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| `POST` | `/api/v1/agent/opportunities` | 创建商机 | 业务员 |
| `GET` | `/api/v1/agent/opportunities` | 商机列表（看板/列表视图） | 业务员 |
| `GET` | `/api/v1/agent/opportunities/:id` | 商机详情 | 业务员 |
| `PATCH` | `/api/v1/agent/opportunities/:id` | 更新商机 | 业务员 |
| `POST` | `/api/v1/agent/opportunities/:id/advance` | 推进阶段 | 业务员 |
| `POST` | `/api/v1/agent/opportunities/:id/won` | 标记成交 | 业务员 |
| `POST` | `/api/v1/agent/opportunities/:id/lost` | 标记丢单（含原因） | 业务员 |
| `GET` | `/api/v1/agent/opportunities/stages` | 阶段定义及停留建议 | 业务员 |
| `GET` | `/api/v1/admin/opportunities/lost-reasons?startDate=&endDate=` | 丢单原因分析 | 管理员 |

## 边界条件

| 场景 | 处理方式 |
|------|---------|
| 商机推进阶段跳级 | 允许跳级（如方案→谈判），记录跳级日志 |
| 已丢单商机重新激活 | 允许从 lost → discovery 重新激活 |
| 成交后创建合同 | 自动跳转到报价单/合同管理页 |
| 阶段停留超时 | 在商机卡片上标注 ⏰ 停留超时标记 |
| 商机关联客户后客户注销 | 保留商机记录，客户部分标记为"已注销" |
