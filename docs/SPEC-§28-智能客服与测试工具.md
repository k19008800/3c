## 28.1 智能客服辅助

### 功能描述

在客服工作台和聊天窗口中嵌入智能辅助功能，帮助客服更快定位问题、推荐最佳回复方案。

### 28.1.1 用户意图识别

当用户输入问题时，系统根据关键词和语义自动识别意图并推荐知识库文章。

**聊天窗口中的智能推荐：**

```
用户: "我充值了 100 块钱，但余额没有增加"

系统自动识别: 意图=充值未到账 (confidence: 92%)
推荐:
  📌 知识库: "充值未到账排查步骤"
  📌 快捷回复模板: "充值确认流程"
  📌 相关操作: [查看该用户充值记录]

客服点击 "查看该用户充值记录" →
  自动打开用户信息面板，定位到充值记录标签页
```

**意图分类清单：**

| 用户输入特征 | 识别意图 | 推荐动作 |
|------------|---------|---------|
| "充值/付款后没到账/余额没变" | 充值未到账 | 查看充值记录+推荐排查步骤 |
| "调用/接口返回 401/403" | API 鉴权失败 | 查看 Key 状态+推荐 Key 配置指南 |
| "余额不足/不够用" | 余额查看 | 显示当前余额+充值入口 |
| "发票/开票" | 发票问题 | 推荐发票申请流程+查看历史发票 |
| "Key 被禁/不能用了" | Key 状态异常 | 查看 Key 状态和操作日志 |
| "速度慢/延迟高" | 性能问题 | 查看最近调用延迟统计 |
| "退款/退钱" | 退款申请 | 推荐退款政策+创建退款工单 |

### 28.1.2 常见问题自动回复

当用户提问命中高置信度（>95%）的知识库文章时，系统可自动回复或建议客服直接引用。

```
系统检测到用户问题与知识库文章"如何创建 API Key"匹配度 97%
→ 在客服输入框上方显示:
  "💡 推荐回复: [引用知识库文章 — 如何创建 API Key]"

客服点击 → 自动填入回复内容:
  "您好，创建 API Key 的步骤如下：
  1. 登录 3Cloud 控制台
  2. 点击左侧菜单"API Keys"
  3. 点击右上角"创建 Key"
  4. 输入 Key 名称，点击确认即可"
```

### 28.1.3 异常自动诊断

用户投诉调用失败时，系统自动展示该用户最近调用记录和错误分析。

```
用户: "我的 API 一直报错"

客服界面自动展示（无需手动查询）:
┌──────────────────────────────────────────────┐
│  🔍 自动诊断结果                               │
│                                                │
│  用户: 张三 (user.id=42)                       │

│  14:23:45  deepseek-chat  [失败] 429 限流      │
│  14:23:42  deepseek-chat  [失败] 429 限流      │
│  14:23:40  deepseek-chat  [失败] 429 限流      │
│  14:23:35  deepseek-chat  [失败] 429 限流      │
│                                                │
│  🔎 分析: 用户触发了频率限制（RPM 超限）         │
│  该用户当前套餐: 标准版 (RPM: 60)               │
```

**诊断触发时机：**

```
├── 客服打开新工单时自动触发
├── 聊天窗口中用户提到"失败/报错/不能用"时自动触发
└── 客服手动点击"诊断"按钮触发
```

**诊断数据范围：**

```
├── 最近 20 条调用记录（成功/失败/耗时）
├── 当前余额和配额状态
├── 最近的 ERROR 级别错误日志
├── API Key 状态列表（活跃/禁用）
└── 账号安全事件（异地登录/密码修改等）
```

### 28.1.4 余额不足主动预警

用户在聊天或工单中咨询时，客服界面自动标注用户的余额状态。

```
聊天窗口 → 用户信息面板 → 顶部显示:

  ⚠️ 用户余额: ¥3.50（低于 ¥10 阈值）
  按当前日消费速度，预计 1 天后余额耗尽
  [快速充值引导] [赠送小额体验额度]
```

### 技术实现

```typescript
// 意图识别：基于关键词规则匹配（初期）或调用 NLP API（后期）
// 不需要训练模型，使用简单的关键词匹配+分类树即可覆盖 80% 场景

interface IntentMatchResult {
  intent: string
  confidence: number
  suggestedActions: SuggestedAction[]
  matchedKeywords: string[]

interface SuggestedAction {
  type: 'knowledge_article' | 'quick_reply' | 'api_query'
  label: string
  action: string  // 如 jump_to_page / fill_reply / execute_query
  params?: Record<string, any>

// 配置在 site_configs 中，运营可编辑关键词和映射
```

```
GET /api/v1/admin/support/assist/diagnose/:userId   — 自动诊断
```

## 28.2 客服测试工具

### 功能描述

提供客服辅助排查的测试工具集合：模拟用户调用、查看用户视角、生成临时测试 Key。

### 28.2.1 模拟用户调用

客服以指定用户的身份测试 API 调用，验证用户遇到的问题是否能复现。

**使用流程：**

```
客服在用户详情页 → [工具] → [模拟调用]

  模拟调用
  用户: 张三 (ID: 42)
  模拟 Key: [使用用户 Key ▼]  或者 [使用临时测试 Key]

  模型: [deepseek-chat ▼]
  Prompt: "你好，请介绍一下自己"

  [发送测试请求]
  ─────────────────────────────────
  响应状态: 200 OK
  请求耗时: 1.2s
  输入 Token: 45 | 输出 Token: 128
  费用: ¥0.00009

  用户最近调用（同模型）平均耗时: 1.5s
  结论: 该用户的 API 调用正常，无明显异常
```

**权限控制：**

```
├── 仅客服主管及以上权限可用
├── 所有模拟调用记录到操作日志（含客服ID、用户ID、调用时间）
├── 模拟调用不计入用户实际消费
└── 模拟调用消耗由平台承担（记录到内部费用）
```

### 28.2.2 查看用户视角

客服查看"用户看到的页面是什么样子"，帮助理解用户遇到的 UI/UX 问题。

**使用流程：**

```
客服在用户详情页 → [工具] → [查看用户视角]

  进入用户视角 →
  ├── 客服界面切换到该用户的控制台页面
  ├── 展示的页面和数据完全以该用户身份展示
  ├── 页面顶部显示黄色提示条:
      "🔍 您正在查看用户 张三 的视角 — [退出用户视角]"
  ├── 客服可导航到该用户能看到的任何页面
  ├── 不能执行写操作（创建Key/充值等）—— 只读模式
  └── 退出后回到客服工作台
```

**权限控制：**

```
├── 仅客服主管及以上权限可用
├── 用户视角期间所有页面切换记录到日志
├── 超过 10 分钟无操作自动退出
└── 同时只能查看一个用户的视角
```

### 28.2.3 临时测试 Key

客服生成临时测试 Key 用于排查用户反馈的问题，无需使用用户的真实 Key。

```
客服点击 [生成临时测试 Key] →
  ├── Key 名称: "临时测试-客服张三-20260728"
  ├── 有效期: 24 小时（自动过期）
  ├── 关联用户: 无（不消耗任何用户的余额）
  ├── 额度限制: 总 Token 上限 100 万，总费用上限 ¥5
  └── 可用模型: deepseek-chat / qwen-plus（仅限低成本模型）

生成的 Key:
  ┌──────────────────────────────────────┐
  │  临时测试 Key:                         │
  │  sk-test-xxxxxxxxxxxxxxxxxxxxxxx       │
  │                                        │
  │  有效期至: 2026-07-29 14:00             │
  │  剩余额度: 100 万 Token / ¥5.00         │
  │                                        │
  │  [复制 Key]  [复制 cURL 示例]          │
  └──────────────────────────────────────┘
```

### API 接口

```
POST /api/v1/admin/support/test-key               — 生成临时测试 Key
GET  /api/v1/admin/support/test-keys               — 测试 Key 列表
POST /api/v1/admin/support/test-key/:id/revoke     — 撤销测试 Key

POST /api/v1/admin/support/simulate-call           — 模拟用户调用
  请求体: { userId, model, messages, useUserKey?: boolean }
  响应: { status, response, latency, tokenUsage }

POST /api/v1/admin/support/user-perspective/enter  — 进入用户视角
POST /api/v1/admin/support/user-perspective/exit   — 退出用户视角
```

### 验收标准

1. 客服生成临时测试 Key → 可用该 Key 调用 API → 24 小时后自动过期
2. 客服模拟用户调用 → 看到和该用户一样的调用结果
3. 客服进入用户视角 → 看到用户看到的页面（只读）
4. 模拟调用和测试 Key 的消耗都不计入用户账单
5. 所有测试操作记录到审计日志

- AI 意图识别置信度低于 0.6 时不触发自动回复，标记"需人工处理"
- 测试工具使用独立测试数据库，测试数据带 `is_test_data` 标记，防止污染生产
- 临时测试 Key 默认 24h 过期、100 次调用配额，泄漏可立即吊销
- AI 引用过期知识时会标注"该信息可能已过时"
- 测试任务最大并发 10 个，单用户最多同时运行 3 个
- AI 回复触发内容安全审查时替换为"正在审核中"提示

**常见问题**：
Q: 为什么 AI 没有自动回复？
A: 当 AI 对用户输入意图识别置信度低于阈值时，系统不会自动回复，会转入人工客服处理。

Q: 测试 Key 能用于生产环境吗？
A: 不能。测试 Key 仅限测试环境，有独立数据库和严格配额，24 小时自动过期。

Q: AI 推荐的知识答案可靠吗？
A: AI 回复会附带引用来源和最后更新时间，过期内容会明确标注。

## 边界条件

### 模块概述

智能客服与测试工具模块涵盖智能客服辅助（AI 意图识别、知识库检索、自动回复建议）和客服测试工具（模拟用户会话、测试 Key 管理、测试报告）。当前为草案状态。

### 边界条件清单

| # | 场景 | 触发条件 | 预期行为 | 影响范围 | 优先级 |
|---|------|---------|---------|---------|--------|
| AI-001 | AI 意图识别准确率低时降级 | AI 模型对用户输入意图识别的置信度低于阈值（默认 0.6） | 不触发自动回复，标记为"需人工处理"，将用户的输入直接分配给人工客服，并附带模型认为可能的多意图候选 | 智能客服 | P0 |
| AI-002 | 测试工具模拟数据导致真实数据污染 | 测试工具生成的模拟数据意外写入生产环境 | 测试工具使用独立的测试数据库/Redis 实例，配置独立的 API Key；测试数据写入前严格校验 `env=test` 标记；数据模型中增加 `is_test_data` 标记 | 测试工具 | P0 |
| AI-003 | 临时测试 Key 泄漏风险 | 测试用的临时 API Key 被滥用或泄漏 | 测试 Key 设置较短的有效期（默认 24h 自动过期）、较低的配额（如 100 次调用）和受限权限范围；泄漏后可通过管理后台立即吊销 | 测试 Key | P0 |
| AI-004 | AI 知识库内容过期 | 自动回复引用的知识库内容已过时或不准确 | 知识库内容自动标记版本和有效期；AI 在回复时附带引用来源和"最后更新时间"；过期内容在回复中标记"该信息可能已过时" | AI 回复 | P1 |
| AI-005 | 测试任务并发限制 | 大量测试任务同时运行导致系统资源耗尽 | 测试任务设置最大并发数（默认 10 个）；超出限制的任务排队等待，前端显示排队状态；单用户最大同时运行 3 个测试 | 测试工具 | P1 |
| AI-006 | AI 回复内容安全审查 | AI 生成的回复内容触发了内容安全规则 | 安全审查拦截的回复不发送给用户，替换为"该回复正在审核中，稍后将由人工客服跟进"；触发审查的记录进入安全审核队列 | AI 回复 | P1 |
| AI-007 | 测试报告生成失败 | 测试工具生成测试报告时数据源不可用 | 使用已采集的局部数据生成部分报告；失败的指标标记为"数据不可用"；提供重新生成按钮 | 测试报告 | P2 |
| AI-008 | 智能客服多轮上下文丢失 | 用户在多轮对话中切换话题，AI 的上文理解丢失 | 每轮对话携带完整的上下文摘要（前 5 轮摘要）；超过 10 轮的对话自动裁剪最旧的轮次；对话超时（30 分钟无消息）自动结束 | 智能客服对话 | P1 |

### 详细边界说明

#### AI-001: 意图识别置信度降级

**处理逻辑**:
```
用户输入 → AI 意图识别
  → 置信度 >= 0.8 → 自动回复（附带引用来源）
  → 置信度 >= 0.6 且 < 0.8 → 显示候选回复供客服选择（不自动发送）
  → 置信度 < 0.6 → 直接转人工，附带原始输入和多意图候选列表
```
- 置信度阈值可在后台按业务场景调整
- 每季度评估一次准确率，调整默认阈值

#### AI-002: 测试数据污染防护

**多层防护**:
1. 环境隔离：测试工具连接独立数据库（`_test` 后缀）
2. 配置校验：所有写操作校验 `APP_ENV !== 'production'`
3. 数据标记：测试数据携带 `test_session_id` 元数据
4. 定期清理：测试环境数据每天凌晨自动清理
5. 监控告警：检测到生产环境写入带有测试标记的数据立即告警
