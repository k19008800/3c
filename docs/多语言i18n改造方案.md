## 一、现状核对（事实）

### 1.1 门户 Portal（`web-portal`）— ❌ 仅 2 语言
- `src/lib/i18n.ts`：`PORTAL_LANGS = ["zh-CN","en"]`；`normalizeLang()` 只接受 `en`，其余回落 `zh-CN`。
- 语言由 cookie `3cloud_portal_lang` + `?lang=` 查询参数决定；词典走 `GET /api/v1/public/i18n/entries?lang=xx`（no-store），缺 key 回退内置 `EN_DEFAULTS`（**仅英文**）。
- 首页/定价/博客/导航/页脚已 key 化；**ja/ko/vi/th/id/fil 无任何条目**。

### 1.2 用户后台 Console（`web-console`）— ❌ 完全没有国际化
- 172 个文件含中文，约 6.4 万中文字符；文案/按钮/菜单/错误提示/`toLocaleString("zh-CN")` 全部硬编码中文。
- 覆盖三类角色：**个人用户（`/`、`/agent/*`）、企业渠道（`/vendor/*`、`/agent/*`）、管理后台（`/admin/*`，约 150+ 路由）**。
- 无语言切换器、无 i18n 字典、无语言持久化字段。
- 唯一例外 `AdminI18nPage.tsx`：`LANGS` 预设 **4 语言**（zh-CN/en/ja-JP/ko-KR，第 45-50 行）+ 覆盖率面板——但仅管理数据，**无 8 语言消费端、界面本身亦硬编码中文**。

### 1.3 后端 API（`api`）— ✅ 基础设施已具备承载能力，但需补 8 语言与 scope 数据
- `i18n_entries`：`key×lang×value×scope×status`，`lang varchar(10)` 自由、`scope` 预设 `portal/console/admin/common/error/email/notification`（7 scope，见 `admin-i18n.ts` `SUPPORTED_SCOPES`）。天然支持任意语言。
- 管理端 `/admin/i18n/entries` CRUD + import + 审计已实现；公开端 `/public/i18n/entries` 已实现。
- **缺口**：seed 仅 114 key × zh/en（`src/db/seed.ts`）；`lang` 无白名单（脏语言风险）；`users` 表无 `language` 字段；JSON 错误/邮件/通知为硬编码中文，无 `t()` 基础设施。

### 1.4 现状与要求差距表

| 维度 | 项目要求 | 现状 | 差距 |
|------|---------|------|------|
| 门户 Portal | 多语言 | 2 种（zh/en） | ❌ 缺 6 种 |
| 用户后台 个人 | 多语言 | 硬编码中文 | ❌ 未实现 |
| 企业后台 Vendor | 多语言 | 硬编码中文 | ❌ 未实现 |
| 管理后台 Admin | 多语言 | 硬编码中文 | ❌ 未实现 |
| 后端承载 | 多语言 | 表结构支持、seed 仅 zh/en/portal | ⚠️ 缺 8 语言+console 数据 |

## 二、推荐技术方案

核心理念：**沿用现有 `i18n_entries` 契约 + 8 语言预设，让翻译"一次录入、八端/四端消费"，后端集中语言白名单，前端轻量接入，不引入重型框架。**

### 2.1 统一语言模型（关键约定）

- **唯一语言标识（8 种）**：
  `zh-CN / en / ja-JP / ko-KR / vi / th / id / fil`（管理页映射 `zh_cn→zh-CN`、`en_us→en`… 由集中白名单归一化）。
- **同一套 key、按 scope 划分**，复用后端行式存储：

| scope | 消费端 | 说明 |
|-------|--------|------|
| `portal` | 门户 | 已存在，扩至 8 语言 |
| `console` | 个人 User + 企业 Vendor | 新建复用（登录/导航/设置/账单/密钥/统计等） |
| `admin` | 管理后台 | 全部运维/审核/配置页（二期完整、首期保底处置路径英文） |
| `common` | 全端共用 | 通用按钮/日期/货币/状态/错误 |
| `error` | 动态（后端错误） | 参数化 message key |
| `email` | 动态（邮件） | 模板取词 |
| `notification` | 动态（通知） | 站内+邮件 |

> **动静约定**：`error/email/notification` 为**动态 scope**，前端默认不随页面全量拉取，仅显式请求或后端消费；`portal/console/admin/common` 为**静态 scope**，随页面加载。

### 2.2 前端接入方案

**门户（Portal，仅需扩展）**：
- `PORTAL_LANGS` 扩为 8；`normalizeLang` 放开 7 种非 zh-CN；`siteAlternates()` 的 hreflang `languages` **动态生成 8 语言**。
- ⚠️ **连带项（评审要点）**：放开 `normalizeLang` 前必须先补 7 种语言 seed/词典，否则整页退英文（Gate，见 §2.4）。

**控制台（Console，改造重点）** — 新增对等轻量层：
- 新建 `web-console/src/lib/i18n.ts` + `fmt.ts`：
  - `CONSOLE_LANGS = ["zh-CN","en","ja-JP","ko-KR","vi","th","id","fil"]`，默认 `zh-CN`。
  - `makeT(dict)` 翻译函数；**英文源语字典按各 scope 自建**（`EN_DEFAULTS` 不再只存在于 portal）——建议源语由后端统一维护（en scope 录入完毕=源语完备），前端缺 key 回退英文词表或 key 原文。
  - `fmtNumber/fmtMoney/fmtDate/curLocale`（见 §2.5 格式化本地化）。
- **App 壳层语言 Provider**（评审要点 A）：Console 是"个人+企业+管理"三合一 SPA（`basename=/app`），**登录页/注册页不在 `ConsoleLayout` 内**。语言上下文必须在**应用壳层**提供，覆盖登录前后全部页面。
- **切换器位置**：个人/企业顶栏 + 门户顶栏/页脚双入口；管理后台切换器单独拍板（二期默认跟随后端 preference）。
- **语言持久化优先级（评审要点 B，防闪现抖动）**：
  1. `?lang=`（直达链接，最高）
  2. `localStorage`（登录前立即同步渲染）
  3. 登录后异步 `/me/settings` 的 `language`（服务端覆盖，回写 localStorage）
  4. `navigator.language` 归一化
  5. 默认 `zh-CN`
- cookie 名建议 `3cloud_console_lang`（与门户 `3cloud_portal_lang` 区分，域名隔离）。

### 2.3 后端与数据改造（含评审关键修正）

1. **后端语言白名单集中校验（前置 Gate-1，评审要点 1.2③）**：新建 `api/src/lib/i18n-langs.ts`：
   ```ts
   export const I18N_LANGS = ['zh-CN','en','ja-JP','ko-KR','vi','th','id','fil'] as const;
   export type I18nLang = (typeof I18N_LANGS)[number];
   export function normalizeI18nLang(v?: string|null): I18nLang | null;
   ```
   用于 `public.ts`(读)、`admin-i18n.ts`(写/import)、`/me/settings`(写) 三处——**杜绝脏语言**（`zh-CN`/`zh_cn`/`en_us` 分裂唯一键、覆盖率失真）。
2. **`/public/i18n/entries` 增加 scope 参数**（向后兼容）：
   ```http
   GET /api/v1/public/i18n/entries?lang=ja-JP&scope=console&scope=common
   ```
   多值 scope，缺省 `portal`；`error/email/notification` 默认排除（防 payload 膨胀）；响应含 `lang/scope` 元数据；**不推荐 no-store** → HTTP 缓存 `public,max-age=300` + 前端模块级缓存（可选 Redis）。
3. **用户语言偏好落库**：`users` 表新增 `language varchar(10) NOT NULL DEFAULT 'zh-CN'`（≤1 条幂等 migration，cost 低；不推荐 jsonb 过度设计）。
   - 契约：`GET /api/v1/me` 增加 `language`；新增 `GET/PUT /api/v1/me/settings`（body `{language}`），值域过白名单非法 400。
   - **按账号维度独立**：个人与每个企业子账号各自存储 `users.language`，不按企业共享。
4. **动态消息 key 化（新建后端 `t()` 基础设施）**：
   - `api/src/services/i18n/index.ts`：`t({ key, params, lang })` → 查 `(scope,key,lang)`，缺查 `en`，再缺返 key 原文——与前端 `makeT` 语义对称。
   - 参数占位建议**单花括号命名参数 `{name}`**（与前端模板引擎一致）。
   - 关键接入点：`lib/errors.ts`（错误 key 化入口）、邮件服务、通知服务；错误响应可返回 `{ key, params }` 由前端本地渲染（SYS-007 落地）。
   - **一条 key 前后端同源**（共用 `i18n_entries`、同一 key），杜绝双份词表漂移。
5. **seed 扩充**：现有 portal 114 key × zh/en 补 7 语言；为 console/admin/common 新建关键 key；`AdminI18nPage.LANGS` 扩为 8 语言 + 覆盖率。

### 2.4 实施顺序（Gate 把关，评审要点 2.4）

| 阶段 | 内容 | Gate / 验收 |
|------|------|-------------|
| **Gate-0（基建前置）** | fmt.ts 骨架 + App 壳层语言 Provider + `/me/settings` 契约 + 后端集中 `normalizeI18nLang` 白名单 | 白名单进 public/admin；`fmt.*` 就位 |
| **Gate-1（数据前置）** | 后端 scope 参数扩展 `/public/i18n/entries`；补 8 语言 seed（or 至少 zh/en/ja/ko 首批 + 其余随推进） | 杜绝脏语言；接口可多 scope 拉取 |
| **P1 控制台骨架** | 控制台 i18n 层 + 切换器 + scope 合并拉取 + users.language | 4 端入口可切语言、登录前后覆盖、防抖 |
| **P2 关键页 key 化（个人+企业）** | 登录/注册/导航/仪表盘/API Key/账单/充值/统计/设置等 | 关键页 100%、全 console scope ≥90% |
| **P3 门户扩充** | `PORTAL_LANGS`→8 + 补 7 语言词典/seed + siteAlternates 动态 hreflang | ⚠️ Gate：seed 补成后再放开 normalizeLang |
| **P4 管理后台 key 化** | `/admin/*` 高频页 | 二期完整；首期保底处置路径英文 |
| **P5 动态消息+邮件/通知** | 后端 `t()` + `lib/errors.ts` + email/通知（拆 P5a 关键链路 / P5b 全量） | 参数化错误本地化、对外邮件定向语言 |
| **P6 翻译资产+覆盖率** | seed 补全 + AdminI18nPage 8 语言覆盖率治理 | 覆盖率 ≥90%（8 语言白名单内计） |

> **并行建议**：P2（console）与 P3（portal）分属两套前端，**可并行**，但都依赖 Gate-1。P4 复用 P2 的 console 层与 `fmt.*`，排 P2 之后。

### 2.5 格式化本地化（评审要点：独立大工程，勿漏）

- 实测 `web-console` **157+ 处 `toLocaleString("zh-CN")` 硬编码**（日期/货币/数字）。这是独立于文本 i18n 的工程。
- 封装 `web-console/src/lib/fmt.ts`：
  ```ts
  export const curLocale = (): string => getI18nLang() === 'en' ? 'en-US' : getI18nLang();
  export const fmtNumber = (n, opts?) => n.toLocaleString(curLocale(), opts);
  export const fmtMoney  = (n, currency='CNY') => new Intl.NumberFormat(curLocale(),{ style:'currency', currency }).format(n);
  export const fmtDate   = (d, opts?) => new Date(d).toLocaleString(curLocale(), opts);
  ```
- **仅显示层格式化**，本币结算口径不变、**不做汇率换算**；时区与语言解耦（语言只改语言，不改时区）。
- 模块级批量替换（只读、风险低），在 P2 内并行推进。

## 五、产品边界补充（评审要点）

- **动态内容策略**：
  - 表单校验错误（client+server）**全覆盖**（P1/P2 验收单列）。
  - 帮助文档/条款/隐私政策等**长文 → "文档级多语言"**（markdown 分语言文件 + lang 字段），非 key-value。
  - 工单/客服/UGC（企业名/模型名等）**不强制翻译**，原文呈现 + 可选提示。
  - 邮件：**对外交易/告警必翻**；运维告警/内部审计不翻。
- **权限与归属**：默认 `admin` 全量管理 8 语言；缺 key 由运营兜底（覆盖率 <90% 顶部横幅 + 可导出清单）；`status` 映射"草稿/已发布/已废弃"。
- **`AdminI18nPage` UI**：作为"管理工具"保持中文（运维常用中文），它≠翻译目标端，需显式声明。
- **合规边界**：本期**纯 UI 多语言**，不附带 GDPR/结算/税务等国际合规改造；法务文书语言效力按决策 B。

## 六、已确认决策（项目方拍板，输入本方案）

| # | 决策项 | 结论 |
|---|--------|------|
| 1 | 语言集合 | **8 种（zh-CN/en/ja-JP/ko-KR/vi/th/id/fil）**，对齐 PRD v1，不再降载 |
| 2 | 管理后台一期边界 | **首期不含完整 4 语→按 8 语相应延后；首期核心审批/审核处置路径保底英文** |
| 3 | 用户语言偏好 | **落库 `users.language`，按账号维度独立** |
| 4 | 验收门槛与切换交互 | **覆盖率≥90% + 关键页/关键路径 100% + 任一 scope 的 ja/ko 等非默认语言非 0 + 缺 key 回退英文 + 切换保持当前路由不丢会话**，门槛仅在 8 语言白名单内计 |

> **追加待澄清（评审提出，需项目方二次确认）**：
> - A. 登录前后语言一致性 + 切换保持路由/不丢会话 —— 已按"继承+停留路由"采纳。
> - B. 法务/合同文书"单一主版本为准 + 翻译版免责声明" —— 建议采纳，需与法务对齐后确认。
