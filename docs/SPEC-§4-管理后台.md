## 4.1 总览看板 `/admin`

> **📖 页面功能说明帮助**
>
> **页面用途**：后台首页，一眼看清平台整体运营状况 — 营收数据、用户增长、API 调用量、待办事项一目了然。
>
> **适用角色**：所有管理员（super_admin / admin / finance / ops / support 等全部角色）
>
> **核心操作**：
> - 查看 KPI 卡片：今日/本月营收、活跃用户数、调用量、平台余额等指标
> - 待办中心：点击各待办项跳转到对应处理页面
> - 趋势图表：按 7/30 天查看营收、调用量、用户增长趋势
> - 快速入口：从首页直接进入各功能模块
>
> **常见场景**：
> - 每天早上打开后台先看总览，了解平台运营状况
> - 查看待办事项了解今天需要处理哪些事务
> - 对比近 7 天营收趋势判断业务变化
>
> **注意事项**：KPI 数据缓存 5 分钟，非实时刷新
>
> **常见问题**：Q: 待办数字不更新？A: 刷新页面即可

### 完成能力 / 展示效果

**总览看板分为三部分：**

**顶部 KPI 卡片（每个卡片右上角[?]说明卡片含义和数据来源）：**
- 今日营收 / 本月营收 / 同比增长
- 活跃用户数 / 新注册用户数
- API 调用总量 / 成功率
- 平台余额 / 供应商可用率

**中间待办中心（§4.11 详细规格）：**
- 各模块待处理事项汇总，点击跳转对应页面
- 红色标记紧急待办，黄色标记常规待办

**底部趋势图表：**
- 近 7/30 天营收趋势（折线图）
- 近 7/30 天调用量趋势（柱状图）
- 用户增长趋势
- 各模型调用占比（饼图/环形图）

### 上下游关系

```
数据来源：
  operational_kpi API → KPI 卡片数据
  tickets + real_name_reviews + recharge_orders → 待办统计
  stats API → 趋势图表数据
```

## 4.2 用户管理 `/admin/users`

> **📖 页面功能说明帮助**
>
> **页面用途**：管理所有平台用户的账号信息、余额状态、API Key、调用记录和操作时间线。
>
> **适用角色**：客服（support）、运营（ops）、管理员（admin / super_admin）
>
> **核心操作**：
> - 用户搜索：支持 ID/邮箱/手机号模糊匹配，多条件组合筛选
> - 用户详情：点击用户行进入详情页，查看余额/Key 列表/调用日志/操作时间线
> - 批量操作：批量充值、通知、导出、启用/禁用
> - 用户状态管理：调整余额、实名审核、授权/冻结账号
>
> **常见场景**：
> - 客服接到用户咨询 → 搜索用户查看详情
> - 运营做活动 → 选中目标用户批量充值赠送
> - 安全发现异常账号 → 禁用用户并追溯操作记录
>
> **注意事项**：调整余额和禁用用户需二次确认，记入审计日志
>

### 功能描述

用户列表展示、批量操作、用户详情查询、用户状态管理。

### 完成能力 / 展示效果

**用户列表（含批量操作）：**

**批量操作弹窗（以批量充值为例）：**


- 最近 10 条调用日志
- 近 30 天消费趋势
- 操作时间线（登录/Key 变更/充值/设置变更）
- 关联工单

```
  批量导出 → POST /api/v1/admin/batch/export
```

>

>
> **适用角色**：运营（ops）、管理员（admin / super_admin）

> - 供应商管理：新增/编辑/停用，连通性测试

## 4.4 财务管理 `/admin/finance`

> **📖 页面功能说明帮助**
>
> **页面用途**：平台所有资金相关操作总入口 — 充值审核、佣金管理、提现审核、对账、发票、退款。
>
> **适用角色**：财务（finance）、管理员（admin / super_admin）
>
> **核心操作**：
> - 财务总览：今日/本月营收、充值提现汇总
> - 充值订单：审核、标记异常、补登、退款
> - 佣金管理：计算/审核/发放代理佣金
> - 提现审核：双审流程（财务初审 → 运营复审）
> - 对账：供应商结算对账 + 平台内部对账
> - 发票管理：审核和开票
>
> **常见场景**：
> - 用户反馈充值未到账 → 查订单 → 补登或退款
> - 月初结算佣金 → 计算 → 审核 → 发放
> - 月底与供应商对账 → 核对差异 → 确认
>
> **注意事项**：所有资金操作需双人复核，记入审计日志
>

### [?] 按钮级帮助对照表

| 按钮/入口 | 功能说明 |
|---|---|
| `审核通过[?]` | 确认充值订单有效，资金进入用户余额 |
| `标记异常[?]` | 充值回调异常时使用，需人工核实后补登 |
| `发起退款[?]` | 确认后退款金额退回用户余额或原路返回 |
| `审核提现[?]` | 确认提现申请后发起实际打款 |
| `结算佣金[?]` | 计算并发放代理佣金到代理账户余额 |
| `确认对账[?]` | 核对无误后标记该对账周期已完成 |

### 完成能力 / 展示效果

#### 4.4.1 财务总览 `/admin/finance/dashboard`

财务核心指标：今日/本月营收、充值总额、提现总额、平台余额、待结算佣金。

#### 4.4.2 充值订单 `/admin/recharge-orders`

充值订单列表，支持审核、标记异常、退款。

#### 4.4.3 佣金管理 `/admin/finance/commissions`

代理佣金计算、审核、发放。

#### 4.4.4 提现审核 `/admin/withdraws`

代理提现申请审核、打款确认。

#### 4.4.5 对账 `/admin/finance/reconciliation`

供应商结算对账 + 平台内部对账。

#### 4.4.6 价格管理 `/admin/finance/prices`

各模型/各维度的售价管理。

#### 4.4.7 发票管理 `/admin/finance/invoices`

发票申请审核、开票。

#### 4.4.8 退款管理 `/admin/finance/refunds`

## 4.22 数据生命周期管理（P0）

> **📖 页面功能说明帮助**
>
> **页面用途**：配置数据保留和归档策略，自动清理过期数据，管理存储容量。
>
> **适用角色**：运维（ops）、管理员（admin / super_admin）
>
> **核心操作**：
> - 配置策略：修改各数据表的在线/归档保留天数
> - 手动归档：立即将过期数据迁到冷存储
> - 手动清理：删除过期归档和临时文件
> - 存储概览：查看在线/归档使用量和扩容预估
>
> **常见场景**：
> - 调用日志增长过快 → 缩短保留天数或增加存储
> - 磁盘空间告警 → 触发归档和清理
> - 用户注销 → 7 天后物理删除个人数据
>
> **注意事项**：归档数据校验通过后才会删除在线数据
>

### 功能描述

任何平台运营久了都会面临数据增长问题。调用日志、操作日志、统计快照等数据长期在线保存成本高昂。需要建立数据的自动归档、清理、销毁策略，以及用户注销后的数据彻底清除流程。


### [?] 按钮级帮助对照表

| 按钮/入口 | 功能说明 |
|---|---|
| `配置策略[?]` | 修改数据表的在线保留天数和归档保留天数 |
| `立即归档[?]` | 手动触发归档，将过期数据移到冷存储 |
| `立即清理[?]` | 手动触发清理，删除过期归档和临时文件 |
| `查看日志[?]` | 查看归档和清理操作的历史记录 |

### 完成能力 / 展示效果

**管理后台 → 运维 → 数据生命周期：**

```
数据生命周期管理

  ┌────────────────────────────────────────────────────────┐
  │  数据保留策略                                            │
  ├─────────┬──────────┬──────────┬────────┬────────┬──────┤
  │ 数据表  │ 在线保留  │ 归档保留  │ 清理周期 │ 当前量 │ 操作 │
  ├─────────┼──────────┼──────────┼────────┼────────┼──────┤
  │调用日志 │ 90 天     │ 180 天   │ 每日    │ 2.3GB  │ [配置]│

  │资金流水 │ 永久      │ —        │ —       │ 500MB  │ [配置]│
  │统计快照 │ 30 天     │ 90 天    │ 每日    │ 800MB  │ [配置]│
  │审计日志 │ 365 天    │ 3 年     │ 每日    │ 600MB  │ [配置]│
  │临时文件 │ 7 天      │ —        │ 每小时  │ 200MB  │ [配置]│
  └─────────┴──────────┴──────────┴────────┴────────┴──────┘

  存储概览:
  在线存储使用: 5.5 GB / 50 GB     🟢 (11%)
  归档存储使用: 12.3 GB / 200 GB   🟢 (6%)
  预计满额时间: 在线 45 天 / 归档 8 个月
```

**数据归档流程：**

```
调度器触发（每日凌晨 03:00） →
  ├── 检查各数据表的在线保留期
  │   ├── 调用日志 > 90 天 → 归档到冷存储（压缩为 .gz）
  │   └── 统计快照 > 30 天 → 归档到冷存储
  ├── 归档后校验（文件完整性检查）
  ├── 校验通过 → 从在线表删除已归档数据
  ├── 校验失败 → 告警通知运维
  └── 记录归档日志（文件路径/行数/大小/校验值）
```

**数据清理流程：**

```
调度器触发（每日凌晨 04:00） →
  ├── 检查各数据表的归档保留期
  │   ├── 调用日志归档 > 180 天 → 删除归档文件
  │   └── 临时文件 > 7 天 → 直接删除
  ├── Redis 清理
  │   ├── 过期 Key 清理（已由 Redis 自动处理）
  │   └── 孤儿 Key 清理（无对应记录的缓存 Key）
  ├── 文件存储清理
  │   └── 未关联任何记录的已上传文件（孤儿文件）
  └── 记录清理日志
```

**用户注销数据清除流程：**

```
用户提交注销申请 →
  └── 管理员审核确认 →
      └── 执行数据清除:
          ├── 7 天后物理删除:
          │   ├── users 表（标记 deleted，7 天后真正 DELETE）
          │   ├── api_keys 表
          │   └── user_preferences 表
          ├── 匿名化保留（法律要求保留的数据）:
          │   ├── call_logs 表 → userId 置为 NULL，保留调用记录
          │   ├── recharge_logs → userId 置为 NULL，保留交易记录
          │   └── operation_logs → userId 置为 NULL，保留操作记录
          └── 不可恢复确认:
              └── 管理员确认数据已清除 → 注销完成通知
```

```
  ● 所有管理后台页面（/admin/* 全部路由）

```

### 详细边界说明

#### ADMIN-002: 角色权限变更与活跃会话

**设计规则**:
- 权限变更写入后，系统标记用户的 `permission_version` +1
- 活跃会话不主动检查版本变更（避免每秒轮询）
- 管理员可选"强制重新登录"选项（立即生效），通过会话 ID 推送断连信令
- 默认策略：不强制断连，下次登录时重新加载权限

#### ADMIN-005: 并发编辑冲突

**处理流程**:
```
用户 A 打开记录（版本 3）→ 开始编辑
用户 B 打开记录（版本 3）→ 开始编辑
用户 A 保存成功 → 版本升为 4
用户 B 保存 → 检测到版本 3 ≠ 当前 4 → 冲突
  → 提示"记录已被用户 A 修改"
  → 展示 A 的修改内容（diff 视图）
  → 用户 B 选择：覆盖 / 放弃 / 合并
```

#### ADMIN-006: 数据生命周期管理

**策略**:
- 清理计划：`soft_delete + delay_physical_delete`
- 软删除时间戳 `deleted_at` 设置后，查询层自动过滤（`WHERE deleted_at IS NULL`）
- 物理删除窗口为每日凌晨 02:00-04:00
- 物理删除前再次确认数据无引用

### 异常流程汇总

| 场景 | 恢复策略 | 是否通知 |
|------|---------|---------|

| 权限变更影响活跃会话 | 下次登录生效 | 可选强制下线通知 |
