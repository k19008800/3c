## 1.1 平台定义与商业模型

### 功能描述

3cloud 是一个 AI API 中间层平台，从多家上游模型供应商批量采购 API 能力，通过智能路由和精细计费系统，转售给下游开发者和企业用户。

### 完成能力

- **平台角色**：采购→加价/抽佣→转售，赚取差价 + 佣金
- **供应商角色**：提供模型 API 能力，通过平台触达更多终端用户
- **代理角色**：一级代理发展用户和子代理，赚取佣金分成
- **用户角色**：开发者用 API Key 调用模型，企业用户集中管理团队消费

### 上下游关系

```
上游：模型供应商（OpenAI/DeepSeek/GLM 等）
  ↓ 采购 API
平台：3cloud（智能路由 + 计费 + 管理）
  ↓ 转售
下游：开发者 → 企业用户 → 代理商（一级代理 → 子代理）
```

## 1.3 核心商业指标（运营 KPI）

### 功能描述

运营 KPI 看板展示 12 项核心商业指标的定义、采集方式和运营预警。

### 完成能力 / 展示效果

管理员在运营看板看到 12 项指标的完整表格：

| 指标名称 | 定义 | 采集方式 | 运营意义 | 预警阈值 |
|---------|------|---------|---------|---------|
| DAU | 每天发起至少 1 次 API 调用的独立用户数 | call_logs.user_id 去重计数 | 衡量平台日活健康度 | 连续 3 天下降 > 10% |
| 日调用量 | 全天 API 请求总数 | call_logs 计数 | 系统负载和营收来源 | 增长率 > 100%/周需扩容 |
| MRR（月流水） | 月度用户消费总额 | consumption_logs 按月聚合 | 平台营收核心指标 | 月环比下降 > 15% |
| 毛利率 | (用户收入 - 供应商成本) / 用户收入 × 100% | 财务模块自动计算 | 平台盈利能力 | < 15% 需调整定价 |
| 7 日留存率 | 注册后第 7 天仍有调用的用户 / 注册总数 | 用户分析模块 | 产品粘性 | < 20% 需优化 Onboarding |
| 30 日留存率 | 注册后第 30 天仍有调用的用户 / 注册总数 | 用户分析模块 | 长期价值判断 | < 10% 需调整运营策略 |
| 代理活跃度 | 近 30 天名下用户有消费的代理 / 总代理数 | 代理模块 | 分销体系健康度 | < 50% 需代理激励 |
| Key 使用率 | 已创建 Key 中近 7 天有调用的占比 | api_keys 关联 call_logs | Key 闲置率监控 | < 40% 需提醒用户清理 |
| 供应商健康度 | 各供应商 API 可用率（近 24 小时）| 健康检查模块 | 服务质量监控 | < 99% 触发告警 |
| 告警收效率 | 真实告警 / 总告警数 × 100% | 告警模块 | 告警质量、避免告警疲劳 | < 60% 需调整规则阈值 |
| 自助结算率 | 代理自主确认结算的比例 | 结算模块 | 运营人力投入 | < 70% 需优化结算流程 |
| ARPU（客单价） | 月总消费 / 月活跃用户数 | 财务模块 | 用户价值分层 | 连续 3 月下降需营销刺激 |
| 新用户注册数 | 每日独立注册用户数 | `users` 表当日注册 | 增长动力指标 | 连续下降需加大拉新 |
| 新用户次日留存 | 注册次日仍有调用的用户占比 | 用户分析模块 | 产品上手体验 | < 40% 需优化 Onboarding |
| 新用户 7 日付费转化 | 注册 7 天内首次充值的用户占比 | 充值模块 | 商业变现效率 | < 15% 需优化付费引导 |
| API 响应时间 P50/P95 | 50% / 95% 请求在多少毫秒内完成 | `call_logs` 耗时字段 | 服务质量 | P95 > 3s 触发告警 |
| 活跃模型数 | 每日至少被调用 1 次的模型数量 | `call_logs` 去重计数 | 产品丰富度 | 单日活跃 < 50% 需检查 |
| API 成功率 | (成功数/总数) × 100 | `call_logs` 状态统计 | 服务质量 | < 97% 调查故障原因 |

## 1.2 运营 KPI 看板

### 功能描述

管理后台提供一个运营看板，实时展示 12 项核心商业指标，帮助管理员掌握平台健康度。

### 完成能力 / 展示效果

管理员在管理后台→运营看板看到：

| 指标 | 展示方式 | 说明 |
|------|---------|------|
| DAU（日活跃用户） | 数字 + 近 7 天趋势折线图 | 每天至少 1 次 API 调用的独立用户数 |
| 日调用量 | 数字 + 趋势图 | 全天 API 请求总数 |
| MRR（月流水） | 金额数字 + 月环比 | 月度用户消费总额 |
| 毛利率 | 百分比 + 色标 | (用户收入 - 供应商成本) / 用户收入 |
| 7 日留存率 | 百分比 + 趋势 | 注册后第 7 天仍有调用的用户占比 |
| 30 日留存率 | 百分比 + 趋势 | 注册后第 30 天仍有调用的用户占比 |
| 代理活跃度 | 百分比 | 近 30 天名下用户有消费的代理占比 |
| Key 使用率 | 百分比 | 已创建 Key 中近 7 天有调用的占比 |
| 供应商健康度 | 百分比 + 色标 | 各供应商 API 可用率（近 24 小时） |
| 告警收效率 | 百分比 | 真实告警 / 总告警数 |
| 自助结算率 | 百分比 | 代理自主确认结算的比例 |
| ARPU（客单价） | 金额数字 + 趋势 | 月总消费 / 月活跃用户数 |

### 上下游关系

```
上游数据源：
  call_logs 表 → 日调用量、DAU
  consumption_logs 表 → MRR、ARPU
  users 表 → 留存率、分层
  api_keys 表 → Key 使用率
  健康检查模块 → 供应商健康度
  告警模块 → 告警收效率
  结算模块 → 自助结算率

看板本身 → 前端展示（OperationalKpiPanel 组件）
异常触发 → 告警规则引擎（指标触达预警阈值时）
```

### 异常与预警

| 场景 | 触发条件 | 展示效果 |
|------|---------|---------|
| DAU 异常下降 | 连续 3 天下降 > 10% | 指标红框闪烁 |
| 毛利率下降 | < 15% | 红框警告 |
| 供应商故障 | 可用率 < 99% | 触发告警通知 |
| 告警疲劳 | 告警收效率 < 60% | 提示调整规则阈值 |

## 1.3 用户分层与运营策略

### 功能描述

系统自动将用户按月度消费金额分为 5 层，管理员可针对不同层级制定差异化运营策略。

### 完成能力 / 展示效果

| 层级 | 定义 | 占比 | 系统自动配备的策略 |
|------|------|------|-------------------|
| 种子用户 | 月消费 > ¥1000 | ~5% | 专属客户经理、优先技术支持、专属折扣 |
| 活跃用户 | 月消费 ¥100-1000 | ~15% | 定期推送用量报告、活动通知 |
| 普通用户 | 月消费 ¥10-100 | ~30% | 邮件营销、满赠活动 |
| 休眠用户 | 有登录无消费 | ~25% | 推送模型更新、优惠券唤醒 |
| 流失用户 | 注册 > 30 天且近 30 天无登录 | ~25% | 召回邮件、新模型上线通知 |

运营看板中展示用户分层分布饼图，点击各层可查看详情列表。

### 上下游关系

```
上游：consumption_logs + users 表 → 自动计算分层
下游：运营策略引擎 → 自动触发对应策略（推送/优惠/客服）
```

## 1.4 近 7 天趋势数据流

### 功能描述

所有 KPI 指标均提供近 7 天趋势数据，以折线图展示每日变化。

### 完成能力

- 后端 API：`GET /api/v1/admin/operational/kpi`、`GET /api/v1/admin/operational/user-tiers`、`GET /api/v1/admin/operational/trends`
- 前端：`OperationalKpiPanel.tsx` 组件集成在管理仪表盘
- 所有指标支持按日/周/月切换查看粒度
- 数据缓存 5 分钟，避免频繁查询大表

### 上下游关系

```
后端定时任务 → 每日聚合 KPI 数据 → 存入 kpi_snapshots 表
└→ 前端请求 → 读取快照 → 渲染图表
└→ 异常检测 → 达到阈值 → 触发告警
```

## 边界条件

### KPI 计算边界场景

| # | 场景 | 触发条件 | 预期行为 |
|---|------|---------|---------|
| KPI-001 | 新平台无历史数据 | 首次部署，所有 KPI 看板无历史聚合值 | 前端展示
| KPI-002 | 数据加载超时 | 批量数据加载超过配置的超时阈值（默认 30s） | 记录错误日志并触发重试机制，最多重试 3 次
| KPI-003 | 并发数据加载冲突 | 同一时间段内多个数据源同时写入 KPI 聚合表 | 采用写锁机制，按优先级顺序处理，冲突回滚后等待 1s 重试
| KPI-004 | 空数据源 | 已配置的数据源无可用数据 | 前端展示空状态提示，并在系统日志标记数据源异常
| KPI-005 | KPI 聚合精度丢失 | 浮点数聚合时累计精度误差超过 0.01% | 使用定点数存储并记录精度偏差日志
| KPI-006 | 跨时区数据对齐 | 数据源使用不同时区 | 统一转换为 UTC 存储，前端按用户时区展示
