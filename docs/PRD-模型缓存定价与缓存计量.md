## 2. 需求背景与目标

### 2.1 背景（四类缺口）

| # | 缺口（方案原文） | 现状依据 | 核心影响 |
|---|-----------------|---------|---------|
| G1 | **渠道模型定价没有缓存费用定义** | `supplier_models`（方案术语 `vendor_models`，见 §5 表名映射）仅有 `input_price / output_price`（varchar(30)），且 **L0 成本列（cost_input_price/cost_output_price）整体未落地**，无任何缓存字段（评审 S1 核实） | 缓存成本无法定价 → 渠道结算无法区分缓存成本，毛利率失真 |
| G2 | **渠道模型定价没有显式缓存价格** | `vendor_pricing` 只有 `cache_discount_rate`（命中按全价 × 折扣率，`ref-5.2 §3.2.1 / §5.1`） | ① 无法表达上游**独立发布的缓存读取价**（DeepSeek 命中 ¥0.5/1M vs 未命中 ¥2/1M）；② 无法表达 Anthropic **缓存写入价**（`cache_creation` 有独立单价）；③ 折扣率是"比例"，不满足"给用户明码标价" |
| G3 | **用户无处查询缓存定价** | 模型中心价格弹窗设计稿含 `cache_hit_price` prop（`ref-2.2.2 §二`），但数据来源未定义、列表不展示、公开价目/帮助中心缺失 | 用户无法预知缓存调用成本 |
| G4 | **用户看不到调用消费到的缓存信息** | `consumption_records`（方案术语 `call_logs`，见 §5 表名映射）已落库 `cache_hit_tokens / cache_discount`（评审 S4 核实；`data-dictionary §2.2`），但调用日志页、用量统计、账单均不透出 | 用户不知道"这次调用有多少 token 命中缓存、省了多少钱" |

## 4. 业务规则

> 本节为方案 §三/§五/§六 的正式化表述，**未修改任何既定决策**；对歧义处的默认建议见第 11 节。

### 4.1 计费公式（权威口径）

```
输入费用 = cacheReadTokens × cacheReadPrice
         + cacheWriteTokens × cacheWritePrice
         + (prompt_tokens − cacheReadTokens − cacheWriteTokens) × inputPrice
输出费用 = completion_tokens × outputPrice
总费用   = (输入费用 + 输出费用) × user_discount_rate
实际扣费 = 总费用按精度规则舍入（见 4.7）
```

规则约束：

1. **收敛约束（D-11 定稿）**：`cacheReadTokens + cacheWriteTokens ≤ prompt_tokens`；超出时**优先保留 read**：`cacheWriteTokens = max(prompt_tokens − cacheReadTokens, 0)`（写入是读取的前置，read 价通常更低，保留 read 对用户有利、对平台口径保守）；归一化层与计费层双保险同规则。
2. **退化规则**：上游未返回任何缓存字段，或模型无缓存计费能力时，`cacheReadTokens = cacheWriteTokens = 0`，公式退化为 `prompt_tokens × inputPrice + completion_tokens × outputPrice`，**计费结果与现状完全一致**。
3. **生效范围（D-9 定稿）**：非流式响应，以及携带 usage 缓存字段的流式响应均适用。**流式注入范围**：`stream=true` 时对 **chat / messages / openai-compat** 三端点注入 `stream_options.include_usage=true`（responses 端点已有；anthropic 上游天然携带 usage，无需注入）；注入逻辑集中在 `buildUpstreamBody` 单点并预留渠道级开关。**计费时点与回滚**：沿用现有「预扣 → 流结束按最终 usage 结算（determineStreamBilling）」时序，无状态机改动；流超时/中断回滚时缓存字段恒 undefined，回滚口径不变。⚠️ 此为本期对 `ref-5.2 §3.2.1`「流式场景沿用全价计费」的**有意扩展**（方案既定决策），属行为变更点，见第 10 节。
4. `user_discount_rate` 为现有用户折扣率（`users.discount_rate` / 代理折扣），仅作用于总费用，不单独作用于缓存价（D-3 定稿）。

### 4.2 价格解析优先级（缓存读取价，从高到低共 5 级）

| 级 | 来源 | 计算 | 说明 |
|:--:|------|------|------|
| 1 | 模型覆盖价 `models.override_cache_read_input_price` | 直接取值 | L2，可空；**本期缺省**（models 表不存在，P0 不落地，D-10） |
| 2 | 标准价 `vendor_pricing.cache_read_input_price` | 直接取值 | L1，可空；渠道显式缓存读取售价 |
| 3 | 模型折扣率 `vendor_pricing.cache_discount_rate` | `生效 input_price × rate` | 兼容/快捷配置；rate ∈ (0,1]，可空 |
| 4 | 全局折扣率 `system_config.billing.cache_hit_discount` | `生效 input_price × rate` | 默认 0.1，rate ∈ (0,1] |
| 5 | 代码兜底 `CACHE_HIT_DISCOUNT` | `生效 input_price × 0.1` | 前四级均不可用时生效 |

补充语义：

- 表中「生效 input_price」= **当前请求最终生效的输入单价**（经 L5/L4/L3/L2/L1 定价流程后的 input，含覆盖/折扣推导，D-3 定稿）；折扣率回退（级 3/级 4/级 5）= 生效 input_price × rate；**显式缓存价（级 1/级 2）独立于折扣类优惠**，不随活动/分组/代理折扣联动（L5/L3 分支缓存价字段恒 null，与 pricing.ts 现状一致）；L3 代理折扣与用户折扣一样只乘总费用。
- 某一级为空/非法 → 自动落入下一级；任意一级命中即停止。
- **反推展示**：配置显式缓存读取价后，系统自动反推等效折扣率（= 显式读取价 ÷ 生效输入价）**仅用于展示**，不作为计费依据。
- **P0 生效级数（D-10）**：P0 按 **4 级**生效（级 1 缺省）；L2 覆盖价语义由 `vendor_pricing(pricing_group='default')` 显式缓存价列（级 2）**天然承载**（default 组即模型级覆盖价的代码载体，`queryDefaultPricing`），无需为 models 表额外加列，避免双载体并存。

### 4.3 缓存写入价解析

| 场景 | 写入价取值 | 说明 |
|------|-----------|------|
| 配置显式写入价（`vendor_pricing.cache_write_input_price`；models 覆盖列本期缺省，D-10） | 显式价 | 与读取价解析同构；仅 Anthropic 系模型通常需要 |
| 显式写入价缺失 | `生效 input_price` 全价 | 保守口径，计费标注"未配置写入价"（透出标识 `cache_write_price_source: 'full_price'`，D-4 定稿，见 §5.5/§7.7） |
| `cache_pricing_mode = discount_rate` | 写入 token 按全价、读取按折扣率 | **行为与旧版（ref-5.2 §3.2.1）完全一致** |

### 4.4 `cache_pricing_mode` 计费模式开关

| key | 可选值 | 默认 | 业务语义 |
|-----|--------|:----:|---------|
| `cache_pricing_mode` | `explicit` / `discount_rate` | `explicit` | `explicit` = 显式价格优先、折扣率为回退；`discount_rate` = 完全沿用旧行为（写入全价 + 读取折扣率），作为**灰度开关**可一键回到旧版 |

- 开关生效方式：配置保存后即时生效（价格缓存失效机制沿用 `ref-5.2 §3.3`，TTL 5 分钟内）；存量已发生调用不受影响（价格变更只影响变更后请求，不追溯历史，对齐 `ref-5.2 §八`）。
- 开关为全局配置（`system_config.billing`），由 admin 以上角色维护（权限见第 6 节）。

### 4.5 上游 usage 归一化

| 上游 | 原始字段 | 归一化结果 | 说明 |
|------|---------|-----------|------|
| DeepSeek | `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens` | 命中 → `cacheReadTokens`；miss **不单独计** | 命中/未命中成对出现；miss 部分自然落入"未命中全价"段 |
| Anthropic | `cache_read_input_tokens` / `cache_creation_input_tokens` | read → `cacheReadTokens`；creation → `cacheWriteTokens` | **写入价独立**，写入 token 不入读取段 |
| OpenAI | `prompt_tokens_details.cached_tokens` | → `cacheReadTokens` | 官方按 50% 计费，平台落显式价（如实配置） |
| 其他 / 无缓存字段 | — | 全部按未命中全价 | 与现状一致 |

约束：`cacheReadTokens + cacheWriteTokens ≤ prompt_tokens`，超出收敛（见 4.1-1）。

**计价单位归一化**：全部价格统一为 **¥/1K tokens**（与现有价格一致）；上游同步/抓取时若为 `/1M` 口径 → **÷1000** 后存储（示例：DeepSeek 命中 ¥0.5/1M → 存 0.0005/1K；未命中 ¥2/1M → 存 0.002/1K）。**P0 范围**：÷1000 自动换算逻辑属 P3 价格同步引擎（F21）验收；P0 仅保证存储口径契约 = ¥/1K（录入/API/存储一致，不得按 /1M 值入库，见 AC-06）。

### 4.6 回退规则汇总

| # | 场景 | 回退行为 |
|---|------|---------|
| R1 | 显式读取价未配置（级 1/级 2 皆空） | 级 3 模型折扣率 → 级 4 全局折扣率 → 级 5 代码兜底 |
| R2 | 显式写入价未配置 | 按生效输入价全价计（4.3） |
| R3 | 上游未返回缓存字段 / 模型无缓存能力 | 全价计，与现状一致（4.1-2） |
| R4 | 命中+写入数超输入上限 | read 优先保留，write 收敛（write = max(prompt − read, 0)）（4.1-1，D-11） |
| R5 | `cache_pricing_mode = discount_rate` | 写入全价 + 读取折扣率，等价旧版（4.4） |
| R6 | 上游/1M 口径价格 | ÷1000 归一为 /1K（4.5） |

### 4.7 精度规则

| 对象 | 精度 | 说明 |
|------|------|------|
| 价格字段（读取/写入单价、成本价） | numeric(18,6) | ¥/1K tokens |
| 计量金额字段（cache_hit_cost / cache_write_cost / cache_discount / cost） | numeric(18,8) | ¥；与现有 cost / cache_discount 列一致 |
| token 计量 | integer | 精确计数 |
| 计算 / 扣费 / 流水输出 | toFixed(8) | 对齐现有 cost 列与全链路输出（settle 链路），**不引入额外舍入层** |
| 前端展示 | toFixed(2) | 前端职责，不丢原始精度 |
| 批量消费精度 | 按每笔分别计算后汇总 | 沿用现有规则 |

> 精度口径已按 **D-1 定稿**：存储/计算 numeric(18,8) + 输出 toFixed(8) + 展示 toFixed(2)；同时修订 `ref-5.2 §3.1`（原"6 位"）与 `§8.2`（原"4 位"）三处不一致口径（见第 10.6 节）。

## 7. 用户端查询与消费透出需求

> 每项给出：功能描述 / 页面与交互要求 / 验收点（编号对应第 8 节）。

### 7.1 模型中心 ModelCard 价格区（F07）

**功能描述**：有缓存读取价的模型在卡片价格区展示缓存读取单价，用户无需展开即可感知"命中缓存更便宜"。

**页面与交互要求**：
- ModelCard 价格区格式：`输入 ¥x / 输出 ¥y / 缓存读取 ¥z`（仅在价格解析后存在有效缓存读取单价时展示 `缓存读取 ¥z`；无缓存计费能力的模型不显示该段）。
- `缓存读取 ¥z` 旁带按钮级 `[?]`（文案见第 9 节）。
- 价格与计费引擎同源（实收价，非原始价），数据来源为价格解析后的最终值（P0 生效 4 级，级 1 缺省）。
- 展示判定规则（**D-7 定稿**）：**5 级解析后存在有效缓存读取单价 且 上游支持缓存字段**。上游支持矩阵 = 常量（本期定义，P1 前端落地）：DeepSeek / Anthropic / OpenAI 的 chat / completions 类端点支持缓存 usage 字段；embedding / rerank 类不支持（上游无缓存语义）。P0 归一化层以运行时 `hasCacheInfo` 判定（不依赖静态矩阵）；静态矩阵仅供 P1 展示层使用。

**验收点**：AC-21、AC-22。

### 7.2 PriceDetailModal 价格明细弹窗（F08）

**功能描述**：弹窗新增「缓存计费」区块，向用户明码标价并给出示例换算。

**页面与交互要求**：

## 10. 变更影响分析

### 10.1 存量数据与现有计费行为兼容

| 影响面 | 分析 | 处置 |
|--------|------|------|
| 存量数据 | 新增字段全部可空、无默认值迁移 | **无数据迁移**（方案 §十-1） |
| 存量未配置显式缓存价模型 | 命中部分按折扣率/全局回退（0.1），计费结果与现状一致 | **无行为变更**（方案 §十-2） |
| `cache_pricing_mode` 灰度开关 | 可一键回到旧版行为 | 作为上线/回退开关保留（方案 §十-4） |
| 已有 `cache_discount_rate` 配置 | 语义由"计费依据"降级为"兼容/快捷配置 + 展示反推"，存量配置值继续生效（作为 5 级解析级 3） | 不清理存量配置 |
| `cache_hit_discount` 全局配置 | 保留，降级为 5 级解析级 4 回退 | 不清理存量配置 |

### 10.2 行为变更点（升级后可能变化的场景）

| # | 变更点 | 影响 | 对策 |
|---|--------|------|------|
| C1 | **流式 `stream_options.include_usage` 场景开始按缓存价计费**（原 `ref-5.2 §3.2.1` 为"流式沿用全价"） | 携带缓存字段的流式请求计费金额可能**降低**（用户受益）；注入范围 = chat / messages / openai-compat 三端点（stream=true 注入 include_usage），responses 已有、anthropic 天然带；渠道成本侧同样变化 | 属方案既定决策（D-9）；注入集中在 `buildUpstreamBody` 单点 + 预留渠道级开关；上线前通过 §5.5 通知策略对受影响用户说明（降价方向受益，仍建议告知） |
| C2 | 配置显式缓存价后计费金额可能变化（显式价 ≠ 原折扣率口径） | 涨/降双向可能 | 按价格变更流程（`ref-4.3 §8.2` 分级 + `§5.5` 通知）处理；显式价配置属价格变更 |
