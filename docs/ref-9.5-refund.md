## 概述

用户充值后因各种原因需要退款（平台问题、用户误操作、重复充值等）。当前退款全靠运营手动操作——查余额、调账、手工记录，流程不透明且容易出错。涉及代理佣金时，还要手动扣回佣金，非常复杂。

**核心价值**：退款流程标准化、自动化佣金扣回，全程可追溯。

---

## 功能模块

### 1. 退款发起

| 发起方 | 场景 | 说明 |
|--------|------|------|
| 运营/客服 | 用户申请退款 | 人工审核后发起，需填写退款原因和金额 |
| 系统自动 | 充值未到账 | 充值回调超时 30 分钟 → 自动退款 |
| 系统自动 | 重复充值 | 同一订单号收到多次回调 → 自动退款多余部分 |

**退款表单**：

```
新增退款

  用户: [搜索用户] *
  退款金额: [________] *
  退款类型: [充值退款 ▼]  // 充值退款 | 平台补偿 | 重复充值 | 其他
  关联订单: [RCH-20260728-0001] (可选)
  退款原因: [________] *
  是否通知用户: ☑
  备注: [________]

  [提交] [取消]
```

### 2. 退款审核流程

```
退款申请 → 财务初审 → 财务复审 → 已退款 → 完成
                  ↓                   ↓
               驳回               退款失败（重试/人工）
```

| 阶段 | 操作人 | 说明 |
|------|--------|------|
| 提交 | 运营/客服 | 填写退款信息，提交申请 |
| 初审 | 财务员 | 检查退款金额是否合理、用户余额是否足够 |
| 复审 | 财务主管 | 确认退款合规性，审批通过 |
| 执行 | 系统 | 执行退款：扣减余额 + 调用支付网关退款 API（如已支付）|
| 完成 | 系统 | 记录审计日志 + 通知用户 |

**金额限制**：
- 单笔退款 ≤ ¥500：客服直接提交，财务初审即可
- 单笔退款 > ¥500：需财务复审
- 单笔退款 > ¥10,000：需财务主管+管理员双审

### 3. 退款执行逻辑

```
退款执行流程：

1. 检查用户当前余额 ≥ 退款金额
   → 否：标记"余额不足"，提示人工处理
2. 冻结退款金额
3. 调用支付网关退款 API（如原订单已支付）
   → 成功：更新订单状态
   → 失败：重试 3 次，仍失败 → 标记"退款失败，需人工处理"
4. 扣减用户余额
5. 扣回代理佣金（如有）
6. 记录审计日志
7. 发送站内通知给用户
```

### 4. 佣金扣回

当退款涉及已结算佣金的充值订单时，需自动扣回佣金：

| 场景 | 佣金扣回策略 |
|------|-------------|
| 佣金未结算 | 直接从待结算佣金中扣除，不影响已结算 |
| 佣金已结算 | 生成负向佣金记录，从下次佣金结算中抵扣 |
| 佣金已提现 | 标记"佣金透支"，从后续佣金中逐步抵扣 |

**扣回规则**：
- 退款全额 → 佣金全额扣回
- 退款部分 → 按比例扣回（退款金额/充值金额 × 佣金金额）
- 佣金扣回记录到 commission_logs

### 6. 数据表

```typescript
// refunds — 退款记录
export const refunds = pgTable("refunds", {
  id: serial("id").primaryKey(),
  refundNo: varchar("refund_no", { length: 20 }).notNull().unique(), // RF-260728-0001
  userId: integer("user_id").notNull().references(() => users.id),
  orderId: integer("order_id").references(() => rechargeOrders.id), // 关联充值订单
  amount: numeric("amount", { precision: 14, scale: 4 }).notNull(),
  refundType: varchar("refund_type", { length: 20 }).notNull(),
  // recharge_refund | compensation | duplicate | other
  reason: text("reason").notNull(),
  status: varchar("status", { length: 20 }).notNull().default("pending"),
  // pending | approved | rejected | processing | completed | failed
  approverId: integer("approver_id").references(() => users.id),
  reviewerId: integer("reviewer_id").references(() => users.id),  // 复审人
  commissionDeducted: boolean("commission_deducted").default(false),
  commissionAmount: numeric("commission_amount", { precision: 14, scale: 4 }),
  gatewayRefundId: varchar("gateway_refund_id", { length: 100 }), // 支付网关退款单号
  note: text("note"),
  createdBy: integer("created_by").notNull().references(() => users.id),
  createdAt: timestamp("created_at", { withTimezone: true }).notNull().defaultNow(),
  updatedAt: timestamp("updated_at", { withTimezone: true }).notNull().defaultNow(),
});
```

### 7. API 接口

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| `POST` | `/api/v1/admin/refunds` | 发起退款 | 客服/运营 |
| `GET` | `/api/v1/admin/refunds` | 退款列表 | 客服/财务 |
| `GET` | `/api/v1/admin/refunds/:id` | 退款详情 | 客服/财务 |
| `POST` | `/api/v1/admin/refunds/:id/approve` | 初审通过 | 财务 |
| `POST` | `/api/v1/admin/refunds/:id/review` | 复审通过 | 财务主管 |
| `POST` | `/api/v1/admin/refunds/:id/reject` | 驳回退款 | 财务 |
| `POST` | `/api/v1/admin/refunds/:id/retry` | 重试执行（失败后） | 财务 |
| `GET` | `/api/v1/admin/refunds/summary` | 退款统计（日/周/月汇总） | 财务 |

### 8. 边界条件

| 场景 | 处理方式 |
|------|---------|
| 用户余额不足 | 拒绝退款，提示"用户当前余额 ¥X，小于退款金额 ¥Y" |
| 退款金额超过充值金额 | 拒绝退款，提示"退款金额不能超过关联订单金额" |
| 支付网关退款失败 | 重试 3 次（间隔 30s），仍失败则标记"需人工处理" |
| 佣金扣回后余额为负 | 允许负值，后续佣金自动抵扣 |
| 用户已注销 | 不允许退款，提示"用户已注销" |
| 退款后用户余额 | 退款完成后余额 = 原余额 - 退款金额 |
