## 31.0 总览

### 功能描述

系统运行过程中，供应商宕机、配置错误、环境差异等问题常常靠"出事了再救"的方式处理。本模块提供提前验证机制：手动模拟供应商故障验证熔断器效果、多环境配置同步与差异对比、配置沙箱预览。

### 子模块清单

| 编号 | 模块 | 优先级 | 核心价值 |
|------|------|--------|---------|
| 31.1 | 供应商故障演练 | P1 | 模拟供应商宕机，验证熔断器和自动切换是否正常工作 |
| 31.2 | 多环境配置管理与同步 | P1 | 测试/生产环境配置差异可视化和同步导入 |
| 31.3 | 配置沙箱预览 | P1 | 配置变更前在沙箱中模拟执行，预览预期效果 |

## 31.1 供应商故障演练

### 功能描述

运营/运维人员在管理后台手动模拟某个供应商宕机，观察平台的熔断器、自动重试、供应商切换是否按预期工作。验证完成后自动恢复。用于定期演练和排查问题时复现场景。

### 边界条件

| 场景 | 处理方式 |
|------|---------|
| 正在有真实故障时 | 不允许开始演练，提示"当前供应商已有真实故障，请处理后再演练" |
| 演练中真实用户恰好转到这个供应商 | 演练仅影响测试请求，真实用户请求按正常路由（熔断器状态影响所有请求，需区分测试流量） |
| 同时演练多个供应商 | 不允许同时演练 2 个以上供应商 |
| 演练超时未自动结束 | 定时器兜底，到时间自动结束并生成报告 |

### 验收标准

#### □ 流程图一致性校验 — 与对应流程图对比验证流程分支、异常处理、决策节点完全一致

1. 管理员选择 DeepSeek + 超时场景 → 开始演练 → 模拟请求全部超时
2. 熔断器在阈值后触发（HALF_OPEN） → 自动切换到备用供应商
3. 演练中的测试请求标记特殊 header（X-Drill: true），不影响真实用户
4. 演练结束后熔断器自动恢复
5. 演练报告显示熔断器是否正常触发、切换延迟、结论和建议

## 31.2 多环境配置管理与同步

### 功能描述

平台有测试环境和生产环境，配置不同步容易导致"测试环境好好的，上线就出问题"。本模块提供环境配置差异可视化对比和配置导入/导出，解决环境配置漂移问题。

### API 接口

```
GET  /api/v1/admin/environments                   — 环境列表
GET  /api/v1/admin/environments/:name/config      — 某环境的当前配置快照
POST /api/v1/admin/environments/compare           — 对比两个环境的配置差异
POST /api/v1/admin/environments/export            — 导出配置
POST /api/v1/admin/environments/import            — 导入配置
```

### 验收标准

1. 选择"测试环境 vs 生产环境" → 对比显示所有配置项的差异
2. 差异项按关注度排序（Key/价格/限流等高关注优先展示）
3. 点击"导出配置" → 下载 JSON 文件
4. 导入配置 → 预览显示将修改的配置项 → 确认后导入
5. 导入后记录到配置版本历史

## 31.3 配置沙箱预览

### 功能描述

配置变更之前（如修改定价、限流阈值、风控规则），先在沙箱中模拟执行，展示预期效果和影响范围，确认无误后再应用到生产环境。

### 完成能力 / 展示效果

**配置变更前的"沙箱预览"按钮：**

```
修改 deepseek-chat 定价
  输入价格从: ¥0.50 → 新价格: ¥0.55

  [沙箱预览]

  ↓

  沙箱预览结果:
  ┌──────────────────────────────────────────────┐
  │  预计影响:                                     │
  │                                              │
  │  📈 平台收入: +¥8,500/月（+5.2%）             │
  │  📉 用户调用量: -3.2%（价格敏感用户减少）      │
  │  👥 受影响用户: 128 人（月调用 >100 万 Token）│
  │  📊 Top 受影响模型占比: deepseek-chat 42%     │
  │                                              │
  │  历史价格变更影响（参考）:                       │
  │  上次调价（¥0.45→¥0.50）: 调用量-1.8%         │
  │                                              │
  │  ⚠️ 此变更预计产生显著收入影响                  │
  │  建议: 灰度发布或分阶段调整                     │
  │                                              │
  │  [确认修改] [取消]                              │
  └──────────────────────────────────────────────┘
```

### 沙箱计算逻辑

```
定价变更影响预估:
├── 基于近 30 天该模型的调用数据
├── 按用户分层计算（高频/中频/低频用户）
├── 使用价格弹性系数预估调用量变化（默认 -0.25，可配置）
└── 结果：预期收入变化 / 调用量变化 / 受影响用户数

限流变更影响预估:
├── 基于近 7 天该限流档位被命中的频率
├── 如果降低阈值：预估每天新增的被限流请求数
└── 结果：受影响用户 / 新增限流请求数

风控规则变更影响预估:
├── 基于近 30 天的审核数据模拟执行新规则
├── 对比当前规则：新增拦截 / 误伤 / 漏放
└── 结果：新增拦截数 / 预估误伤用户数
```

### API 接口

```
POST /api/v1/admin/environments/sandbox/preview
  请求体: { configType: string, changes: Record<string, any> }
  响应: {
    impact: { revenue, callVolume, affectedUsers },
    historicalReference?: { lastChange, impact }
  }
```

### 验收标准

1. 修改模型定价 → 点击"沙箱预览" → 显示预估收入/调用量变化
2. 修改限流阈值 → 沙箱预览显示受影响用户数
3. 风控规则变更 → 沙箱预览显示新增拦截数和预估误伤数
4. 沙箱预览数据基于真实历史数据计算
