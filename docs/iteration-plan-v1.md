## 5. 关键技术选型建议

### 5.1 工单系统
- **表设计**：`tickets`(id, user_id, title, description, category, priority, status, assignee_id, created_at, updated_at, resolved_at) + `ticket_messages`(id, ticket_id, sender_id, content, attachments, created_at)
- **状态流转**：待处理 → 处理中 → 待确认 → 已关闭
- **后端**：独立 `routes/admin/tickets/` + `routes/tickets/`（用户端）
- **前端**：管理端工单列表 + 详情页 + 用户端提交/查看页面

### 5.2 在线客服
- **实时通信**：复用现有 `alert-ws` 或 `rate-limit-ws` 的 WebSocket 基础设施
- **表设计**：`chat_sessions`(id, user_id, agent_id, status, created_at, ended_at) + `chat_messages`(id, session_id, sender_type, content, created_at)
- **排队机制**：Redis 队列（利用已有 Memurai）
- **客服工作台**：WebSocket 长连接 + 消息通知

### 5.3 代理邀请
- **表设计**：`agent_invitations`(id, agent_id, code, invitee_email, status, commission_rate, created_at)
- **邀请链接**：生成唯一邀请码/链接 → 注册时关联邀请人 → 自动关联代理关系

## 6. 风险与注意事项

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 在线客服 WebSocket 与现有连接管理冲突 | 中 | 复用现有 WS 基础设施，代码审查 |

| 数据库迁移与现有 schema 冲突 | 低 | 使用新 migration 文件，编号接续 |
| 批量 3 业务员体系范围大 | 高 | 可拆分为多次迭代，先做 CRM 基础版 |
| 当前未测试的边界条件（27 份文档补充中） | 低 | 已有边界条件文档，开发时参照 |
